# 导入的小说：解析"有没有视频风格字段"（2026-10-09）

用户原话：「另外导入的小说也需要解析是否存在视频风格相关字段」。
（本轮前半「小说库导入制作可选渲染风格」见 `小说库导入-渲染风格可选-2026-10-09.md`。）

## 2. 修法：`scanNovelStyle`（`internal/server/novels_style.go`，纯函数）

优先级写死，先精准后兜底：

1. `立项.json` 的 `art_style`（老行为，最高优先）
2. `立项.json` 的 `渲染风格串`（同义字段）
3. `立项.json` 的 `画风`（中文画风名，**只在没有英文串时**兜底；播报里写明"兜底"）
4. `设定集/视觉风格卡-*.md` 的**第一段代码块**（多张卡取**文件名排序最后**的一张 = 本书专用那张）

- `立项.json` 的 `风格`（文学风格）**永不参与**画风裁决；取用只认**字符串**（dict 取不到值）。
- 扫到 ⇒ 日志说清**取自哪个字段**，并顺带报出风格卡文件名与字数；扫不到 ⇒ **如实说**
  「这本书里没有解析到视频风格字段（立项.json 的 art_style / 渲染风格串 / 画风 与 设定集/视觉风格卡-*.md 都没有）」。
- 结果进入**已有的裁决链**（用户选 > 书的字段 > LLM 自定），不另开一条路。
- 新接口 `GET /api/novels/style?path=`，「视频制作」对话框里显示**原书风格**（串 / 来源 / 风格卡 / 画风名）；
  **只写日志不算解析** —— 用户要在导入那一刻看得见。

## 4. 反向验证：5/5 全红（`reverse_verify_style_scan.ps1`）

① 导入时根本不扫字段 ② 没有英文串时也不看风格卡 ③ 多张卡取错那张（取排序第一）④ 文学风格传进画风
⑤ 解析结果只在日志、界面不显示。跑完 3/3 文件 sha256 与基线一致。

**过程中又抓出我自己两处摆设守卫（同一类错第二次记）**：

- ④ 第一版判据盯**输出**（"文学风格不许被取用"）—— 可 `风格` 是 dict，本来就不是字符串，
  把 `pick("画风")` 改成 `pick("画风","风格")` 也取不到值 ⇒ **改坏照样绿**。
  改成盯**传参**（源码里不许出现 `pick("画风", "风格")`）才咬得住。
- ⑤ 第一版断言前端里有 `"原书风格"` 这个字符串 —— 而**注释**里也有这四个字，
  把渲染标签改掉照样绿。改成断言**渲染出来的** `<b>原书风格</b>`。

## 5. 边界（说清楚，不假装完美）

- 风格卡**只用于取串与播报**（"本书画面口径以它为准"）；**没有**把整张 4 KB 的卡拼进提示词 ——
  那是另一件事（把卡当画面口径材料喂给分镜），需要单独设计与判据。
- 多张卡按**文件名排序**取最后一张：这是目前唯一可用的确定性判据（真机恰好符合：技能自带快照名在前、
  本书专用名在后）；若将来卡名不带可比较前缀，需要改读卡内"当次点名"那行（现在没有这样的字段）。
- 本轮只接**风格串**；`立项.json` 里其它口径字段（`_画面口径`、`_合规提示`、`protagonist`、`novelty`）
  **没接**（它们是给编剧/分镜当材料的，接它们要另设计判据）。
- 扫到的中文画风名进提示词不如英文串（平台的门对 `<d>` 外的汉字有上限），所以它只是**兜底**，
  且播报里明确写了"只有中文名，兜底"。
