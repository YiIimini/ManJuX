# 剧本提取：段边界与爆款纪律的机器判据（2026-10-07）

> 起因：用户一句话 —— 「**总感觉剧本提取文章内容不是按照爆款短剧要求来的**」。
> 这句话不是"感觉"，它对应三处能证实的缺陷：两处真缺陷 + 一处"写了但没人真读"的边界。
> 本文留证据与判据设计，方便下次有人问"这条纪律到底有没有门"时不用再查一遍。

## 0. 结论先摆

那份真机剧本（`data/projects/名册之外，八万零一号/名册之外，八万零一号·第01集·重新检测到生命反应/source.txt`，
2082 字）**结构门全过**：

* 4 个场次头、每场「目的/冲突/转折/爽点/钩子」五节 + 正文齐全（`missingBriefSections` 返回空）；
* 【关键道具与信息】7 条、【本集钩子】1 条；
* 每场的「爽点:」都写了、每场的「钩子:」都写了。

所以"不对劲"不在结构上 —— 这正是此前所有门都没响的原因。真正的问题：

| # | 缺陷 | 性质 |
|---|---|---|
| ① | `【本集剧情】` 那一段的读/写边界取「第一个空行」⇒ 读回 **51 字**（整段 2090 字） | 🔴 每轮重写剧本 + 旧稿残留 |
| ② | 爆款纪律（3 秒爆点 / 爽点密度 / 段段留钩）**只有提示词、没有机器判据** | 🔴 真机剧本逐条违规 |
| ③ | 逐场节检查是**全篇级**（`briefHasMarker(brief, "钩子")`）——某一场漏写会放行 | 🟠 段段留钩有洞 |

## 1. 🔴 段边界：读回 51 字，写回留旧稿

`episodeBriefOf` / `replaceEpisodeBrief`（原实现，`strings.Index(rest, "\n\n")`）：

```
真机 source.txt：
  【本集剧情】【开场爆点】“重新检测到生命反应。”——灰纪元第八万年，…
                        ← 这里就有一个空行（模型常态）
  【场 1|归墟环·维护舱|灰纪元第八万年·第三千四百六十二标准日|内】
  …
  【本集钩子】…
  【本集原文】(素材：…) ← 平台自己写的节标记
```

实测：`strings.Index(rest,"\n\n") = 51`（整段 2090 字）。三件事一起发生：

1. **每轮重写剧本**：`briefIsUsable` 按 51 字判（结构 + 字数都过不去）⇒ `ensureEpisodeBrief` 每次都重新调 LLM
   改编、覆盖上一稿。2026-10-07 00:11 那轮日志正是现场：
   `🎬 轮到这一集了,先把原文**改编成剧本**` → `✔ 本集剧本已改编并回填(2082 字)`。
2. **静默覆盖（连备份都没有）**：备份分支的条件里写着 `len(brief) >= epScriptMinRunes(800)`，51 字过不去。
3. **写回留旧稿**：`replaceEpisodeBrief` 用同一条边界，写出的是
   `【本集剧情】+ 新稿 + 旧稿从【场 1|…】起的全部内容 + 【本集原文】` —— 每重写一轮多堆一份旧剧本，
   而【本集原文】前面那段正是**分镜要读的输入**。

**修法**（`internal/server/novels_jobs.go` / `novels_split.go`）：

* 新增 `briefEndMarkers = []string{"【本集原文】", "【本集剧情】", "【前情提要】"}` 与 `briefSectionEnd`：
  边界取**平台自己写的节标记**（拆集那一步写的是 `\n\n【本集原文】(素材：…)`），无标记则到文末。
  与"模型爱在哪里空行"无关。
* 备份门槛与"为什么重写"**解耦**：只问旧稿里有没有内容（`briefLooksEmpty`）——
  一份 600 字但真有内容的旧稿不再被静默覆盖。

## 2. 🔴 爆款纪律：真机逐条违规，判据从零到三

用户的《一、网文小说转剧本提示词指令》把改编纪律写死了四条。平台此前**抄进了提示词**
（`novels_jobs.go` sys「一、爆款开篇」/「二、改编纪律」），但**一条机器判据都没有** ——
而本仓的结论早就写死了（AGENTS.md）：**散文规则管不住模型**。

真机那份剧本逐条对账：

| 纪律 | 真机实况 | 判定 |
|---|---|---|
| 开篇 3 秒爆点：第一句极致冲突/绝境/反转/悬念，**无铺垫、无旁白起手** | 【开场爆点】=「“重新检测到生命反应。”——灰纪元第八万年，一个不该存在的编号，在死寂的维护舱里睁开了眼。」；引号里那句台词**在第 1 场正文里一次都没出现**。正文前 3 行是「镜面地板，冷白灯只亮右边一排。」「祁七单膝撑地，右手攥着枚发暗的铭牌。」「头顶黄铜环转，六个发光点，亮四个。」；冲突台词到第 6 行才起（「异动来源，硬件钢印U-80001。」） | ✕ 违规（分镜第一镜拍的是铺垫） |
| 爽点密度：每 80 字小爽点 / 每 200 字大爽点（分镜侧口径：**2-3 个大爽点**） | 4 场里 `大爽点` **1** 个（场 3），小爽点 3 个 | ✕ 违规（数量不足） |
| 段段留钩 | 4 场都有「钩子:」，另有【本集钩子】 | ✓（但判据是全篇级，见 ③） |
| 砍冗余 / 放大反差 | 需要人看 | — **不进机器门** |

**新增判据**（`internal/server/brief_viral.go` 的 `briefViralIssues`）：

1. **爆点必须被演出来**：取【开场爆点】里**引号内的台词**（没有引号时取第一个句末标点前的那一句，
   「——」后的解释性旁白不算），归一化（只留汉字/字母/数字）后必须出现在**第 1 场正文的前 3 行**内。
   为什么是 3 行：剧本正文一行 ≈ 一镜（3-8 秒）⇒ 3 行 ≈ 首 10-20 秒；仍排不进去就说明开场在铺垫。
2. **大爽点 ≥2**：数 `大爽点` 字面（写在「爽点:」节里）。
3. **逐场逐节**：每一场都要有自己的「目的/冲突/转折/爽点/钩子」+ 正文；某节在**全篇**有、但某一场漏了 ⇒
   报「第 N 场缺「X」节」。正文为空也报。

**故意不做的**：

* 「放大反差」「砍冗余的取舍」——要靠人看，进门就是天天误报，然后被忽略，等于没有。
* 「每 80 字小爽点」按字数硬算 —— 一份 2000 字的剧本会被判"该有 25 个小爽点"，那不是门是噪音；
  分镜侧既有口径同样只按 200 字卡强节拍（`internal/project/plan_checks.go`）。这里只卡"大爽点 ≥2"，
  与 `stages_script.go` 的分镜提示、`project.CoreBeats` 用的是同一个数。
* 分镜侧提示词**没有**加"必须把【开场爆点】放第 1 镜"这一条：修好剧本后，爆点就写在第 1 场正文最前面，
  而分镜读的正是正文，链路自然成立（多写一条提示词反而多一处会漂移的口径）。

## 3. 接线：一个判据入口，三处共用

`briefContractIssues(brief) = missingBriefSections + briefViralIssues`，被三处共用：

| 消费方 | 位置 | 作用 |
|---|---|---|
| 跳过判据 `briefIsUsable` | `novels_jobs.go` | 不合契约的旧稿 ⇒ **备份后重写这一集**（播报逐条列出差哪几条） |
| 生成后的自检 | 同上 | 有问题 ⇒ 把**逐条违规**喂回去**补写一轮**（`briefIssueBullets`），只做一轮 |
| 采纳判据 `adoptRepairedBrief` | 同上 | 补写稿必须"不合契约的条数真的变少且不是空稿"，否则保留原稿 |

提示词与补写指令同步改成**可执行动作**：

* 「**这句台词或动作要写成第 1 场正文的最前面 2-3 行** —— 分镜第一镜就得拍到它；写成「某年某地、某个不该存在的××
  睁开了眼」这种旁白概述不算爆点。」
* 「每场的「爽点:」节必须写明是「小爽点」还是「大爽点」，**全集至少 2 个大爽点**，写清具体是哪一下。」
* 输出格式那一节补上「**每一场**都要把这五节 + 正文逐节写全」。

## 4. 守卫与验证

夹具是**照抄的真机 source.txt**（`internal/server/testdata/ep01_source_real.txt`，18KB）——
这两处缺陷只在"模型真的这么写"时出现，自己编"两三句意思一下"的夹具一个都测不到。

| 测试 | 挡什么 |
|---|---|
| `TestBriefSectionBoundsFollowTheNextSection` | 读边界：真机那份要取回整段（≥800 字、4 个场头、不含【本集原文】）；结构判据不报缺节**但**爆款判据要报；无标记时取到文末 |
| `TestReplaceEpisodeBriefDoesNotKeepTheOldScript` | 写边界：场次数不翻倍、【本集原文】仍 1 次、旧稿那句描写不再出现、**幂等** |
| `TestViralRulesCatchTheRealScript` | 判据本身：真机两条违规都要报；合规稿**一条都不报**；爆点被挤到第 4 行 / 大爽点降到 1 个 / 第 3 场漏钩子 ⇒ 都要报 |
| `TestViralRulesAreWiredIntoTheBriefPipeline` | 接线：三处消费方 + 提示词可执行措辞 + 备份，缺一即红 |

八门自检全过；`scripts\build.ps1` 出片 17.30MB。

## 5. 重跑这一集会发生什么（如实说）

这一步修好之后，轮到第01集时：读到的旧稿是**整段 2090 字**（不再 51 字），判据会报两条爆款违规
（爆点没被演出来 + 只有 1 个大爽点）⇒ **旧稿先备份成 `source-brief-prev.txt`，然后按契约重写这一集剧本**，
生成后若仍不合契约还会**喂回去补写一轮**。也就是说：**这一集的剧本会变**（内容是新的、爆点会被放到正文最前面）。
不想让它重写就先把 `source-brief-prev.txt` 之外的那份稿子留住 —— 播报里会逐条说明改了什么。

## 6. 还没做的（别当漏项）

* 「爽点密度按字数」「放大反差」「砍冗余的取舍」仍只有提示词层面的引导（见 §2 的理由）。
* 分镜侧那两条既有机器门（`plan_checks.go` 的 G057 开篇旁白 / G058 强节拍密度）作用在**分镜**上，
  本轮没有改动它们；剧本侧的这三条是给分镜**喂料**的那一端。
* 剧本 → 分镜的"场次覆盖"（真机：维护舱一场占 7/13 镜、剧本 4 场只用了 3 场）仍是已知项，
  与告警文案问题一起记在 `docs/剧本与渲染链审计-2026-10-06.md` 的未改清单里。
