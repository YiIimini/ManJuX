# ManJuX 架构

> 技术底座:Go 1.25 + Wails v2(桌面)+ Vue 3 + Vite + Element Plus + Tailwind(界面)+ ffmpeg(合成/质检)。
> 设计目标:模块化、解耦、可扩展 —— 新增渲染引擎或管线阶段不动已有代码。

## 总体结构

```
┌────────────────────────────────────────────────┐
│ Wails 原生窗口(桌面 exe,单实例)                 │
│  ┌──────────────────────────────────────────┐  │
│  │ Vue 3 前端(embed 嵌入 exe)               │  │
│  │  Home / ProjectView / Settings + 抽屉组件  │  │
│  └───────────────┬──────────────────────────┘  │
│                  │ fetch /api/* + SSE /api/events│
│  ┌───────────────▼──────────────────────────┐  │
│  │ internal/server  REST API + SSE 事件出口    │  │
│  └───────────────┬──────────────────────────┘  │
│  ┌───────────────▼──────────────────────────┐  │
│  │ internal/pipeline 五阶段编排器(协调器)     │  │
│  │  script → assets → render → qc → assemble │  │
│  └──┬──────────┬──────────┬─────────┬────────┘  │
│  director  engine(注册表) compose  qc          │
│  (LLM直出) ├─ comfyengine(本地 ComfyUI)        │
│           └─ h3api(MiniMax 云端 API)           │
│  project(域模型/存储) config(设置) ff(封装)     │
└────────────────────────────────────────────────┘
        同进程另起独立 HTTP(127.0.0.1:8790,浏览器入口/排障)
```

## 模块职责

| 包 | 职责 | 关键点 |
|---|---|---|
| `main.go` | Wails 装配 | 窗口/单实例锁(Wails 内建)/日志 Tee/独立 HTTP |
| `internal/server` | HTTP 层 | REST + SSE;`APIHandler()` 给 Wails 直通;文件服务防路径穿越;API Key 回显脱敏;**来源守卫**(`guardAPI`:Host 必须回环 / Origin-Referer 必须回环 / 写操作必须 JSON,两条装配路径共用)。按主题拆分:`handlers_{project,asset,shot,comfy,settings,enhance}.go` + 各业务文件(原单文件 1407 行) |
| `internal/pipeline` | 编排器 | 每项目单运行实例;阶段可单跑(`phase`+`only`);事件总线(SSE 推送+环形历史回放);断点续跑(输入指纹)。拆为 `coordinator.go`(调度)+ `prompts.go`(提示词与上下文)+ `refs.go`(参考图装配)+ `stages_{script,assets,render,qc_assemble}.go` |
| `internal/project` | 域模型 | 项目/方案/资产/清单结构体;`StageParams` 阶段参数(项目级快照+Sanitize 钳制);原子写 |
| `internal/director` | LLM 直出 | H3 官方提示词规范全量内嵌的系统提示(六段式/三段式/S1-S2/`<d>` 台词/亮度护栏);JSON 容错解析+二次修复 |
| `internal/engine` | 引擎抽象 | `Engine` 接口 + 注册表;`AlignLength` 17k+5 帧网格;`SnapCanvas` 32 对齐 |
| `internal/engine/comfyengine` | 本地引擎 | 工作流程序化组装(R2V/I2V→BasicGuider 采样链);两阶段条件缓存(.pt+sidecar 记账);ComfyUI 代管启动;产物 animated 文件回收;`maskgraph.go` 局部重绘 / `upscalegraph.go` 放大 / `preflight.go` 渲染前体检 |
| `internal/engine/h3api` | 云端引擎 | `/v2/video_generation` 异步任务(10s 轮询/20min 上限);参考图 base64 data URI;**任何非成功退出路径都取消远端任务**(超时/鉴权失败/下载失败),鉴权类错误立即失败而不被当成"网络抖动" |
| `internal/library` | 跨项目资产库 | 角色/场景条目(名 + 中文描述 + 英文提示词 + `Images[]` 多图 + 来源与复用计数);同名精确复用;入库时 `relatedImages` 按主图同目录同名收集关联图(`*_turnaround.png` 转台图、`*_view_*.png` 多视角原图) |
| `internal/compose` | 合成 | 逐镜规范化重编码(禁流复制保 P 帧链)→ cut/xfade(acrossfade)拼接 → ASS 字幕 + loudnorm + faststart;SRT 同步导出 |
| `internal/qc` | 质检 | ffprobe 时长/音轨/分辨率 + ffmpeg 按**实测时长**抽 25%/50%/75% 三帧统计暗像素(抽帧失败计入 Problems,不假装通过) |
| `internal/ff` | ffmpeg 封装 | PATH/显式路径解析;Run(30min 上限+stderr 摘要);Probe |
| `internal/textutil` | 文本工具 | `Truncate` 按字符(而非字节)截断 —— 原先在 llm/comfyengine/server/h3api 四处各有一份逐字相同的实现,现统一至此 |
| `internal/fsutil` | 文件工具 | `WriteFileAtomic`(写 `.tmp` 再 rename);项目元数据/方案/清单与资产库的写入都依赖这个原子性保证 |
| `internal/config` | 设置 | data/settings.json 原子读写;默认值自适应 exe 目录 |
| `internal/tray` / `browser` | 可选 | 系统托盘 / Edge App 独立窗口(独立 HTTP 模式用) |

> 注:`internal/watchdog`(命名互斥量单实例看门狗)已在 2026-09-11 的改造中**删除** —— 单实例统一交给 Wails 内建 `SingleInstanceLock`(`main.go` 里的 `UniqueId` + `OnSecondInstanceLaunch` 唤回已有窗口),不再维护第二套机制。

## 双引擎设计

```go
type Engine interface {
    Name() string
    Available(ctx) error      // 探测 + 修复指引
    Render(ctx, Job) (*Result, error)

    // —— 通用可选能力:本地引擎实现,云端引擎给安全空实现 ——
    FreeVRAM(ctx) error
    ClearQueue(ctx)
    Interrupt(ctx)
    GenerateImage(ctx, prompt, neg string, seed int64, w, h int, outPath string) (string, error)
}
```

- **auto 模式**:先探本地 ComfyUI(存活或可代管启动)→ 不可用切云端 API;两边都不可用报可读错误。
- **每镜可重渲**(`only` 参数),manifest 记录输入指纹(提示词+资产指纹+参数+seed),同指纹产物跳过(断点续跑),资产变更自动视为过期。
- **接口收口(2026-09-11)**:`FreeVRAM`/`ClearQueue`/`Interrupt`/`GenerateImage` 原先要调用方断言 `*comfyengine.Engine` 才能用 —— 具体引擎的能力泄漏到了管线层与 HTTP 层(云端不可用却必须存在这些方法)。现提升为 `Engine` 接口方法,`h3api` 补空实现(释放显存/清队列/中断对云端无意义,`GenerateImage` 明确返回不支持),调用方只依赖接口。

## 角色多视角转台图(2026-09-11)

定妆照只有正面一个角度,转身/走位/多人同框时身份容易漂移。资产阶段生成定妆照后追加一步 `genCharacterViews`:

```
Krea-2 定妆照 → H3 Ref2V「原地缓慢转身」短视频(124 帧≈5.2s,留在 <safe>_views/ 子目录)
             → ffmpeg 按 1.3/2.6/3.9s 抽 3 帧,直接写进 assets/characters/ 下
               (命名 <base>_view_threequarter|side|back.png,与前端 labelOf 标签对齐)
             → hstack 横向拼成 assets/characters/<base>_turnaround.png
               (第一格用定妆照本身 —— 0s 正面帧与它同角度,不必再抽一份)
```

> **抽帧为什么不能放 `_views/` 子目录**(2026-09-12 修):资产库的 `relatedImages` /
> `ClearRelated` 用 `filepath.Glob(<dir>/<base>_view_*.png)` 收集与清理,glob **不递归**
> —— 帧放子目录里,多视角原图既收不进库(详情弹窗只有定妆照),重抽后也清不掉(仍是
> 上一张脸的过期角度图)。产物路径与库的 glob 是同一份契约,改动时必须成对。

- 为什么不直接用 Krea-2 img2img 出多张:Krea-2 是**纯文生图模型、没有身份条件注入机制**,只能靠 denoise 在「改动幅度」与「保住身份」之间猜(0.7 直接换人、0.55 角度几乎不变),是模型固有限制;正解是让有身份参考机制的 H3 Ref2V 来完成(与 ComfyUI-ALLinONE 的 Character Sheet 模式同源)。
- 渲染侧由 `pipeline/refs.go` 的 `AssembleShotRefs` 自动追加:`turnaroundPath` 由定妆照路径推导同目录同名 `_turnaround` 文件,**仅在文件存在时追加** —— 没有转台图的老项目参考图组成与渲染指纹完全不变。拼成**单张**是为了只占 1 个参考槽。
- 契约影响:`sysH3Format` 已改为要求 LLM「按画面内容而非下标对应 Subject」——有转台图的角色占 2 张图,场景下标不再是 N+1。
- 增强项:任一步失败只告警、不阻断资产阶段,退回单张定妆照继续。

## 镜头级增强:局部重绘与音频驱动(2026-09-11)

两项能力都从镜头卡发起,产物均落成**独立文件**(不覆盖原镜头,由用户比对后决定是否采用)。

| 能力 | 端点 | 链路 |
|---|---|---|
| 局部重绘(Mask Fix) | `POST /api/projects/{id}/shot/{shotID}/mask-fix` | `LoadVideo → GetVideoComponents` 取源帧 → SAM3 跟踪(`SAM3_VideoTrack`/`SAM3_TrackToMask`)→ `MVEx_SubjectCrop` 裁出 → `MiniMaxH3ReferenceToVideo` 重绘(裁剪出的主体仅作 `ref_images` 参考锁外观;**采样画布仍是整幅机位画面**,成本与整镜重渲同级,"局部"只体现在最后一步的羽化贴回;按裁剪尺寸采样是**尚未实现的优化项**,见 `maskgraph.go` 的 `buildMaskGraph` 注释)→ `MVEx_SubjectUncrop` 羽化贴回原帧(其余帧像素原样保留,动作因此不变);音轨沿用源视频 |
| 音频驱动(Audio Drive) | `POST /api/projects/{id}/shot/{shotID}/audio-drive` | `Job.Audios` → `ref_audios` 条件喂入 H3 Ref2V,重渲时口型与动作节奏跟随给定配音 |

- 局部重绘的 `buildMaskGraph` 只用 ComfyUI 核心节点 + MaskVidExperiments,**不引入 VideoHelperSuite 等额外依赖**;需要 SAM3 跟踪模型(`checkpoints/sam3.1_multiplex_fp16.safetensors`),缺失时无法定位目标 —— `Preflight` 只覆盖 H3 生成链的根节点,**这条链路另有 `Engine.MaskAssets()` 事前体检**(节点 SAM3_VideoTrack / SAM3_TrackToMask / MVEx_SubjectCrop / MVEx_SubjectUncrop + SAM3 权重),缺件在点下去之前就返回 409 并写明该放哪个目录。
- **目标短语是必需输入**(2026-09-24 修复):`SAM3_VideoTrack` 要求 `initial_mask` 或 `conditioning` 二者之一,而本应用没有框选 UI,所以走文本检测 —— `CheckpointLoaderSimple` 的 CLIP 槽(槽 1,SAM3 自带文本编码器)→ `CLIPTextEncode(目标短语)` → `conditioning`。此前两者都没传,节点直接 `raise ValueError("Either initial_mask or conditioning must be provided")`,该功能**必然失败**;现在引擎/API/前端三层都会拦下空目标。
- 两个端点都默认复用该镜原 H3 提示词(只把崩坏部分的描述改对,其余保持不变,重绘的局部才与原画面接得上);源镜头必须已渲染完成(`manifest` 状态 `done`)。
- 调用方统一走 `prepareShotEnhance` 取数(定位镜头 → 校验产物 → 准备源视频/参考图 → 取本地引擎),`comfyEngine()` 断言抽出一处。

## 放大后处理:LTX / ESRGAN(2026-09-11)

`comfyengine/upscalegraph.go` 在已完成的镜头上追加 2× 放大分支,两条链路都**重混源音轨**(放大只提升画面,声音原样复用):

- **LTX 隐空间 2×**:`VAEEncodeTiled(LTX VAE) → LTXVLatentUpsampler → VAEDecodeTiled`;LTX 视频 VAE 要求时间轴为 8n+1 帧,不足时复制尾帧补齐,解码后再 `ImageFromBatch` 裁回原帧数防时长漂移。
- **ESRGAN 帧级 2×**:`UpscaleModelLoader → ImageUpscaleWithModel → ImageScaleBy(0.5)` 收敛到精确 2×(ESRGAN 多为 4×)。

模型已就位(`comfyui/shared/models/latent_upscale_models/ltx-2-spatial-upscaler-x2-1.0.safetensors`、`upscale_models/4x-UltraSharp.safetensors` 与 `vae/LTX2_video_vae_bf16.safetensors`,经 `extra_model_paths.yaml` 注册)。**2026-09-24 已端到端接通**:`Upscale` 与 `FreeVRAM`/`GenerateImage` 等同属「通用可选能力」,已提升进 `engine.Engine` 接口(云端引擎给带指引的错误),端点 `POST /api/projects/{id}/shot/{shotID}/upscale`,界面入口为故事板镜头卡的「2× 放大」下拉。

**默认参数按方式成套给出**(`engine.UpscaleOptionsFor`),不是一份公共默认:`ModelName` 的含义随 `Type` 而变 —— ltx 要去 `latent_upscale_models/` 找、esrgan 要去 `upscale_models/` 找。只换 `Type` 不换权重名,隐空间加载器会拿着帧级超分的文件名去找而必然失败(2026-09-24 修的真 bug:界面选「隐空间」时正是这样)。默认文件名(含 ltx 的 VAE)同时经 `GET /api/meta` 下发给前端回显,前端不再自己记常量。

**放大链路的权重体检**(`comfyengine/preflight.go` 的 `UpscaleAssets`):与节点体检互补的那一半。`Preflight` 管「缺插件」,它管「缺模型」 —— 按本次要走的链路问 ComfyUI 的 `VAELoader.vae_name` / `LatentUpscaleModelLoader.model_name` / `UpscaleModelLoader.model_name` 三个 combo 输入,缺失即阻断提交,并写明「该放哪个文件到哪个目录」。引擎不可达时返回空(与 `Preflight` 同一条原则:连不上 ≠ 资产缺失)。

## 渲染前节点预检与冲突检测(2026-09-11)

- **`Preflight`**(`preflight.go`):渲染开始前按本次用到的 mode 校验 graph 根节点存在(Ref2V / I2V / SigmaShift),缺失即**阻止本次渲染**并给中文提示,而不是跑到一半抛 ComfyUI 原始 `node_errors`。引擎不可达时返回空(不把「暂时连不上」误判成「节点缺失」)。条件缓存与镜间接缝**刻意不列入阻断项** —— 缓存在引擎内已有自动降级,接缝缺失 ComfyUI 会回明确报文,误判会挡住整个生产。
- **`Conflicts`**:扫描 `custom_nodes/` 下已安装但未禁用的已知冲突插件(`MiniMaxH3-Cache` 的启动期 monkeypatch 会让镜间接缝必然失败),**只告警不阻断**(用户可能为其它工作流有意保留)。机制说明见 `docs/COMPATIBILITY.md` 第三节。
- 调用点在渲染阶段起点(`stages_render.go`),位于生成缺失参考图与排队之前。

## 条件缓存清理闭环(2026-09-11)

ComfyUI 侧的条件缓存数据是 `ComfyUI/models/conditioning/*.pt`,文件名只有 `s{shot}_{hash}`(projectID 只参与记账)。此前清理只删本地 sidecar 记账、不删 `.pt`,实测堆积 **4.9GB**;现在清理项目缓存时按记账一并删除 `models/conditioning` 下的对应文件,形成闭环。

## 整本小说拆集(2026-09-11 定稿:严格一章一集)

拆集把整本书切成「书名·第NN集」子项目,规则经三轮摇摆(1-2 章/集 → 每章强拆 2-3 集 → 回归 1:1)后定稿:

- **一章正好一集,严格 1:1,集数 = 章数。** 此前提示词自相矛盾:集粒度铁律说「默认 1 章 1 集」,密度公式与「不要压并事件」的表述又暗示可以多拆,结果第 1 章被拆成两集、集名对不上。
- **集名 = 章名。** 提示词要求 TITLE 取章标题原文,但 LLM 仍会自起文艺标题(实测第001章《第一万三千七百四十一号》被起成《七文一斤》);解析层用 `normalizeEpisodeTitles` 从 CHAPTERS 字段解析出章标题后**强制覆盖** TITLE(解析不出时保留 LLM 标题,不强行清空)。集名脱离章名会让「章→集」失去可对账性,章节覆盖核对随之误报缺章。
- **分镜数量不设上限。** 镜数由内容决定(内容密的一章可正当需要 15-30 镜),`MaxShotsCeiling` 30→120 只是防手改 JSON 的天文数字安全网;内容驱动(`max_shots=0`)时规划轮不预设总镜数、`normalizeSegments` 也不截断(`segMax` 取规划轮自己给出的最大镜号)。
- **拆集协议**为分节定界纯文本(`===EP N===` + TITLE/CHAPTERS/BRIEF 行标签,`parseEpBlocks`),JSON 路径降级为兜底 —— brief 携带大段中文台词,JSON 的六类结构错误轮番炸(见 CHANGELOG v0.33.16)。全本按章切块、多段并行(默认 3 路)拆解。
- **护栏**:`checkOneChapterPerEpisode` 检测「一章被拆成多集」并告警(**不自动合并** —— 合并要重排 Brief 与集号,风险高于收益);章节覆盖核对时,若某集缺【本集原文】附着,`epCoveredChapters` 退回全文扫描;警告文案会交代代价(缺章在最前面时,自动补缺意味着删除全部分集后重拆)。

## 关键工程纪律(源自 H3 生产实践)

1. 帧数 17k+5 网格(Go 负数取模已归一);宽高 32 整除、短边 ≤768。
2. UNET/LoRA 文件名大小写敏感,配置须与 ComfyUI 实际文件一致。
3. trim/拼接必须重编码(H3 源仅首帧 IDR);成片必须 +faststart。
4. 音频 VAE 缺失 = 黑屏;H3 产物自带 32kHz 立体声,不另做 TTS。
5. 缓存名带 项目_镜头_指纹 前缀,防跨项目串用。

## 数据流(渲染一镜)

```
Job{prompt, refs, w×h, length, seed, steps}
 → engine 选择(auto/comfy/api)
 → [comfy] 参考图上传 → encode(CondSave 缓存命中则跳过) → 采样图提交 /prompt
          → 轮询 /history(progress 事件) → animated 产物下载到 clips/
 → [api]   content[] 组装(text+reference_image) → 创建任务 → 10s 轮询 → 下载
 → manifest 落盘(状态/指纹/引擎) → SSE 镜头完成事件 → 前端卡片点亮
```


## ComfyUI 进程治理(2026-09 定稿)

停止/直接退出=代管主进程树杀(taskkill /T /F,CREATE_NO_WINDOW 防闪黑窗)+ gopsutil 全系统扫描 rootDir 下 python(exe 前缀或命令行命中 main.py;RootDir 为空守卫绝不误杀),等主进程消失再清 pidfile;空闲自动退出仅停代管(stopManagedOnly,外部实例不碰)。代管 PID 持久化(pidfile),应用重启自动接管(gopsutil 验 python 身份,托盘手杀不误认领)。全部子进程经 sysexec.Hide(CREATE_NO_WINDOW),桌面端零黑窗。

## 上传管线:JSON 双通道(2026-09-09)

桌面 webview 经 wails 资产代理发 multipart 大文件会被截断为 0 字节(角色自定义上传「源图不存在」根因)。全站上传改 JSON:点击选择 → 前端 FileReader 转 base64(canvas 预压缩 ≤1600px)+ `image_b64`;桌面拖放 → wails 原生 DragAndDrop/OnFileDrop 给出本机绝对路径 + `image_path`。后端 `imagePayload.resolve()` 统一落成本地文件(角色库新建/项目资产/封面三处),multipart 入口保留给浏览器模式;拖入预览走 `GET /api/thumb?path=`(仅图片扩展名,≤64MB)。

## 系列角色一致性:书级 roster + 锚定种子(2026-09-09)

跨集换脸根因:每集分镜由 LLM 独立撰写,同一角色形象描述措辞漂移,文字拉偏画面(同集内镜头间一致、两集定妆照 md5 相同仍换脸的实证定位)。三层修复:①runScript 注入书级 roster——扫描同系列兄弟集 plan/plan.json 已确立的角色「名+description」强制沿用(新角色放行);②渲染默认种子按镜头角色组合派生(fnv 哈希,替换 time.Now 随机);③Krea2 定妆种子改 fnv 全串哈希(原长度哈希易撞)。第一道防线仍是资产库同名精确复用(字节级同图)。

## WebView2 稳定性(2026-09-09)

这一类问题是**两个独立成因、两条独立修法**,不要混为一谈(踩过:把两者当成一件事之后,
第二个成因复发时被误判为"GPU 那条没修好"):

1. **渲染期 GPU 挤崩**(2026-09-09):渲染采样期 GPU 满载会挤崩 webview 的 GPU 进程,
   而 go-webview2 对失效 webview 的兜底是 `os.Exit(1)` 整进程退出。
   修复:`windows.Options{WebviewGpuIsDisabled: true}`(界面为 DOM 型,软件合成足够;
   `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS` 环境变量在 WebView2 152 实测无效)。
   满载压测(100% GPU/18GB 显存 + 窗口聚焦悬停)存活验证通过。
2. **原生对话框开闭期的焦点瞬时错误**(2026-09-09 同日实证):`onFocus → Focus →
   errorCallback` 崩溃栈两次完全一致,成因是对话框持有焦点时 `MoveFocus` 返回瞬时错误。
   这属于 go-webview2 上游行为,**靠 wails 选项修不了**,得改依赖 ——
   本地打了补丁走 `replace` 接入,细节与自检见 **`third_party/README.md`**。
   删掉那个 `replace` 或重新同步上游会让它静默复发。
