# 剧本为主源、原文只是素材 — 2026-10-08

用户口径（原话）：

> 文章内容转剧本，需要的是 LLM 提取内容分析总结后输出**爽文爆点剧本**（根据剧本内容再完善输出分镜脚本），
> **而不是去要求原文内容怎样怎样**。

这份文档回答：这句话对应的**代码事实**是什么、这次改了什么、判据在哪、还差什么。

---

## 1. 取证：哪一步在"要求原文"

先说清楚**已经有的**（不是缺口，别当成没做）：

- **专职编剧会话**（`internal/server/novels_jobs.go`）：system 提示词逐条来自作者的《一、网文小说转剧本提示词指令》，
  产出**结构化剧本** —— `【开场爆点】` + 逐场 `【场 N|地点|时间|内外】` 五节（目的/冲突/转折/爽点/钩子）+ 正文
  + `【关键道具与信息】` + `【本集钩子】`，还带**契约门**（`briefContractIssues`：爆点有没有真的演在第 1 场正文最前面、
  大爽点够不够 2 个、每场五节齐不齐）与**补写一轮**（生成 → 机器判定 → 喂回去重写）。
  真机日志形态：`🎬 轮到这一集了,先把原文**改编成剧本**(专职编剧会话)` → `⚠ 本集剧本有 1 条不合契约…喂回去补写一轮`
  → `✔ 补写一轮:不合契约从 1 条降到 0 条` → `✔ 本集剧本已改编并回填(2626 字)`。
- **剧本落盘位置**：写回同一份 `source.txt` 的 `【本集剧情】` 段（与 `【本集原文】` 并列），拆集/写回边界是平台自己的节标记。

**不对劲的是分镜那一步**（三处，都是代码事实）：

1. `internal/director/director.go` 的 `withSettingBrief` 返回的是
   `设定集 + "\n\n【本集原文】\n" + 材料` —— 而**材料里同时含【本集剧情】(剧本) 与【本集原文】(小说原文)**。
   贴上那个标签之后，模型看到的只有"一份原文"，剧本/素材的分工**被抹掉了**。
2. `internal/pipeline/stages_script.go` 给模型的提示是 `ADAPTATION IS A REWRITE, NOT A COPY…① 先提炼…④ 输出的是核心分镜`
   —— 让**分镜阶段**自己"从原文提炼爽点、重建分镜"。那本是编剧会话的活；重做一遍的结果是两头都不作数，
   而且模型自然会围着原文的段落顺序排镜头（"去要求原文内容"的最直接来源）。
3. **剧本缺失时静默按原文硬跑**：脚本阶段只判 `strings.Contains(text, "【本集原文】")`，
   从不检查 `【本集剧情】` 在不在、是否为空 —— 于是"没有剧本"这件事在日志里看不见。

## 2. 改法（判据只写一处，四个消费方共用）

1. **段落边界收进 `internal/project`**（新文件 `source_sections.go`）：`EpisodeBriefSection` / `EpisodeSourceSection`
   / `EpisodeSectionEnd` / `EpisodeBrief` / `EpisodeOriginal` / `EpisodeSourceParts`。
   `server` 侧的 `briefSectionEnd` / `episodeBriefOf` / `episodeOrigOf` **改为委托**（名字保留，调用点很密）。
   判据本体只有一份 ⇒ 写剧本的一侧与读剧本的一侧永远看同一个边界。
   （边界为什么不能用"第一个空行"：真机那次只取回 51 字 ⇒ 剧本被每轮重写、写回还堆旧稿，教训写在文件头。）
2. **材料原样 + 主源分工**（`director.sourceRoleClause`，接在 `withSettingBrief` 里 —— 四条生成路径全过这一处）：
   - 剧本 + 原文都在 ⇒ 「【本集剧情】是**剧本**（专职编剧已完成提取/分析/总结）：分镜**逐场**按它组织 ——
     第 1 镜拍【开场爆点】那一下、台词逐字取自它、每个大爽点都要有对应镜头。【本集原文】只是**参考素材**：
     仅用于补细节与核实；**不得**用它替换、重排或稀释剧本的场次/爽点/钩子。」
   - 只有剧本 ⇒ 同一句（去掉原文那半）。
   - **没有剧本 ⇒ 直说"没有剧本"**，并给出退路（按原文组织：先提炼核心冲突与 2-3 个大爽点、砍冗余、允许跳段）。
   - 两个标记都没有（技能侧导入的包）⇒ 不塞噪音（返回空串，行为与改动前逐字一致）。
3. **剧本阶段按剧本排、缺剧本如实播报**（`stages_script.go`）：
   有剧本 ⇒ `SCRIPT FIRST: …分镜**逐场**按剧本组织…原文只用于补细节与核实` + 播报「以**剧本**为准排分镜（剧本 N 字…）」；
   没剧本 ⇒ **warn**「本集**没有剧本**（材料里找不到【本集剧情】，或它是空的）—— 分镜只能按小说原文组织」；
   并删掉 `ADAPTATION IS A REWRITE`（不再让分镜阶段重做编剧的活）。

## 4. 边界与未做的事（别把这节读成"全好了"）

- **这次只钉"谁当主源"**。剧本本身的质量（爆点是不是真爆、爽点密度、台词锋利度）仍由编剧会话 + 契约门管；
  契约门只判**确定性**的东西（爆点在不在正文最前、大爽点够不够、每场五节齐不齐），"好看不好看"不进机器判据。
- **存量项目不用改文件**：`source.txt` 的结构没变，判据只是被拆开读了。
  但**已经生成的分镜不会自动变** —— 要看新口径得重跑「剧本分镜」（剧本已在盘上，**不必**重跑编剧那一轮）。
- **运行里的 app 需重启**才用上新 exe（旧进程仍是旧代码）。
- 分镜"逐场覆盖剧本"目前是**提示词级**约束 + 播出前已有的一道对账（`project.SceneCoverageIssues` 报场次覆盖问题）；
  "每一场是否都有镜头"还没做成**致命门**（现有行为是 warn 点名，见 2026-09-30 那条改动）。
