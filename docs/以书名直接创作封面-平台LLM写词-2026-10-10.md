# 以小说名称直接创作封面（词由平台 LLM 写）（2026-10-10）

用户两问：**「不能以小说名称直接创作封面吗？」** → 补上"一键按书名出封面"之后，
**「平台有LLM功能啊」** → 对，封面词是**创作**，不该由我拼模板句。

这一轮把封面词从"我拼的模板"改成"**平台 LLM 按这本书写**"，并把它接进两条一键入口；
同时修掉上一轮埋下的一个**与平台自身口径冲突**的错（模板词是中文）。

---

## 一、三档来源（唯一出处 `novel_cover_prompt.go` 的 `coverPromptFor`）

| 档 | 谁写的 | 什么时候用 |
| --- | --- | --- |
| ① | 技能端留档 `封面/pos-qwen21.txt` | 有就用，且**不调 LLM**（技能端写过一版就尊重那一版） |
| ② | **平台 LLM**（书名 + 本书风格串 + 立项简介 + 正文开头 800 字） | 没有留档词时**默认走这条** |
| ③ | 模板 `coverSeedPrompt`（书名 + 风格 + 竖版口径） | ② 拿不出可用结果时兜底，**如实标注"模板兜底（LLM 没参与）"** |

`From` / `Note` 两个字段把"这行词是谁写的、清掉了几个字、LLM 为什么没参与"带出来，
日志（`🎨 封面候选…正向词来自:…`）与弹窗都**照实显示**，不许把兜底说成 AI 写的。

## 二、两条硬约束（都是平台自己的口径，不是我定的口味）

1. **正文必须是英文** —— 出图装配只吃英文提示词，汉字注解会被模型当"要画的字"照抄
   （`pipeline/artstyle.go` 里那条 `StripCJK` 注释）。
2. **书名要出现在封面上，就必须放进英文引号** —— 官方 ON-SCREEN TEXT 的判据是
   「没被英文引号括起来的文字，就是模型会画成字形的来源」（`project/prompt_cjk.go` 顶上那段）。
   于是判据很干脆：**词里引号之外不许出现任何汉字，引号内只有书名**。

**上一轮我埋的错**：那份模板词整句是中文（`《书名》的小说封面主视觉（竖版 3:4）。构图：单一主视觉…`）——
按上面第 1 条，那等于让模型把"下三分之一留出标题位置"这类**说明**也当字形画到封面上去。这一轮改成
英文正文 + 引号里的书名，模板与 LLM 两条路都守这条判据（门直接钉"引号外汉字数 == 0"）。

LLM 的输出平台侧统一收口（不喂回去重写：出图前的一次性动作，清+判+兜底更快也更可判）：
剥围栏/标签 → **清掉引号外的汉字** → 模型漏了书名标题句就补一句 → **再判够不够成句**
（`coverPromptUsable`：≥60 字符、≥6 个英文单词），不过就退模板。

## 三、三条入口都通到同一处

| 入口 | 走哪档 | 结果 |
| --- | --- | --- |
| 菜单 **「按书名出封面」**（新） | `coverPromptFor` | 出 3 张候选 → **直接进左右对比**挑，挑定才落盘 |
| 视频制作 **「这本书没有封面图时，按书名先生成一张封面」**（新，默认勾） | `coverPromptFor` | 拆集**之前**出 1 张并落盘 → 拆出来的每一集都有封面 |
| 封面重做弹窗里的 **「AI 按书名写词」**（新） | **强制走 LLM**（`/api/novels/cover-prompt`） | 写好的词落进文本框（可继续改）→ 再点「生成候选」 |

弹窗打开时仍给**模板词**（毫秒级，不让用户等模型）；想要 AI 的，点那个按钮。
`config` 另回 `llm_ready`，LLM 没配置时按钮置灰并说明 —— 不让用户点了才报错。

落盘一律走**同一段** `applyCoverCandidate`（旧封面先备份 → 按后缀落盘 → 刷新这本书的集项目封面），
"挑定候选"与"按书名出的那张"共用它，免得只在一半路径上做备份/刷新。

## 五、门与反向验证

`internal/server/novels_cover_produce_wiring_test.go` 新增 7 条（本轮共 16 条）：

| 门 | 钉什么 |
| --- | --- |
| `TestCoverPromptForPrefersArchivedThenLLM` | 有留档 ⇒ 用它且**一次 LLM 都不调**；没有 ⇒ LLM 写（`calls()==1`）、词里有引号书名 |
| `TestCoverPromptForStripsCJKOutsideQuotes` | 引号外汉字清光、引号里书名留住、清掉几个字写进 Note；**且平台不许替模型补书名** |
| `TestCoverPromptForFallsBackWithHonestNote` | 整段中文 ⇒ 判不可用走模板 + Note 说清；LLM 没配置 ⇒ 同样兜底 + 说清原因 |
| `TestCoverPromptEndpointForcesLLM` | `/cover-prompt` **强制走 LLM**（有留档也走）；LLM 挂了回模板 + 说清（200，不 500） |
| `TestSeedCoverFromTitleWithoutEngineKeepsExistingCover` | 无引擎 ⇒ 报错说清、**不动现封面**、不造候选目录 |
| `TestTitleCoverIsWiredIntoProduceAndMenu` | 视频制作真的调 `seedCoverFromTitle`；前端菜单项/弹窗按钮/复选框/`auto_cover` 都在 |
| `TestCoverConfigOpensWithoutArchivedPrompt`（改） | 模板词：**引号外 0 汉字** + 书名在引号里 + 英文竖版口径 + `llm_ready` 字段 |
| `TestNovelCoverRedoGuards`（期望反转） | "没有留档词要 400" ⇒ 改成 503（**已经拿到词、走到了出图那一步**） |

**反向验证 9/9 全红**（`scratch/reverse_verify_cover_llm.ps1`）：LLM 档拿掉 / 引号内也清 /
引号外不清 / 先补书名再判成句 / 有留档也先调 LLM / 接口不再强制 LLM / 先造目录再查引擎 /
视频制作接线被拔 / 菜单项被删 —— 每一根针都让对应的门变红。

**这一轮被自己的门咬出 2 处**（都不是读代码读出来的）：
1. `cleanCoverPrompt` 第一版是"先补书名句、再判成句" ⇒ 整段中文的输入被补成
   「， ， 。. The cover title text "《书名》" typeset clearly on the poster.」，英文词数够 6、长度够 60，
   判成了"可用"（`TestCoverPromptForFallsBackWithHonestNote` 当场红）⇒ 改成**先判模型自己那段**。
2. `TestCoverPromptForStripsCJKOutsideQuotes` 第一版只看"引号里还有书名" ⇒ 把引号内的书名也清掉时，
   平台补一句就把它掩盖过去了（**判据挂在会被下游补写的数据上**，AGENTS 明令禁止的形态）
   ⇒ 加"Note 里不许出现『平台补了一句』"（反向针 N2 当场把它咬出来）。

## 六、边界（如实说）

* **没跑真机出图**：ComfyUI 不在线，所以"书名能不能被 Qwen-Image 2.1 画对"**没有验证** ——
  这一轮只保证"词是平台 LLM 按这本书写的、且守平台自己的口径"。出图效果要等引擎在线再看。
* **正文开头只给 800 字**（`coverPromptExcerptChars`）：够看出主角与基调，不是让模型复述剧情。
* **视频制作的自动出封面默认开**：书没有封面图时会多花约 1 分钟 GPU（对话里可见、可关）；
  出图失败**如实播报**并退回"没有封面图"那句共用说明（集项目封面仍按 `projectCover` 的既有兜底）。
* 散文件小说（小说库根下直接一个 `.md`/`.docx`）仍然做不了封面重做：没有书目录就没有 `封面/`
  —— 菜单置灰 + 后端 400，永久边界。
