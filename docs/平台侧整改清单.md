## 一、必须做

### 1.1 渲染期追加的 `PICTURE MANIFEST` 是**最后一块**，且它自己写中文名 —— 需要"收尾复位"

- **证据（顺序）**：`internal/pipeline/stages_render.go:245` 先 `prompt := ShotRenderPrompt(...)`
  （其内部链是 `prompts.go:327`：`anchorPrompt → EnsureChineseDialogue → EnsureOnScreenTextRule → EnsureVoiceInline`），
  **然后**在 `stages_render.go:261` 才 `prompt = EnsureRefManifest(prompt, shot, roles)`。
- **证据（内容）**：`internal/pipeline/refmanifest.go:57-76` 每条清单行都写 `r.Name`（中文名，如「翻篇」）。
- **风险**：官方 ON-SCREEN TEXT 规则的判据是——**没被英文引号括起来的文字，就是模型画成字形的来源**。
  技能侧 v2.3 刚把提示词里的中文清干净（实测《翻篇》第 01 集 `<d>` 外 **7083 字 → 可避免的 0**），
  而平台在**最后一步**又追加一段中文名，且它**后面再没有任何"不得画字"的收尾**——
  等于前面 7000 字的清洗被最后一段抵消。你们 `voice_bind.go` 的注释本身也记过同族事故
  （"提示词里那些短英文行被当成要打字幕的一行"）。
- **动作（二选一，推荐 a）**：
  - **a（便宜、全覆盖）**：`EnsureRefManifest` 追加完之后**再补一句收尾**（可复用 `onScreenTextMarker` 的第 ②/③ 条，
    或就一句短句）：`The names and numbers in this manifest are production notes, not visible text: never draw, caption or subtitle any of them.`
  - **b（更彻底）**：manifest 里的主体改用 **S 号 + ASCII 身份**（技能侧 `subject_definitions` 里已经有 `(S1)` 与英文身份句，
    可直接对齐），中文名不再出现在最后一块。
- **判据（可机检）**：`stages_render.go` 拼装完的**最终提示词**，尾部 300 字符内不应出现**无防护的连续汉字串**。

### 1.2 把"汉字卫生"写进两侧共守的规则表（`internal/project/plan_contract.go`）

- **背景**：契约的既有纪律是「**一张规则表，两侧各跑一遍**」。
- **证据**：`internal/project/plan_contract.go` 目前**没有任何汉字/CJK 门**（只有与字幕/旁白相关的注释）。
- **技能侧已加（v2.3，可照抄口径）**：`<d>` 外**可避免的**汉字 **>200 → fail**、**>60 → warn**；
  `keyframe_prompt` 出现任何汉字 → warn。
- **动作**：平台侧 `validatePlan` 加同源一条，导入时守门。这样**别的书**与**平台 LLM 直出路径**也能被拦住，
  而不是只有 `screenplay_plan.py` 出的包干净。
- **⚠ 阈值口径必须一致**：**扣掉主体名**——官方要求"用文字点名主体"（供 `PICTURE MANIFEST` 对齐），
  9 个角色同镜时名字本身就近百字；不扣就会天天误报，真出问题时反而被淹掉。

### 1.3 单镜时长下限**三处口径不一致**，且云端下限是 5 秒

| 位置 | 现在写的 | 证据 |
|---|---|---|
| 平台自己的 SystemPrompt（LLM 直出路径） | **4–8 秒** | `internal/director/director.go:47`、`:53` |
| Go 常量 / 计划契约 | **4–10 秒** | `internal/director/dialogue.go:30-31`；`project.PlanMinShotSeconds`（`plan_contract_ext_test.go:25-29` 只断言了这两处相等） |
| **云端引擎实际** | **≥5 秒** | 你们清单 §2.2 |

- **后果**：
  ① 平台 LLM 直出路径会**稳定产出 4 秒镜** → 云端静默抬成 5 秒（成片比计划长，且现在只是"如实记账"）；
  ② SystemPrompt 的 **4–8** 比契约的 **4–10** 更窄 → 长台词镜被迫拆得比需要的更碎。
- **动作**：把下限**同源成一个常量**（推荐 **5–10**；若本地引擎确实吃 4 秒，就只在下限处按引擎分档），
  并把 SystemPrompt 的文案也纳入断言——`plan_contract_ext_test.go` 现在只断言了 `dialogue.go ↔ project` 两处，
  **SystemPrompt 里那句"4-8 seconds"没有闸门盯着**，会继续漂。

### 3.1 `<d>` 通道本身会不会被画出来（唯一还没验的假设）

- **现状**：技能侧已把 `<d>` **外**的汉字清到"只剩官方要求保留的主体名"。

  技能侧**无法自证**：H3 是音视频同一次生成，把 `<d>` 摘掉就没有原生中文配音了，不能靠"技能侧少写点"解决。
- **动作**：出一集实拍（建议第 01 集，5:20，最省）判定。若成片仍有字，三条路选一条：
  - **a（推荐先做）**：平台侧在**后处理**加一道**画面文字检测**（抽帧 OCR，命中就标记该镜/报警）。
    便宜、可自动化，而且顺带成为"字幕回归"的长期监控——不依赖任何人记得检查。
  - **b**：若 H3 支持把台词放到**单独的音频条件字段**（不混在 `detailed_description` 里），
    则技能侧把 `<d>` 从描述段迁出去（这是**格式级**改动，两边要同版本号一起改）。
  - **c**：都不行就接受"字幕由后期加、模型烧的一律重渲"，并把这条写进契约的**已知边界**，
    别让它继续以"以为已经解决了"的形式挂着。
- **这一条我不打包票**：技能侧能做的已经做完（`<d>` 外可避免的汉字 = 0）；剩下的是 H3 通道本身的特性。

# 追加（2026-09-26 晚）· 造型变体 / 人物比例

> 起因：用户问「角色的服装发型会随剧情而改变吗？」＋「《求你们骂我》主角和女角的人物渲染比例不是黄金比例，太丑了」。

## 四、必须做（造型变体）

### 4.1 变体卡必须**从主卡图生图派生**，不许各自文生图

- **背景**：造型要随剧情变（用户规则「造型不得一成不变」），而契约是"一人一卡、锁造型"
  （`retention_analysis` 要求 `face shape, hairstyle and costume` 照抄参考图）。技能侧的解法是
  **把每个造型档做成一张独立的卡**：主卡 `翻篇` ＋ `翻篇·归零`／`糖球·雨夜`／`老墙·认错`……
  （名字带档名，所以 PICTURE MANIFEST 仍能逐张对上；声线与 `sid` 继承主卡，换档不换嗓子）。
- **风险（必须由平台侧兜住）**：每张变体卡若**各自文生图**，同一角色的几张脸会漂——
  实测教训就在 `refmanifest.go` 的注释里（"同一角色逐镜不同人"）。
- **动作**：定妆照生成时，**同角色的变体卡以主卡为 `--init-image` 图生图派生**，指令写死
  `Change ONLY the costume / the stated state. Keep the face, muzzle shape, fur colour and markings EXACTLY as the reference.`
  （与技能侧 `封面工艺卡 §2.5` 的后备路径同一套口径）。
- **判据**：同一角色的两张变体卡之间，脸型/毛色/印记应能过你们自己的**逐帧身份校验**；过不了就重出变体。

### 4.2 接缝/资产逻辑要把"同角色的多张卡"当**一个人**

- **证据**：`refmanifest.go` 与接缝策略都按 `scene`（以及 subject 身份）做事；变体卡的 `id` 不同
  （`char_01` / `char_01v4`），但**名字共享前缀**（`翻篇` / `翻篇·归零`）。
- **动作**：凡按"角色"聚合的地方（资产库列表、接缝重置、人物面板分组），**按名字前缀归为同一人**，
  不要显示成两个新角色；跨集复用时也别把变体当成"新角色需要重新定妆"。
- **建议的判据**：`id` 形如 `char_NN` 与 `char_NNvK` 视为同一角色的第 K 档；名字形如 `X` 与 `X·档名` 同理。

## 五、必须做（人物比例 —— 定妆照"太丑"的直接原因）

### 5.1 定妆/镜头的脸与人体比例要给**可核对的锚点**，不能只给风格词

- **实测病根**：技能侧旧口径只写风格词（`Clean anime-style face, clear-cut jawline, large bright eyes`），
  **没有任何比例**，于是模型各按各的审美发挥：脸被拉长、三庭不匀、眼距失衡、头身比失调 → 丑。
- **技能侧已加**（`manju_plan.HUMAN_PROPORTION_CLAUSE`，人体卡自动带）：
  眼线在头部垂直中线／两眼间距＝一个眼宽／鼻长约脸长 ⅓／嘴约 ⅕／下巴宽约颧骨 ⅔／颈细长／
  肩宽约两个头宽／身高**七个半头**、腰细腿长；并明写 `Never distort these ratios, never lengthen the face and never enlarge the eyes`。
- **平台侧要做的两件事**：
  1. **别覆盖它**：你们取景重写（`entity_prompts.go` 的 `RewriteSheetFraming`）与
     `styleExpand` 的介质块若也带比例/脸型措辞，**以技能侧的比例句为准**（同一段里两套比例＝模型取中值）；
  2. **加一条自检**：定妆照出来后按你们已有的脸部关键点测量（若已有）核对三庭与眼距，
     偏离阈值就报出来——**"丑"以前是主观的，有锚点后它就是可测的**。
