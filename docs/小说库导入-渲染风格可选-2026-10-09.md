# 小说库导入制作：渲染风格可选（2026-10-09）

用户原话：「小说库导入视频制作时，用户需要选择对应的渲染风格，目前所有视频渲染风格都是一样的」。

结论：**导入那一步原来没有选择入口**（风格写死取小说目录 `立项.json` 的 `art_style`），
而且**项目参数里那个多选也压不过它**（会被分镜侧的代码级覆写按旧串盖回去）——
两处一起造成了"所有片子看起来一个风格"。这一轮把两处都改成**确定性**的：

- **导入时能选**（预设多选 + 自由文本附加），选了就是本剧的**权威风格串**；
- **项目参数里改了也生效**（同步平台自有的「全局风格:」那一行，幂等）；
- 不选 = 保持改动前的行为（沿用原书/立项的风格串），一个字都不变。

---

## 1. 先取证：风格这条链到底谁说了算

| 环节 | 位置 | 事实 |
|---|---|---|
| 导入入口（前端） | `frontend/src/views/NovelsView.vue` 的 `produce()` | 原来只有一个 `ElMessageBox.confirm`，**没有任何风格输入** |
| 导入请求体 | `internal/server/novels_produce.go:21-24` | 只有 `path` / `max_episodes` |
| 风格来源 | 同上 `133-145` | 只读小说目录 `立项.json` 的 `art_style` |
| 写入每集输入 | `internal/server/novels_split.go` 的 `createSeg` | 写平台自有行「全局风格:%s」 |
| 读回并**强制生效** | `internal/director/director.go` 的 `extractGlobalStyle` + `enforceStyleLock` | 每轮**代码级覆写** `plan.Style`（跨集一致的最终保障） |
| 项目参数里的「渲染视频风格」 | `frontend/src/components/ParamsDrawer.vue:167` → `Script.Styles` | 只经 `stages_script.go:51` 的 `composeStyleHint` 变成**给模型的一句提示**，最终仍被上面那条覆写盖回旧串 |

所以"风格由谁定"本身是确定的（好事），坏在**只能由立项定**，且用户改哪儿都改不动。
按 AGENTS.md 的纪律（能确定性做到的事不要让模型自觉），修法必须是"用户的选择 → 权威串 →
那一行 → 逐镜 plan.Style"这条确定性链，而不是"给模型加一句提示"。

## 2. 修法

### P1 导入制作时可选择（新增入口）

- 前端 `NovelsView.vue`：卡片菜单的「视频制作」与详情弹窗的「一键视频创作」都先弹一个
  **风格选择框**（预设多选 + 风格附加要求），确认后才开跑；清单来自 `G.metaStyles`
  （后端 `/api/meta` 是**单一真源**，前端不抄第二份，免得漂移）。
- `store.js`：`novelProduce(path, max, styles, styleHint)` → 请求体带 `styles` / `style_hint`。
- 后端 `internal/server/novels_style.go` 新增**纯函数** `resolveImportStyle(briefStyle, styles, hint)`
  与类型 `importStyle`，裁决优先级写死：

  | 情况 | 结果 | `From`（来源档） |
  |---|---|---|
  | 用户勾了预设 / 写了附加要求 | `pipeline.ComposeStyleHint` 拼出的串（**覆盖**立项串） | `user` |
  | 没勾没写，但立项有 `art_style` | 立项串（**老行为不变**） | `brief` |
  | 都没有 | 空（由分镜会话自定，之后仍被那一行锁定） | `llm` |

  勾了平台不认的 key ⇒ **如实点名**（不静默吞掉，也不连坐吞掉同批里认得的项）。
- `novels_split.go`：用户真的选了（`len(style.Styles) > 0`）时，把选择**写进每一集的项目参数**
  （`Script.Styles` / `Script.StyleHint`）—— 项目参数抽屉看得见、重跑「剧本分镜」时 hint 一致；
  没选则**不动默认值**。播报按来源分档（"你在导入时选的 X" vs "立项 art_style"），
  不许把用户选的串说成立项给的。

### P2 项目参数里改风格 ⇒ 让它真的生效

`handlers_project.go` 的 `putParams` 在存完参数后调用 `syncGlobalStyleFromParams`：
把用户选的串**同步写进平台自有的「全局风格:」行**（`setGlobalStyleLine`）。
不这么做，分镜每轮都会用 `enforceStyleLock` 按那一行的旧串把 `plan.Style` 覆写回去 ——
这正是"我在项目参数里改了风格，成片没变"的原因。

边界（有意为之，别当 bug 修）：

- **只动那一行**：其余内容（抬头、【本集剧情】、【本集原文】、锚表）**逐字不动**；
- **幂等**：已经是这个串 ⇒ 不产生任何写入（参数抽屉会被反复保存）；
- **空选择 = 什么都不做**：把"取消勾选"解释成"清空风格"会毁掉原有的风格串；
- 缺那一行（技能侧历史包 / 手改过的输入）⇒ 插在抬头之后，其余原样；
- 读不到 / 写失败 ⇒ **如实播报**"参数存了但输入没跟上，分镜仍按旧串锁定"，不假装成功。

## 3. 判据（一条规则一条测试）

| 测试 | 钉住什么 |
|---|---|
| `internal/server/novels_style_test.go` `TestResolveImportStyle` | 裁决三档优先级、多选拼接、未知 key 点名且不连坐、只写自由文本也算用户要求 |
| 同上 `TestSetGlobalStyleLine` | 只动那一行、幂等、空风格不动、缺行插位（抬头之后）、读回判据与写入口一致 |
| 同上 `TestGlobalStyleLabelMatchesDirector` | 「全局风格:」是**跨包契约**：server 写、director 读，标签漂移即红 |
| `internal/server/novels_style_wiring_test.go` `TestFrontendNovelProduceWiresStyle` | 前端真的先弹选择框、真的把 `styles/style_hint` 传出去、两个入口都不再直接开跑、清单不硬编码 |
| 同上 `TestBackendStyleChoiceLandsInProject` | 选择写进每集项目参数 / 播报分来源 / `putParams` 调了同步 / 未知 key 有播报 |

都不会对"界面加了输入框但请求体没这个字段"报错，只有接线门咬得住。）

## 4. 反向验证：9/9 全红（`reverse_verify_style.ps1`）

① 用户选的风被忽略（`ComposeStyleHint(nil,"")`）② 未知 key 不点名 ③ 同步不幂等
④ 空风格也去动输入 ⑤ 缺行时插到抬头之前 ⑥ 前端请求体不带 `styles`
⑦ 选择不写进每集参数 ⑧ `putParams` 不同步那一行 ⑨ director 侧标签漂移（跨包契约）。

每针都"改坏 → 指定测试必须变红 → 从备份还原"，跑完 6/6 文件 sha256 与基线一致。

## 5. 边界与"还没做"（说清楚，不假装完美）

- **存量项目不会自动变**：已经建好的项目里那一行还是老串。要让某集换风格：进「项目参数」勾一次
  风格并保存即可（P2 会把那一行同步掉，播报会说明"原值是什么"）；或重跑导入。
- **「脚本创作」（导入技能侧脚本包）入口没带选择**：那条路导入的是**技能侧已产出的脚本包**，
  风格本来就在包里（`plan.style`）。要改仍走项目参数（P2 已生效）。
- **多选 = 组合**：与项目参数的语义一致（平台的预设之间本就可组合）；本轮**不做**"冲突检测"
  （没有可靠判据说哪种组合一定矛盾，乱拦反而会拦掉用户要的效果）。
- **VLM/观感不在本轮判据内**：这一轮的判据只保证"用户的选择确定性地成为权威串"，
  至于某种风格出来好不好看，仍要靠出图/出片复核（有专门的 A/B 工具：
  `cmd/renderone -phase qc|assemble`、`cmd/imagecheck`）。

## 6. 过程中被仓库自己的门咬住的一处（如实记）

第一版把 `importStyle` 的来源档字段命名为 **`Source`**（`Source: "user" / "brief" / "llm"`）——
立刻被 `internal/project/source_label_test.go` 的 `TestEveryAssetSourceHasALabel` 咬住：
那门扫全仓 `source[:=] "字面量"` 的写法，要求每个**资产来源**都有中文名 ⇒ 我的三个"风格来源档"
被误当成资产来源，报"这些资产来源没有登记中文名"。

**改法**：把字段改名 `From`（风格来源档不是资产来源，不该往 `assetSourceNames` 里塞假标签）。
教训：**跨模块的字段名/枚举值要避开平台既有词汇**（`Source` / `user` 这类平台已有语义的词），
否则会被那道门正确地拦住 —— 这一次是门帮了大忙，不是门太严。
