# 质检阶段不停闪终端窗口 —— 两处漏了「无窗口」包装的子进程（2026-10-09）

用户原话：**「分镜渲染完成后进行质检时一直不停重复 显示/关闭 终端窗口」**。

## 1. 取证

平台是 **windowsgui** 程序：不加 `CREATE_NO_WINDOW` 的控制台子进程，**每次调用**都会在桌面上闪一个黑窗。
这条规矩本来就写在 `internal/sysexec/sysexec.go` 的文件头：

> 「ManJuX 是 windowsgui 程序:启动 python(ComfyUI)、ffmpeg/ffprobe、explorer 等控制台子进程时,
> 若不加 CREATE_NO_WINDOW,每次调用都会闪一个黑色终端窗……全部 exec 调用一律经 Hide() 包装,根治闪窗。」

**但散文规矩管不住代码**（和管不住模型一个道理）：全仓 29 处 `exec.Command`/`exec.CommandContext`，
27 处都包了 `sysexec.Hide`，**恰好漏掉的两处都落在质检链上**：

| 位置 | 是什么 | 一集跑几次 |
| --- | --- | --- |
| `internal/qc/face.go:125` | insightface 人脸一致性测量（python） | **每个角色一次** —— `stages_qc_assemble.go:999` 的 `for _, cid := range order` |
| `internal/asr/asr.go:145` | faster-whisper 语音对账（`asr.cmd`） | **每一镜一次** —— `stages_qc_assemble.go:242` 逐镜 `qc.CheckSpeech`；有界重出链 `voice_check.go:186` 再各一次 |

一集 13 镜 + 若干角色 ⇒ **十几次到几十次闪烁**，正是用户说的"一直不停重复"。
渲染/合成阶段之所以不闪：`ff`（ffmpeg/ffprobe）、`qc/vlm.go`（抽帧）、`sysmon`（nvidia-smi）、
`compose`、`comfyengine`、`browser` 那 27 处**都已经包了** `sysexec.Hide`。

> 说明（不夸大）：我**不能**从这里"看到"那个窗口。证据是代码本身 ——
> ① 用户报障；② 仓库自己写着"不加就闪"；③ 质检链上恰好存在两处未包装的子进程调用。
> 修完请**重启 app** 再跑一次质检确认（这一改动对已渲染的项目同样生效，无需重渲）。

## 2. 修法

两处都改为经 `sysexec.Hide(...)`（与其余 27 处同一写法）：

```go
cmd := sysexec.Hide(exec.CommandContext(cctx, cfg.Python, args...))   // qc/face.go
cmd := sysexec.Hide(exec.CommandContext(ctx, tool, media, "--model", model, "--out", out)) // asr/asr.go
```

**为什么加 `CREATE_NO_WINDOW` 不会把这两条链的输出搞坏**（这是必须核的，不是想当然）：

- `qc/face.go` 结果从 **stdout** 读（最后一行 JSON），而它已经设了 `PYTHONIOENCODING=utf-8`
  —— 正是为了对付"无控制台时 Python 管道 IO 默认按系统 locale(GBK)"这件事；
- `asr/asr.go` 结果**一律从文件读**（`Parse(out)`），stdout 只收报错，工具说明里也写了"控制台中文会乱码"。

### 2.1 真机 A/B（不是"想当然安全"）

用**真正的** `D:\Ai\Tools\ASR\asr.cmd`（`asr.Locate()` 找到的那个）对同一段 4 秒音频跑两遍 ——
一遍不加窗口属性、一遍加 `sysexec.Hide`：

| | 退出码 | 结果文件 | sha256 前 12 |
| --- | --- | --- | --- |
| 不隐藏 | 0 | 69 字节，`# probe_asr.wav / # model=medium lang=zh prob=1.00 dur=4.0s segs=0` | `dcb10d6f5198` |
| **隐藏** | 0 | **完全相同的 69 字节** | **`dcb10d6f5198`** |

⇒ 隐藏窗口不改变真机 ASR 的行为（参数、退出码、UTF-8 结果文件一字不差）。
根因层面也对上了：`asr.cmd` 自己设了 `PYTHONUTF8=1` + `PYTHONIOENCODING=utf-8`，
`transcribe.py:82` 是 `open(out, "w", encoding="utf-8")` —— 编码不靠控制台。

### 2.2 顺带修掉一处**夹具依赖控制台**（同一个坑咬出来的）

`internal/asr/transcribe_test.go` 的假工具原来是 `echo # shot_003.mp4> %5`：
行尾那个字符正好是**数字**（`mp4` 的 `4`、`4>>` 的 `4`），cmd 把 `4>` 当成**句柄 4 重定向** ——
于是**同一份夹具**在有控制台时写进文件、在无控制台（`CREATE_NO_WINDOW`，平台走的就是这条）时落空，
测试当场变红。这不是产品坏了，是**夹具自己随环境变**。

改成括号重定向块 `> "%~5" ( … )`、只用 ASCII（cmd.exe 按 OEM 代码页读 `.cmd`），
并且**真的把 `%3`（`--model` 的取值）写进结果** —— 原来写死 `medium`，
`r.Model == "medium"` 那条断言其实**没验过参数是否传到了子进程**（等于摆设）。

> 教训（与"夹具必须照真实形态写"同源）：夹具**不许依赖运行环境**（控制台、locale、cwd）。
> 它一变，测的就不是产品，而是"今天这台机器长什么样"。

## 3. 判据（防它再漏）

新增 `internal/sysexec/hide_coverage_test.go`：

| 判据 | 内容 |
| --- | --- |
| `TestEveryExecIsHidden` | 扫全仓**生产代码**（不含 `_test.go`、不含 sysexec 自己）：每一行 `exec.Command(`/`exec.CommandContext(` 必须同处出现 `sysexec.Hide(`，**漏一处就红并点名 `file:line`** |
| `TestHideSetsBothNoWindowFlags` | `Hide` 必须**两个开关都设**：`HideWindow` + `CreationFlags&CREATE_NO_WINDOW`（只设前者在部分场景仍会先建窗再隐藏，看得到那一闪） |
| 反摆设 | `sites < 15` 直接 fail —— 过滤条件写坏时"一处都没扫到"的那种绿是假的 |

**反向验证 3/3 全红**（`scratch/reverse_verify_no_window.ps1`）：
① 把 `qc/face.go` 的包装摘掉（事故现场）⇒ 红；② 去掉 `CREATE_NO_WINDOW` ⇒ 红；③ 把扫描的文件过滤改坏 ⇒ 红。

## 4. 边界（写清）

1. **只判生产代码**：`_test.go` 里的子进程不判（测试本来就跑在控制台里，闪不闪无所谓）。
   —— 注意这意味着**测试代码**若将来大量起进程，不在本门覆盖内。
2. **判据是"同一行"**：`exec.Command` 与 `sysexec.Hide(` 必须写在同一行（这是刻意的 ——
   多行写法会让"是否包住"变得需要解析，而本门刻意用最笨、最不会骗人的判据）。
3. **`sysexec` 自己的包不参与扫描**（它是唯一入口）。
4. `Hide` 只解决"窗口"这一件事，不改变子进程的编码/权限/生命周期；
   `explorer.exe`、`taskkill`、`rundll32`、`git`、`nvidia-smi` 这些也都在这条链上（原本已包）。
