# 全面审计 · 产线主链路与「名称 vs 数据 ID」（2026-09-28）

用户两次点题：「叫你全面审计，然后交付的逻辑搞的跟个啥一样」＋
「资产以元数据保存下来，然后直接以数据ID关联，程序里都以数据ID调用，很简单的逻辑啊，
这样就不会有什么名称问题！」

所以这轮不是修补，是**成体系地扫**：两个 agent 并行扫全库（静默失败/假成功、名称关联残留），
我自己查「判据有没有落到盘上事实」这条主线。共 30 条发现，以下是结论与状态。

---

## 一、已修（本轮，均有守卫测试）

### 1. 交付判据里没有「成片在不在」
`coordinator.go` 的 `execute` 末尾只看各阶段有没有返回 error，全绿就报「✔ 全流程完成」——
**盘上有没有成片从来没查过**；批量产线信这个结论推进下一集，用户最后看到的是一串"完成"、
`output/` 里却没有片子。而这判据此前散落在四处各写各的 `os.Stat`。
→ 收成唯一真源 `project.DeliveredFinal`（存在、非目录、**大小 > 0**），管线收尾必须查它。

### 2. 阶段枚举被降级成单阶段 → 一个镜头都没渲
`runNovelBatch` 里「有方案就用 `PhaseAssets`」，而那是**单阶段**语义
（`pipelineStages` 对显式阶段只返回它自己，这条 `pipeline_stages_test.go` 早就钉着）
⇒ 任何"已有方案"的集只出完资产就被当成跑完，产线立刻推进下一集。
→ 一律起 `PhaseAll`，跳不跳 script 交给 `pipelineStages` 自己判。

### 3. 「提前解析下一集」→ 删掉
两版都被否（先"起 N 之前顺手解析 N+1"，后"加门 + 挪到本集进资产/渲染之后"）。
用户定调：「我有没有说合理分配任务，有叫你主线任务流程中断不做吗？」
→ 现在第 01 集"解析→资产→渲染→质检→成片"跑完才轮到第 02 集；为它加的死代码一并删除。

### 4. 资产库：名字 → **数据 ID 为真源**
库条目此前按名字建目录、按名字命中、同名覆盖：名字里多一个括号注解、换个称呼、繁简标点
都会 miss 或串到别人身上；两个项目各有一个「林昭」时后入库的会把前者的脸**永久覆盖**。
→ `Entry.ID`（卡片 ID）为关联真源；`PutCard`/`FindForCard`/`MatchCard`/`matchByID`；
自动化链路（复用、入库、写回、多视角）全走 ID；界面与上传路径保持按名字（不迁移老库）。

### 5. 审计实测：`Put` 会把条目的 ID 抹掉
`put()` 每次都重建条目、只保留 UsedCount/Fingerprint，而 `Put` 传的 cardID 是空串 ⇒
库详情的「重抽」、渲染前补齐写回、上传替换主图这些**日常操作**都会把 ID 清空，
`FindForCard` 的 ID 分支从此永久空转。
→ 规则改成：显式给了 ID 以它为准；没给就**沿用条目原有的 ID**。

### 6. 审计实测：同名不同 ID 时目录错位 → 操作落到**别人**身上
`PutCard` 在同名不同 ID 时故意另起 `名字__ID` 目录，而所有"按名字重推目录"的入口
（重抽、删除、清角度图、别名回写、详情取图）都会落到第一条上：
给 B 换脸写进 A 的目录、点删 B 删掉 A、别名回写把对方的 asset.json 整份换掉。
→ `Entry.Dir` 记下条目自己的目录；`locateByNameLocked` 统一按"名字 → 条目 → 它自己的目录"
定位；删除/清图/写元数据/别名回写全部改用它。

### 7. 回收守卫下标差一 → 会把**正在跑**的批次判成死批次
`reapStaleBatch` 原来按 `cur` 直接索引 projects，而 cur 是 **1 基** ⇒ 取到的是**下一集**。
产线跑第 1 集时用户再点一次「批量产线」或导入另一本书，守卫读到"下一集没在跑"就把活跃批次
回收掉（还播报"旧批次已让位"这种假消息），随后两个批次一起调 Start ⇒ 两集并发抢一张卡
（2026-09-12「定妆照整批失败、单镜 20+ 分钟」的形态）。
→ 改成"**这一批还有任何一集在跑就不许抢**"，不依赖 cur 的基。

### 8. 判据落到盘上事实：参考图与资产就绪
资产阶段报的「N/N 就绪」是**过程计数**（生成函数返回 nil 就算数），文件有没有落盘、
是不是 0 字节从没验过；`refs.go` 取参考图也只看字段非空 —— 一条指向不存在文件的资产条目
就够让那一镜**静默降级纯文生**（同一角色逐镜换人），界面上却只有"资产就绪 N/N"。
→ 唯一入口 `project.FileOnDisk`（存在、非目录、大小 > 0）：资产阶段保存前剔除鬼条目并如实
播报、取参考图前校验、成片交付判据共用。

### 9. 角色名别名（`碑生（丙十七）` vs 提示词里的 `丙十七`）
`subject_definitions` 一行都没绑到参考图 ⇒ 模型按文字重画 ⇒ 逐镜换人。
→ `authorityPictures` 按「整名 / 括号前主名 / 括号内注解」展开别名。**第一版按字节切括号**
切出乱码别名，被照真实数据写的测试当场抓住，已改 rune。

### 10. 撞脸自检把自己当别人（资产 id 又被拼了一次前缀）
→ `check()` 里显式分开 `assetID` / `cardID`；`castPeers` 的 selfID 统一归一化；
比对点上再加一道兜底：路径相同的图直接跳过。

## 三、模式归口

这 30 条归到四个病根，**根治点各不相同**：

1. **结论由过程变量折出，不由产物验出**（A4/A5/A9/A12/A13、已修的 1/8）
   → 让 `store` 层的写盘调用点**返回值不许用 `_` 接**（一条静态门堵一片）；
   阶段结论一律回盘上核对。
2. **错误被吞**（A3/A6/A7/A8/A10/A15）
   → 同一道门：`Save*/Put/Load*` 的返回值必须被消费或显式播出。
3. **内部关联靠名字**（B4/B5/B6/B8/B9/B10/B11/B12）
   → 一律改按卡片 ID；名字只在"面向 LLM 的自然语言"和"没有 ID 的上传资产"两处保留。
4. **降级不播报**（A2/A14、已修的 8）
   → 降级必须出现在阶段结论里，不能只留一行日志。
