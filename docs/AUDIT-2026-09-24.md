# ManJuX 全项目审计报告（2026-09-24）

> 起因：用户报「总是让你修修补补，补完这又补那」。这份报告的目标不是列出所有小毛病，
> 而是回答**为什么这事反复发生**，并给出让它不再发生的升级方案。
>
> 审计方式：9 个区域并行审计（Go 20 个包约 2.4 万行 + 前端 26 个文件 375KB + 4 篇文档）
> → 高严重度结论做对抗复核（专派"驳倒它"的复核员）→ 逐条人工读码确认后才列入
> P0/P1。**每条都带 file:line 与"我在代码里看到的证据"**；没有证据的推断不进本报告。

## 一、结论：四个根因（"修补"之所以没完没了）

这一整轮报障（数据卡片没主题色 → 表单没主题色 → 多视角老失败 → 局部重绘点了没反应）
表面上互不相干，根子上是同一批毛病：

| # | 根因 | 典型形态 | 本轮实例 |
|---|---|---|---|
| **R1** | **同一职责多处分叉** | 一个语义有 2-4 个实现点/调用点，改一处漏一处 | 定妆照装配 **4 处**、种子派生 **4 种**、实体类型判定 **2 份**（前端表已与 Go 漂移）、引擎能力 **5 处字符串判断**、阶段清单 2 份、权重存在判据 3 套 |
| **R2** | **"看起来有"但没接线** | 有 UI/设置/字段/开关，但没有消费者或必然失败 | 局部重绘必然抛 ValueError（已修）、`fade_sec` / `shot_limit` / `peak` / `auto_open_ui` 四个设置项零读取点、Sage 面板有函数无界面 |
| **R3** | **静默降级 / 错误被吞** | 失败了仍当成功，或关键返回值被丢弃 | QC 抽帧失败被 `continue` 吞掉后仍返回结论、云端鉴权失败当网络抖动重试、单镜重渲指纹不含时长导致"改了却没重渲"、渲染每镜无条件 `/free` 忽略返回值 |
| **R4** | **闸门只测函数、不测调用点** | 测试断言"那个函数是对的"，但没有任何东西保证**所有路径都走它** | 介质锁/身份锁收口在 `ShotRenderPrompt`，而"成片 2K"整条路径绕过它；`TestShotRenderPromptIsSingleSourceForAllRenderPaths` 只测函数本身 |

**升级的总方向**（后文每项都归到这四条）：
**一个语义一个收口点，每个收口点配"调用点闸门"** —— 闸门扫的是"所有会出像素/会写盘/会花钱的路径"，
而不是"那个函数"。这一步做完，同类问题才会从"用户报障"变成"自检变红"。

## 二、P0：功能不可用 / 破坏性 / 静默错误（先修这些）

### P0-1 ✅ 局部重绘是死功能（critical）——**本报告提交前已修**

- 证据：`maskgraph.go` 的 `SAM3_VideoTrack` 既没传 `initial_mask` 也没传 `conditioning`；
  而 ComfyUI `comfy_extras/nodes_sam3.py` 里写着
  `if conditioning ... elif initial_mask is None: raise ValueError("Either initial_mask or conditioning must be provided")`
  —— **必然失败**。UI（`ShotCard.vue:17`）、API（`handlers_enhance.go:117`）一应俱全。
- 修法：`CheckpointLoaderSimple` 的 CLIP 槽（槽 1，即 SAM3 自带文本编码器）→ `CLIPTextEncode(target)`
  → `conditioning`；目标短语改为**必填**（引擎、API、前端三层各拦一次）；新增 `MaskAssets()`
  事前体检（节点 + SAM3 权重），缺件返回 409 并写明放哪个目录。
- 钉住：`TestMaskGraphWiresSAM3Conditioning`（conditioning 接线 + CLIP 取自 SAM3 槽 1 + ckpt 名）、
  `TestMaskOptionsRequireTarget`（缺目标必须报错）。

### P0-2 批量产线运行中仍能删掉整部系列（high，**破坏性**）

- `frontend/src/views/HomeView.vue:326`：守卫写成 `batchStat && batchStat.prefix === prefix`，
  而 `batchStat` 是 `ref`（:203），`.prefix` 恒为 `undefined` → **守卫永不触发**。
  结果是：批量产线正逐集渲染时，用户点「删除整部系列」照删，把正在跑的集一起删掉。
- 修法：`batchStat.value?.prefix === prefix`（脚本内 ref 必须解引用；模板会自动解包，别照抄模板写法）。
- 验收：单测——`batchStat.value={prefix:'X'}` 时调 `removeSeries('X', eps)`，断言未调用 `api.deleteProject`。

### P0-3 QC 的抽帧时间点是错的，且失败被吞（high）

- `internal/qc/qc.go:111-126`（`posOf:131`）：注释称抽 25%/50%/75%，实际固定 `1s/3s/5s`。
  长镜只看到前 5 秒；4 秒镜头第三帧越界，`ffmpeg` exit=0 但无输出文件，被 `continue` 静默吞掉，
  **函数照样返回 darkRatio 结论** —— 于是"质检通过"是假的。
- 修法：按 `-t` 取实际时长，用比例定位 `-ss`（或 `fps+select` 抽帧）；抽帧失败计入 `Problems`。
- 验收：4 秒全黑片跑 `qc.Check`，断言 `Problems` 含黑屏。

### P0-4 `build.ps1` 会把版本号改回旧版并弄脏仓库（critical）

- `scripts/build.ps1:36-73`：版本基线由 `git describe --tags` 反推。当前 HEAD=`v0.34.4-16-g…`、
  最新 tag=`v0.34.4`，而三处版本文件已是 `v0.37.2` → **单独跑一次 build.ps1 就把三处改回 v0.34.4**。
  （本轮我每次都显式传 `MANJUX_VERSION` 才躲过；脚本注释却称此坑已修。）
- 修法：版本基线**不从 git tag 反推**——改为读 `version.go` 现值，或仅在显式传入
  `MANJUX_VERSION` 时同步三处，否则跳过写回。
- 验收：跑 `build.ps1` 后 `git status` 三个文件不得变化；`check.ps1` 加同源断言。

### P0-5 显存护栏在最该生效时失效（high）

- `internal/pipeline/coordinator.go:459-476` + `comfyengine/admin.go:42-64`：
  `ReleaseVRAMIfIdle` 想表达"队列非空绝不释放"，但 `Admin()` **恒返回 err=nil**，
  且 `/queue` 查询失败时 Running/Pending 保持 0、没有"状态未知"标记
  → **"引擎忙到答不上探测"与"引擎空闲"在返回值上完全同构**。
- 影响：`/free` 会把正在跑的权重卸掉，之后每步重新流式加载（代码自述 150s/步、整镜 45 分钟超时）。
- 修法：`AdminStatus` 加 `QueueKnown bool`（只在 Queue 成功时 true）；判据改为
  `st == nil || !st.QueueKnown || st.Running+st.Pending > 0 { return }`——探测不到就不释放。
- 验收：httptest 假 ComfyUI：`/queue` 返 500 时断言不触发 `/free`；空队列且已知时才触发。

### P0-6 云端：鉴权失败被当网络抖动 + 超时不取消（high，**花钱**）

- `internal/engine/h3api/h3api.go:135`：轮询对任何非 200 一律 `continue`（"网络抖动容忍"），
  401/403 也照吞 → 无效 Key 白等 20 分钟才失败，报的还是"超时"；
  而管线拿这个哨兵判定"显存挤压"，于是**再跑一轮**、重新 create 一个云端任务（一次鉴权失败 = 2 个计费任务 + 约 40 分钟）。
- `h3api.go:132`：`ctx.Done()` 分支会 `cancel` 云端任务，**deadline 分支不 cancel** → 超时后远端继续跑并计费，
  与 `docs/架构.md:42` 宣称的"取消防空跑计费"相反。
- 修法：query 返回可判别错误（`*apiError{Status}`），401/403/400/404 立即失败且**不包装** `ErrRenderTimeout`；
  连续失败 3 次即失败；`Render` 加 `defer if !settled { cancel }`。
- 验收：假服务器断言——恒 401 时 ≤2 次查询返回且 `errors.Is(err, ErrRenderTimeout)==false`；
  超时返回后 DELETE 调用 ≥1；失败路径只 create 一次。

### P0-7 成片 2K 绕过画风/身份锁，且提示词主动要求"增强皮肤细节"（high）

- `internal/pipeline/upgrade2k.go:104`：`shotID==0`（**成片 2K**，UI 上点「升级 2K」走的就是这条）
  用的是裸字面量提示词 `enhance textures, skin detail and micro-structures`，
  `refs` 声明了却从未赋值 → 没有身份锚定、没有介质块。
- 影响：一整部哑光赛璐璐的片子送去云端按**写实皮肤先验**重画一遍，付费把全片改成油光写实。
- 修法：新增 `final2KPrompt(proj, plan)`，内部走 `styleAndMediumBlock` + 介质锁，
  把"enhance skin detail"换成"锐化线稿与赛璐璐边缘、保持哑光平涂"；禁止再出现裸写的质量词。
- 验收：表驱动 `TestEveryPixelProducingPathCarriesMediumMarker`——主渲染/单镜2K/**成片2K**/局部重绘/音频驱动
  五条路径的提示词都必须含 `MediumMarker` 且不含 `skin detail`/`photoreal`。

### P0-8 改了镜头时长却"重渲没生效"，界面还报成功（high）

- `internal/pipeline/stages_render.go:315`：渲染指纹串只有 `WxH sSteps seed seam accelTag q1`，
  **不含 `shot.Duration`**；而:223 真正提交的长度是 `shot.Duration*24`。
  于是用户把 4 秒改成 6 秒（为了装下被截断的台词）、点「保存并重渲本镜」→ 指纹不变 → 走跳过分支 → 旧片原样保留。
- 修法：**不动指纹串**（改它会让存量项目全量重渲）——在 `ClipManifest` 加 `Length int`，
  跳过条件追加 `m.Length == shot.Duration*24`。
- 验收：`TestDurationChangeInvalidatesRenderedShot`（改 duration 后必须再次 Render 且 Job.Length 正确）。

### P0-9 单镜重渲会连带补齐全片资产（high，**白烧 GPU**）

- `stages_render.go:72-116`：`only=[shotID]` 只过滤了镜头循环，紧接着的
  `backfillAssets` / `backfillAssetViews` 传的是**整份 plan**，且忽略本次引擎覆盖
  → 只改一镜 seed，却可能生成整片所有缺失定妆照（Krea-2）与所有角色的多视角（H3 数分钟/人）。
- 修法：把过滤后的镜头集贯穿到 backfill（按 assetID 反推所需资产），并透传 `engName`。
- 验收：假引擎计数——`only=[3]` 时 backfill 不得触及其它镜头所需之外的资产。

### P0-10 本地 HTTP 服务没有任何来源守卫（high，**安全**）

- `internal/server/server.go:93` 的 92 条路由无中间件；`readBody(:196)` 不看 Content-Type，
  于是"text/plain + JSON body"这种**不触发预检**的跨站请求就能打到副作用端点：
  `/api/quit`、`/api/comfy/stop`、`/api/cleanup`（`os.RemoveAll` 中间产物/条件缓存）、`/api/open-url`。
- 修法：装配层加**唯一一道**守卫 `guardAPI`（① Host ∈ 回环；② Origin/Referer 非回环则 403；
  ③ 写操作要求 `Content-Type: application/json`），`routes()` 与 `APIHandler()` 共用。
- 验收：契约测试里 `doReq` 显式设 `req.Host="127.0.0.1:8790"`（这正是守卫生效的反向证据）；
  再加"跨源 Origin 必须 403"用例。
