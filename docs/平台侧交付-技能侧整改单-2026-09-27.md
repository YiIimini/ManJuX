## 1. D1（必修）`h3_prompt` 里混着"写给生成器的话"

### 现象与证据

全书 **2462 镜、无一例外**（第 01 集 64/64；全 40 集逐包统计 = 2462/2462），
`plan.json → shots[].h3_prompt` 的开头长这样（**原文照抄**）：

```text
subject_definitions:
REFERENCE ORDER: for each character in the shot's characters array, in array order, FIRST that character's front sheet, and THEN (if it has one) ONE multi-view picture of the SAME subject — never a second character. After all character pictures comes exactly ONE scene picture, always LAST. Props never get a picture; describe props in text only.
Locate every subject by PICTURE CONTENT, never by counting indexes: a front sheet and its multi-view strip are the SAME subject. Never state how many pictures are attached and never assert which picture number the scene is — the renderer appends an authoritative PICTURE MANIFEST that fixes the numbering. Always name the subject in words too.
<Subject 1> is 沈砚·一品 (human) — …
<Subject 2> is 临水城 — the location itself, …
Every <Subject> must map to a picture that exists in the order above; never invent picture tags beyond that count. The attached sheets are the AUTHORITY on how each subject looks: …

retention_analysis:
- One line per reference picture, numbered exactly as in subject_definitions. Name the subject in words in every line so the render-time PICTURE MANIFEST can correct a numbering mismatch.
- Picture 1 — 沈砚·一品 (front sheet): fully_preserved - identity must stay identical …
```

**派生文件 `分镜/H3-提示词.md` 里没有这些行**（`REFERENCE ORDER` 0 次、`PICTURE MANIFEST` 0 次）——
所以问题只在 `plan.json` 的产出这一侧。

### 为什么它是问题（三条独立证据）

1. **官方一手仓里一句都没有**：对 `MiniMax-H3/skills/**`（`.md` + `.txt`）搜
   `REFERENCE ORDER` / `PICTURE MANIFEST` / `characters array` → **0 命中**。
2. **双方共享契约没定义它**：`ManJuX/docs/渲染脚本契约.md` 里的 `h3_prompt` 一节没有这些内容。
3. **平台是把 `shot.H3Prompt` 原样拼给模型的**（只在前面追加风格块 / 比例锚点 / 画外音条款），
   平台自己的 `PICTURE MANIFEST (authoritative…)` 是**渲染期另外追加**的。
   于是模型会同时收到"写给拼提示词的人的规则"和"权威清单" —— 前者纯噪声，且它点名了一个
   模型看不见的东西（*the shot's characters array*）。

**根因**：这几行是**写给"拼提示词的人"的规则**，应当留在作者规范/生成器里，而不该进 `h3_prompt` 正文。

### 改成什么

- `manju_plan.py` 生成 `h3_prompt` 时，**不要把规则行写进正文**；`subject_definitions` 只留
  `<Subject N> is …` 这样的**内容行**，`retention_analysis` 只留**条目行**（见 D5 的目标格式）。
- 这些规则请留在 `references/分镜脚本-多引擎输出规范.md` 或生成器的常量里 —— 它们本身有价值，只是放错了位置。

### 平台侧已做的兜底（兜底 ≠ 替代修复）

- **渲染时自动剔除**：平台在 `Store.LoadPlan`（计划进入平台的唯一入口）按**行首前缀**剔掉这些行，
  并在开跑时播报一次「混进了 N 行生成器指令，已剔除；要根治请让脚本侧重新导出」。
  只按行首前缀匹配、**宁可漏不可误删**（`The scene is the LAST attached picture.` 这种既像规则又像内容的句子不动）。
- **导入时就报警**：契约门会聚合报一条（不是 2462 条），提醒"这份包带着生成器指令"。
- 也就是说：**不改也不会坏渲染**，但每次导出都会再带一遍，平台的兜底日志会一直响。

## 2. D2（必修）派生 H3 提示词把**景别**写成中文

### 现象与证据

`分镜/H3-提示词.md` 的 **64 个提示词块，每块 1 处**，都在 `summary:` 那一行（原文照抄两句）：

```text
[reference generation] A single 5-second 特写 shot in 临水城, generated from 0 character reference sheet(s) plus 1 scene plate.
[reference generation] A single 9-second 中景 shot in 临水城, generated from 1 character reference sheet(s) plus 1 scene plate.
```

`<d>…</d>` 之外出现的汉字串按次数统计（第 01 集，64 块）：

| 汉字串 | 出现块数 | 性质 | 要不要改 |
|---|---|---|---|
| `临水城` / `城隍庙` / `青石观` | 122 / 4 / 2 | **场景名**（主体名） | **不改**（见下方口径） |
| `沈砚` / `周廷` / `苏晚` | 88 / 24 / 22 | **角色名**（主体名） | **不改** |
| `近景` / `中景` / `特写` / `远景` | 28 / 20 / 13 / 3 | **景别词** | **要改** ← 共 64 处 |

### 为什么只有景别要改（平台侧的口径，免得改过头）

平台的汉字门对**主体名是扣除的**：官方要求"用文字点名主体"（渲染期 PICTURE MANIFEST 靠它对编号），
名字里的汉字不可避免，所以 `临水城` / `沈砚` / `沈砚·一品` 这类**保持原样**。
但景别词没有这个理由 —— 官方提示词正文是英文，中文进 H3 会被画成**乱码字形**，
而画面正文一旦出现乱码就是硬伤。另外：**你们的素材三卡已经做到了零汉字**
（角色卡 48 块 / 场景卡 8 块 / 道具卡 15 块，含汉字的块 **0**），分镜这边照同一条纪律处理即可。

### 改成什么

- `storyboard_export.py` 在 `summary` 里把景别译成英文：`特写`→`close-up`、`近景`→`medium close-up`、
  `中景`→`medium shot`、`全景`→`full shot`、`远景`→`long shot`（与规范里的中英对照表保持一致即可）。
- 主体名（角色名 / 场景名）**保留中文**，不要动。
