# 六步产线对账：小说→剧本→资产→分镜→H3 提示词→成片（2026-10-07）

用户给的六步（原话）：

1. 小说内容转剧本时就需要同步提取角色、道具、场景；
2. 角色、道具、场景生成；
3. 剧本再转分镜脚本，**单个分镜脚本需要多个小分镜组成**；
4. 角色配音也同步提取；
5. 将它们整合输出为 **H3 视频渲染提示词**（引入角色、道具、场景、配音渲染分镜）；
6. 将所有分镜**合成**成品视频。

下面逐条对账：**代码落在哪**、**有没有机检**、**这一步现在会不会悄悄丢东西**。
本轮（2026-10-07）在第三步之后查出并修掉一条真缺口：**角色配音的"提取"只做了一半**（见 §4）。

> 本次对账的证据来源：源码 + 契约门 + 真机日志；**真机 `plan.json` 此刻不可用** ——
> 用户正在跑的批次把 `data/projects/名册之外，八万零一号/` 清空重建过（目录一度为空，
> 只剩启动日志），所以凡涉及"真机某个字段的值"的结论都标了出处或明确写"未取到真机值"。

## 4. 角色配音（"也同步提取"）——**本轮查出的真缺口，已修**

**查到什么**：`voice` 只有 ②人物道具会话的 schema 在要（`sessions.go:80`），而**走锚表补出来的角色卡
从来不写它** —— `internal/pipeline/cast_anchor.go:99-106` 的 `project.Character{...}` 只写
`Description` + `ImagePrompt`（真机那本书里苔生/拾叁/回波/关棠/剥线刀/毕申/白手套/议长 8 条都是这么来的）。
渲染侧 `internal/pipeline/voice_rebind.go` 的 `defaultVoiceFor` 对"认不出的说话人"一律返回**同一个常数**
`genericVoiceDefault` ⇒ 这些角色、以及无卡说话人（家丁甲/家丁乙/路人丙…）在成片里**是同一个嗓子**。
这就是"角色配音"这一步只做了一半：**提取来的声线有卡的人有，没写的人几个共用一个**。

**修法（两条，确定性，都在唯一入口）**：

1. `internal/project/voice_defaults.go`（新增）
   * `platformVoicePalette{Female,Male,Neutral}`：每池 12 条音色差异明显的英文声线短句；
   * `DerivedVoice(name, genderHint)`：按**基名**（`Q版` 前缀/括注/造型档后缀都归一）散列到池内 → 同名永远同声；
   * `PickVoice(name, genderHint, used)`：散列位置被占就顺延 ⇒ **同一份方案内每个角色一条不同声线**
     （作者指定过的声线也算"被占"，派生不会去撞它）；池子用尽才复用（同性别 >12 人时必然发生，照实写进注释）；
   * `FillMissingVoices(plan)`：**只填空的**、幂等；
   * 性别来自描述里的结构化行（`- 性别：女/男`）—— **读不到就是不明，不许按名字猜**
     （锚表里毕申那条写的是「性别：未定（正文刻意不给代词）」，那就走中性池）。
2. 挂进 `project.HealPlan`（唯一读取边界，`internal/project/prop_refs.go:438` 起）：预检/渲染/人审
   看到同一份声线；并加 `HealResult.Voices / VoiceNames`，由 `internal/director/director.go` 与
   `cmd/preflight/main.go` **如实播报**"补了谁的嗓子、为什么"。
3. 渲染侧 `defaultVoiceFor` 最后一档改成 `project.DerivedVoice(name, "")`（无卡说话人也不再共用一个常数）。

**判据**：

* `internal/project/voice_defaults_test.go`：夹具 = **真机锚表 14 条角色的名字 + 锚表原文的性别行**
  （含「未定」那条）。要求：14 张卡一张不落有声线、**两两不同**；幂等；跨 plan 稳定；作者给的声线不被改写
  且不被派生撞上；Q 版与本体同声；空名字不许编。
* `internal/pipeline/voice_rebind_test.go`：**HealPlan → voiceFor** 串起来测（未经自愈只能拿中性派生、
  自愈后拿到卡上那条并按性别分池、两个角色不许同声）。
* `internal/director/log_wording_test.go`：播报不许被删（`hr.Voices` + `project.VoiceSummary(hr.VoiceNames)`）。

**反向验证 4 处**（`reverse_verify_voice.ps1`，全红后逐条回滚）：
① HealPlan 不补声线 ⇒ 渲染侧那条链红 ② 所有人共用一条 ⇒ "两两不同"红 ③ 渲染侧退回常数默认 ⇒ 无卡说话人撞声红
④ 播报被删 ⇒ 接线门红。

**照实说的边界**：池子每性别 12 条，超过 12 个同性别角色的书会开始复用；**已经出过的成片不会自动变**
（要重渲那一集）；这里补的是"音色描述"（H3 直出音视频、没有 TTS），听起来像不像仍取决于模型。

## 5. 整合为 H3 渲染提示词（角色 / 道具 / 场景 / 配音 / 小镜头都要进去）

| 要素 | 落点 |
| --- | --- |
| 提示词四步装配（唯一入口） | `internal/pipeline/stages_render.go:1049` 的 `assembleShotPrompt`（缩短重出那一级也复用它） |
| 参考图按**固定顺序**装配：角色定妆照 → 多视图 → Q 版/机器人/面板 → 道具 → **场景图（永远最后一张）** | `internal/pipeline/refs.go:85-184` |
| 每张图的身份说明（"这是谁/这不是场景/别把多人格当多个角色"）写在 subject_definitions 里 | `internal/pipeline/refmanifest.go:86-155` |
| 道具的**文字锚**（跨镜一致靠 `PROP ANCHORS`） | `internal/pipeline/prop_anchor.go:27` |
| 场级光照锚（同场共用一套光态，来自场景卡 `light_state`） | `internal/pipeline/lighting_anchor.go:22-41`、`prompts.go:454` |
| 声线**逐句**重绑成权威文本（`<说话人> (Sx) says [off-screen] in <声线>: <d>`） | `internal/pipeline/voice_rebind.go:223`（`BindLineVoices`） |
| 空提示词/空台词是**致命项**（拦在渲染启动前，不许白烧显卡） | `coordinator.go:568-575`（`fatalPlanIssues`） |
| 小镜头要求写进提示词 | `EnsureShotSpecClause`（见 §3） |

**结论：五个要素都进提示词，且参考图有顺序契约、有身份说明、有门。**
