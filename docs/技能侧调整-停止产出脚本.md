# 技能侧（manju-novel）调整单 · 停止产出漫剧脚本，只出小说正文

> **决定（用户 2026-09-27 拍板）**：技能侧**独立输出小说内容，不再出脚本**；分镜脚本改由**平台侧 LLM 直出**。
> 原话：「感觉技能侧输出的脚本分镜对应的人物根本就是乱配一通，你两根本没有协同配合，我看还是技能侧独立输出小说内容，不出脚本了，还是平台侧走 LLM 合理点」。
>
> 本文是**动作清单**；逐字段的复核明细在 `docs/技能侧调整方案-脚本产物复核.md`（573 行，40 集 / 2462 镜全量实测）。

## 一、为什么停（实证，不是印象）

### 1.1 同一个「第 01 集」有**两份内容完全不同**的 plan.json

| | 技能侧脚本包 | 平台自产（LLM 直出） |
|---|---|---|
| 路径 | `data\小说\求你们骂我\漫剧脚本\…\plan\plan.json` | `data\projects\求你们骂我\…\plan\plan.json` |
| 镜头数 | 64 | 60 |
| shot 1 时长 | 5 秒 | 7 秒（产物实测 7.29s / 175 帧 = 7×24） |
| shot 1 景别 | 特写 | 中景 |
| shot 1 人物 | `characters=[]`（正文写 `No characters in frame`） | `characters=[char_shenyan]`（正文写"平躺在泔水里"） |
| 字段集 | 含 `action_en/emotion_en/sound_en/keyframe_prompt` | 只有 11 个字段（契约 `docs/渲染脚本契约.md`） |

**后果**：同一个集名、同一个文件名，两条线各产一份，**判读与排障都会串线**（本次复核就发生过：引文取自技能侧包、画面取自平台自产包）。

### 1.2 「人物乱配」的真相：不是 id 错，是**语义层的空镜矛盾**

- **机械比对查不出来**：我对着 41 个包 / 2462 镜做了全量校验 —— `characters` 与 `h3_prompt` 正文**零缺配、零多配**，角色 id 引用**零错误**，同镜人数分布也正常（1 人 2082 镜 / 2 人 321 镜 / 3 人 10 镜 / 空镜 49 镜）。
- **语义层是真错**：**空镜里写着有人**。`characters=[]`（→ 平台不给任何角色参考图）而动作描述是"一筐烂菜叶砸在他脸上"（→ 画面里必然有人）。**没有参考图的人 = 一镜一张脸**，这才是"人物乱配"的实质。
- **根因是一行死代码**：`manju_plan.py:1263` 读 `sh.get('action')`，而 `sh['action']` 到 **1293 行**才赋值 —— 契约里要求的"代词归主角"从未生效，**2462 镜全部如此**。
- 典型样本：第 01 集 #1（特写 / 5s / `humiliation` / `characters=[]` / 动作却打在人脸上）、第 26 集 #2（特写 / 陌生人首次登场却无参考图）。

### 1.3 其余阻塞级（复核报告 §3 详列）

| 编号 | 问题 | 规模 |
|---|---|---|
| B2 | 同镜互斥指令：`No characters in frame` + `Main action: 一个人…` + 末句 `no extra people` | — |
| B3 | **画幅写 16:9，实际渲染 768×1344（9:16）** | 场景卡 113/113、首帧 2462/2462、道具 600/600；角色卡 0/184 干脆没写 |

> **B3 这笔账，平台侧也有一半。** `docs/渲染脚本契约.md` 里**从来没有约定过画幅**（逐字查过：全篇没有"画幅 / 16:9 / 9:16 / 宽高 / width / height"任何一处），技能侧只能按自己的假设写，而平台的渲染默认是 768×1344 竖版。这是**契约缺失**，不是技能侧乱写 —— 后续若还走脚本线，第一件事就是把它写进契约。
>
> 顺带:画幅与取景是同一个坑的两面。技能侧的卡写"半身取景"而平台出图是竖幅,结果是**定妆照头顶被裁**(2026-09-27 用户报「角色头都顶上看不全」)—— 平台侧已改成**按画幅算构图**(竖幅给胸像 + 头顶留白),并且不再让 LLM 自己写取景短语。
| B4 | 真人台词 / 人群骂声被判成"系统音"，由平板合成音念出 | 10 条（含第 40 集 #3、第 01 集 #50 苏晚的台词） |
| B5 | 道具一致性机制被自己的汉字清洗整句吃掉 | 28 镜命中道具名、**0** 镜带道具规格 |
| B6 | 首帧 `keyframe_prompt` 不在平台契约里 → 产出全部空转 | 2462 条 |

### 1.4 观感级（12 条，摘要）

- `camera` 100% 由 `shot_size` 决定，只有 2 个取值、零机位/角度，最长连续 **21 镜同景别**；
- **48.7% 的动作是复合结果句**（而规范卡自己要求"只写动作路径、不写结果"）；
- `emotion_en` 842 种抽象标签，且提示词自相矛盾（写了"shown through body and face rather than named"却只给了名字）；
- 开场镜：39/40 集第 1 镜无台词无旁白、31/40 集无人物（自家口径是"别用三句天气开场"）；
- `sound_en=none/silence` 606 镜被当成声音写出（`A quiet ambient bed … : none.`）。

## 二、技能侧要做的事（停止清单）

1. **停掉脚本包产出** —— 不再生成
   `<书名>/漫剧脚本/<集>/manifest.json`、`plan/plan.json`，以及系列根 `series.json`。
2. **保留小说产出** —— `<书名>/` 下的章节正文照旧；平台的 LLM 直出**就是读它**。
3. **保留《立项.json》的「渲染风格串」与「画风」** —— 平台新的默认画风预设（国风电影级）与它**同源**，两条线默认一致；技能侧若继续维护立项，平台照它走。
4. **暂时停不掉的话，至少改名** —— 形如 `漫剧脚本（已废弃）/`，避免平台/人误读为有效输入。
5. **文档标注废弃** —— `references/渲染脚本契约.md`、`references/质检门清单.md`、`references/项目产出结构与命名契约.md` 里与脚本包相关的条款加"已废弃（2026-09-27）"。
6. **`manju_plan.py` 不必再修 B1–B6** —— 那是"不再使用的产物"里的 bug。若保留代码作历史参考，在文件头写清"已停用"。

## 四、过渡期怎么处理盘上已有的脚本包

- 平台**仍能读**已有包（小说库详情弹窗的「剧本脚本 / 角色 / 场景 / 道具」四个页签就是读它），只作**查看**用。
- 渲染输入**二选一，不要混**：要么平台 LLM 直出，要么明确走导入包；同一个集不要两份都在盘上。
- 已存在的平台项目（`data\projects\**`）里的 `plan.json` 是**平台自产**的那份，不受影响。
