## 3. 反向验证：13 处「改坏 → 守卫变红 → 改回」

脚本在 scratch（`reverse_verify_deep_2026-10-08.ps1` / `deep2` / `deep3`），做法是**精确替换一处源码 → 跑对应守卫 → 还原**。

|---|---|---|
| ① | 关掉频域八度纠正 | 变红 ✔（110:1+220:4 读出 220.9） |
| ② | **整段回退 `audio/pitch.go` 到 HEAD**（旧实现） | 变红 ✔：`220.9 / 260.8 / 220.9 / 220.9 Hz（差 101%）` 与 `400 Hz → 200.3 Hz` 全部复现 |
| ③ | 去掉重叠带"不判"分支 | 变红 ✔ |
| ④ | 节标记退回纯 `strings.Index` | 变红 ✔ |
| ⑤ | 空壳也算"有剧本" | 变红 ✔ |
| ⑥ | 回填不清"照抄的抬头" | 变红 ✔ |
| ⑦ | 指纹去掉内容哈希 | 变红 ✔ |
| ⑧ | 清理时当前文件为空就不再留归档 | 变红 ✔ |
| ⑨ | 净化说明不记进清单 | 变红 ✔ |
| ⑩ | 界面不渲染质检结论 | 变红 ✔ |
| ⑪ | 资产指纹键退回裸 id | 变红 ✔ |

| ⑬ | 去掉质检的 `ff == nil` 守卫 | 变红 ✔ |

**这一步抓出了两个"摆设守卫"（过程如实记账）**：

- ② 第一次用的针是"把搜索下界挪一个 lag"，结果**仍绿** —— 抛物线插值把偏差补回来了。
  改用**整段回退到旧实现**才红；同时把 400 Hz 的容差从 6% 收紧到 **2%**（实测误差 0.1%）。
- ④ 第一次的针改的是 `EpisodeBrief` 的**起始**查找，而夹具咬的是 `EpisodeSectionEnd` 的**结束**边界
  ⇒ 仍绿。针换到承重点上才红。

> 结论（写进纪律）：**反向验证的针必须落在承重点上**；"改坏了还是绿的"要当成一次发现，
> 而不是当成"这条不重要"。

1. **夹具的形态必须照生产写**（键形态/路径形态/真机原文都要照抄）：`asset_fp_test.go` 照裸 id 写，
   掩盖了"这道门从未咬到过"整整一年级的缺陷。
2. **反向验证的针要落在承重点上**：改坏了守卫还是绿的 ⇒ 要么针错、要么守卫是摆设，都要当场查清。
3. **判据自己读错 = 拿假证据做决定**：基频估计器读错一个八度，代价是"白烧 GPU 重出"与
   "把好镜判成坏镜"，所以判据本身必须有合成信号自检（没有真机素材的机器上也能验）。
4. **算出来却不显示 = 等于没做**：后端结论必须在界面上有落脚点，否则用户只能"用到才发现"。
