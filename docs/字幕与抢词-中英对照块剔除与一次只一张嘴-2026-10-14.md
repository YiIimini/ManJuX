# 字幕与抢词：中英对照块剔除 + 「一次只一张嘴」（2026-10-14）

> 起因：用户给了一篇公众号实测文（<https://mp.weixin.qq.com/s/WeYyrCDcbUpfEdHk7Fxu0g>，2026-10-11），
> 要求「解析后并深度排查完善优化」。本文是那一轮的排查记录与改动说明。
> 公众号原文本身**不入库**（版权），下面只摘与平台有关、可执行的那几条。

## 一、那篇文章说了什么（只摘能落到代码上的）

作者的现场是「同一套素材、同一条提示词，差的只是抽卡次数」，三条视频分别坏在**出字幕**与**抢词**。
他的结论（既有实测、也有自述的经验线，逐条标明是哪种）：

| # | 主张 | 性质 |
|---|---|---|
| 1 | 画面里冒出**不认识的字幕**，第一个要排查的永远是提示词；换成英文 / 官方结构化写法，概率明显下降 | 作者自测二十来条，**非官方口径** |
| 2 | 分辨率**别一味往下压**（他给的经验线是"别低于约 0.6 档"），压太低会诱发异常字幕 | 作者经验线，他自己也说 0.55/0.65 都合理 |
| 3 | 提示词**信息塞太满**（五六个人 + 一堆动作 + 多轮对白 + 环境光影 + 镜头运动）会把注意力摊薄，长出自造的东西 | 与平台既有口径一致 |
| 4 | **别让好几个人同时处在正在说话的状态里**（"硬规矩"）；一个画面里只留一张嘴，用正反打/反应镜/背影/侧身 | 作者称"硬规矩" |
| 5 | 复杂动作 + 多人 + 说话时错误率飙升，应先重规划对话结构（谁先说/谁出镜/谁只出声） | 同上 |
| 6 | 5 人以上可控性急剧下降，平均抽 3–5 条才出一条能用 | 作者自测 |
| 7 | 分辨率 + 时长一起把显存吃干净会 CUDA OOM；他 8GB 卡在第 30 步爆 2.86 GiB | 他的机型 |

## 二、排查方式（不是读代码猜，是**拿真机产物走真实装配量**）

三路只读排查（提示词组装 / 抢词 / 分辨率与显存）＋ 一个真机探针：
把仓里两份**真机产物夹具**（`internal/project/testdata/plan_real_voiceover.json` 11 镜、
`skill-produced-plan-ep01.json` 56 镜）喂进**真实装配函数**，逐镜量「`<d>` 外、主体名已扣除的
可避免汉字」。判据用它，是因为平台自己的口径就写在那里（`project.CJKOutsideDialogue`，
导入侧 >200 直接 fail）。

## 三、查出来三件事，改了两件半

### 发现 1（最重）：平台自己在每镜正文里灌了 **1502 个汉字**

实测（装配前 → 装配后，`<d>` 外可避免汉字）：

| 夹具 | 夹具原文 | 装配之后 | 其中"中英对照块"占 |
|---|---|---|---|
| `plan_real_voiceover.json`（11 镜，**真机**） | **0** | **1502 / 镜** | 492 |
| `skill-produced-plan-ep01.json`（56 镜，技能端真产物） | 6 | **395 / 镜** | 273 |

**夹具自己是干净的** —— 那些汉字全是平台在装配时追加的：`EnsureOnScreenTextRule` /
`EnsureSpokenLinesClause` / `EnsureSpeechPlacementClause` / 参考图清单 / 转场字幕 / 风格块，
每一条都带一份 `(中文对照:……)`。

而本仓的注释里写得很清楚：这些中文半**是写给维护者看的**，「图片模型会把它当成'要画的字'
整段照抄到画面上」（真机出过这一版，见 `pipeline/prompts.go`）；图像侧也早就统一清了
（`DropHanRunes`）——**只有视频侧一直没清**。

**改法**：新增 `project.StripCNMirror`（整块摘掉对照块；英文规则、`<d>` 台词、主体名一字不动），
接在**两个**装配入口的收口处：
`ShotRenderPrompt`（主渲染/单镜 2K/局部重绘/音频驱动四路共用）＋
`assembleShotPrompt`（主渲染那条路又追加了参考图清单/道具锚定/转场字幕/镜头表字段）。

实测效果（同一批夹具，走真实装配）：

| 夹具 | 装配后（改前） | 装配后（改后） |
|---|---|---|
| `plan_real_voiceover.json` | 1502 / 镜 | **1010 / 镜** |
| `skill-produced-plan-ep01.json` | 395 / 镜 | **122 / 镜** |

**边界（如实说）**：剩下那 1010 个字**不是对照块**，是**身份锚定段本身就用中文写**
（`【身份锚定(全片统一,优先级最高)】` + 逐类型条款 + `【外貌不变项…】`，见 `anchorPrompt`）。
它**没有英文孪生句**，所以不能当"对照块"摘掉 —— 那是改写身份锁的正文，
`stages_render.go` 里作者还专门写了「H3 是 VLM 输入，中文锚定段与六段式正文并存无碍」。
**本轮不动它**：没有 A/B 证据（本机没跑 GPU 渲染），而身份锁翻译错会让脸漂。
⇒ 登记为**待拍板**（判据：同一镜两版提示词 A/B 抽帧 + 出字幕命中率）。

### 发现 2（文章点名的"硬规矩"）：一镜里两位**画内**说话人，平台**一条约束都没有**

真机夹具实测：**11 镜里 5 镜**（45%）有 ≥2 位画内说话人（如「姜晚舟 + 小灯」各说一句）。
而平台此前是**半边**的：

- 画外那半边有确定性约束 —— `EnsureVoiceoverClause`：说话人不在画面里 ⇒「画内的人一律闭嘴」；
- **画面里两个人在说**这半边 → 正文里就是 `<Subject 1> (S1) says…` / `<Subject 2> (S2) says…` 两句，
  **没有一句交代谁在什么时候开口、另一个人此刻是什么状态**。模型只能自己排：排错就是抢词，
  排对也是每一版都不一样。

**改法（渲染侧 + 产出侧两侧同时）**：

1. **渲染侧**：新增 `pipeline.EnsureSingleSpeakerClause`，在 `ShotRenderPrompt` 里
   （逐刀人声清单**之后**）补一条英文硬约束 —— 任一时刻只有一位动嘴、另一位嘴闭着只做反应、
   不许替别人出声、不许第三个人动嘴；并点名是哪几位。
   判据是新的 `project.OnScreenSpeakers`（与画外那半边**共用同一个函数**
   `speakerFrameSplit` 算出来 —— "在不在画面里"只许有一处出处）。
2. **产出侧**：`sysShotRulesTpl__SHOT_PLAN_RULES.md` 新增一条
   `ONE SPEAKING MOUTH AT A TIME`（**标明是平台规则**，官方 §4.4 其实允许 `(S1,S2)` 同时说话），
   并写明做法（每句给一个内切镜头、另一位闭嘴、用反应镜/背影/侧身只留一张嘴）。
   原有的「At most 2 speakers per shot.」保留（那管**条数**，管不住"同一时刻"）。

### 发现 3：分辨率没有下限提示

`RenderParams.Width` 的注释本来就写着「32 整除，短边 ≤768」，云端 2K 链也要求"短边须为 768"，
但渲染侧只在 `Width < 32` 时兜底，32…767 那一段**一路放行且无提示**。

**改法**：`project.RenderResolutionNote` + `project.H3NativeShortSide = 768`，
在渲染阶段**只报不改**（与「亮度/黑场只报不改」同一条政策），合规时一个字都不出声。
文案里标明那条"0.6 档"是**别人的经验线、我们没复核过**。

## 四、与文章其余几条的对账（**有就说有，没有就说没有**）

| 文章主张 | 平台现状 | 处理 |
|---|---|---|
| ① 英文提示词更稳 | **已有**：正向提示词强制全英文 + `<d>` 外汉字卫生门（本轮的对照块剔除是这同一条口径的补漏） | 本轮补齐视频侧 |
| ② 分辨率别压太低 | **没有判据** | 本轮加"只报不改"的提示（未复核他的 0.6） |
| ③ 提示词塞太满 | **已有**：词数门 300–600、`PlanMaxImportantCharacters=3`、每刀 1.5–4 秒、每镜 ≤2 句台词 | 不动 |
| ④ 别让多人同时"正在说话" | **半有**（只有画外那半边） | 本轮补上（发现 2） |
| ⑤ 5 人以上不可控 | **更严**：平台上限是 **3**（warn），不是 5 | 不动 |
| ⑥ 抽卡 3–5 条出一条 | **没有**：镜头层无自动多候选；失败重试 3 次内换种子（`stages_render.go`），音色核对有界重出 2 轮 | **不做**（产品级改动 + 烧 GPU，需单独拍板） |
| ⑦ CUDA OOM | **部分有**：启动参数降峰（`--disable-smart-memory/--cache-none/--vram-headroom`）；**没有** OOM 判定（被当超时处理）、**没有** 降分辨率/分块 | **不做**（渲染主链的 tiled VAE 属工作流级改动，本机此刻没有 ComfyUI 在跑 ⇒ 无法验收，见既有口径"没验过的不接"） |

## 七、边界（**没做到的事，一条都不藏**）

1. **没有重渲**：本机此刻没有 ComfyUI 在跑、`data/projects` 下 11 个项目目录**全空**
   （只有目录壳），所以「改完之后画面里到底还出不出一行白字」**没有用成片验证过** ——
   本轮给的是**提示词不再往模型嘴里塞 1500 个汉字**这个可确定性验证的事实。
2. **身份锚定段仍是中文**（1010 字/镜）：见发现 1 的边界，**待拍板**。
3. 文章那条「0.6 档」**我们没复核**：只做了提示，没有拦截、没有改参数。
4. 抽卡（同镜多候选）与主链 tiled VAE **本轮不做**：前者是产品级改动 + 烧 GPU，
   后者属工作流级改动且本机无法验收。两条都留在上面的对账表里，**不是忘了**。
5. `OffScreenSpeakers` 对"打错名字的说话人"仍会把它算成画面外（改造前就有的口径，
   本轮改动没扩大它，已在测试注释里如实写下）。
