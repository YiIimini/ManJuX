# 「视频看的莫名其妙的，配音也不对」：白天场景被写成 NIGHT scene + 场景图本身偏暗（2026-10-08）

用户报的是《顺其自然（真实事迹短片）》第 01 集（13 镜）。

**一句话结论**：这条报障里能证明的部分是**一条链上的两个缺陷** ——
① 「这一场是不是夜戏」的判据把**灯 / 蜡烛 / 月份**当成了时间词，于是 **7 个场景里 5 个被判夜戏**，
提交给模型的提示词里 **13 镜有 10 镜**带着 `This is a NIGHT scene: …`（那些场景的原文写着「清晨七点四十」
「次日上午」「冬日午后」「今年十一月底」）；
② 白天场景的**参考图本身偏暗**（实测 67.8 / 70.7 / 74.1），而提示词里明写着光照取自参考图。
两条都指向同一个后果：白天戏被渲成夜景 ⇒ 4 镜几乎全黑（其中一镜实测 100% 暗）⇒ 用户看到的"莫名其妙"。

**已修**（`internal/project/light_tier.go` 新 + `lighting_anchor.go` + `scene_exposure.go` 新 + 装配点），
判据 2 个测试文件、反向验证 7 处全红。**已出的那份成片不会自动变**：要重出那几张偏暗的场景图 + 重渲涉及那些场景的镜。

## 2. 根因①：把「灯 / 月」当时间词 ⇒ 白天场景被注入 NIGHT scene

判据原本是两张**逐字复制的词表**（`internal/pipeline/lighting_anchor.go:56` 与
`internal/project/script_scenes.go:147`）：

```
夜 / night / 月 / moon / 烛 / candle / 灯 / lamp / lantern
```

其中 **「月」是月份、「灯 / 烛」是道具**，白天夜里都出现。拿它去判真机那 7 条光态原文：

| 场景 | 光态原文（关键部分） | 旧判据 |
|---|---|---|
| 老城邮局营业厅 | 清晨七点四十…柜台**暖橙吊灯**…相邻镜头不得跳到正午或**夜晚** | 夜（错，三重误判） |
| 慈善总会财务窗口 | 次日上午…**台灯**暖光为次光 | 夜（错） |
| 街口募捐点 | 1999年12**月**傍晚…**路灯**暖黄光为副光 | 夜（错） |
| 总会会长办公室 | 午后…暖金日光 | —（无夜词，一句不加） |
| 慈善总会档案室 | 今年十一月**底**…**台灯**暖光为次光 | 夜（错，月+灯） |
| 山区村小教室 | 冬日晴晨…暖金日光 | — |
| 城市地铁站入口 | 冬日午后…站内暖橙**灯**为次光 | 夜（错） |

**5/7 场景被判夜戏**。这不是"多一句话"的问题 —— 提示词里注入的是：

```
This is a NIGHT scene: a visible in-frame light source must be present (a lamp, a fire,
a shaft of moonlight with a readable direction) — a lightless near-black frame is not acceptable.
```

**直接证据（本机 ComfyUI `/history` 里实际提交的工作流，不是推测）**：那 13 条提交里
**10 条**的提示词带着上面这句 `This is a NIGHT scene`，对应场次恰好是
邮局（镜 1、2）、财务窗口（镜 3、4、5）、募捐点（镜 6、7）、档案室（镜 10、13）、地铁口（镜 12）；
另外 3 条（会长办公室镜 8、9 与教室镜 11）因为旧词表里既没有夜词也没有白天词，**一句都不加**。
⇒ 那四个"不合格"的镜里，镜 8 / 12 / 13 所在的场次，场景原文写的都是**白天**。

顺带一个反例很有说服力：**城市地铁站入口**的场景参考图是全 7 张里**最亮**的（157.1），
提示词还是把它写成了夜戏，镜 12 出来 dark_ratio **0.86** —— 说明这一条不是参考图的锅，是**提示词**的锅。

## 3. 根因②：白天场景的参考图本身偏暗

用平台自己的 `imageMeanLuma`（0–255 平均灰度）量真机那 7 张场景图：

| 场景 | 亮度 | 光态档位 |
|---|---|---|
| 老城邮局营业厅 | **67.8** | 白天 |
| 总会会长办公室 | **70.7** | 白天 |
| 慈善总会档案室 | **74.1** | 白天 |
| 街口募捐点 | 89.1 | 暗光（傍晚） |
| 山区村小教室 | 100.0 | 白天 |
| 慈善总会财务窗口 | 110.2 | 白天 |
| 城市地铁站入口 | 157.1 | 白天 |

（对照：角色定妆照是影棚白底，量出来 154–198 —— 所以这条自检只对**场景图**用。）

场景图是这一场**每一镜**的光照来源，提示词原文写着 `background layout, props and lighting come from it`；
一张 67.8 的白天场景图会让整场镜镜偏黑（镜 1 / 4 / 7 / 10 的"偏暗 warn"就是这一档）。
此前**只有成片侧**的 QC 看得见这件事 —— 那时 13 镜已经渲完、用户已经在看片了。

## 4. 修法（能确定性做到的一律在装配点补，且如实播报）

① **新增 `internal/project/light_tier.go`：时间档只有一处判据，且只认时间词。**

* 三档：`LightDay` / `LightDim`（傍晚/黄昏/暮光/黎明/dusk/twilight…）/ `LightNight`；
* `lightNightWords` 里**没有「灯 / 烛 / 月 / 路灯」**（它们是道具与月份）；
* **否定小句不参与判据**（`stripLightConstraints`）：真机邮局那条末尾是「相邻镜头不得跳到正午或夜晚」，
  那是**约束**不是描述，按字面匹配到「夜晚」会把整场（清晨）判成夜戏；
* 没有时间词 ⇒ `LightUnknown`，**不按夜戏处理**（宁可少加一句，也不要把白天的戏按夜景渲）。

② **判据收成一处**：`script_scenes.go` 的 `isNightLight` 改为委托 `project.IsNightLight`；
`briefHasNight` 去掉与它重复的 `strings.Contains(sc.Time, "夜")`（避免两条会不一致的路径）。

③ **`lighting_anchor.go` 按档给条款**：夜戏原文保留；暗光（傍晚）说"光源要在画面里看得见、别掉进没有细节的黑"；
**白天新增一句**（照这一轮现场加的）：

```
This is a DAYLIT scene: keep the frame properly exposed and readable — do not turn it into a
night look, do not copy an underexposed look from the reference picture, and avoid any frame
that is nearly black or overly dark.
```

④ **新增 `internal/pipeline/scene_exposure.go`：场景图曝光自检，接在资产阶段。**
场景图一出图就量平均亮度（`imageMeanLuma`，Rec.601 权重，与 ffmpeg 的 YAVG 口径接近），
阈值：白天 < **90** / 暗光 < **60** / 光态没写时间 < **55**；夜戏不报（本来就该暗）、光态空着不报
（交给"场景卡缺 light_state"那道门）。告警里带上**实测亮度 + 档位 + 后果 + 改法**：

```
⚠ 场景「老城邮局营业厅」这张场景图**整体偏暗**（平均亮度实测 67.8/255，阈值 90.0；光态是白天：清晨七点四十…）
—— 场景图是这一场**每一镜**的光照来源（提示词写着 lighting comes from it），它偏暗这场戏就会镜镜偏黑…
改法：对这一张点「重新生成」，或在场景卡里把光态与描述写得更亮（正对窗、白天、室内照明充足），再重出
```

**不自动重出**：重出要 GPU，亮不亮是创作判断 —— 平台只如实说，由用户点「重新生成」。

## 7. 这一轮**没验**的与需要拍板的

1. **配音"重复念 / 多念一句"**：`SPEECH PLACEMENT (MANDATORY)` 与 `SPOKEN LINES ONLY` 这两条条款
   在这 13 条提交里**都在位**（`/history` 13/13 命中），而镜 1、5 仍然重复（镜 5 还多一句「或是血」）。
   ⇒ 第 21 轮加的那条条款对"重复念"这件事**不够**（它的有效性本来就写着"待重渲复验"）。
   **可选项（需你拍板）**：QC 抓到 `repeat` / `extra` 时**自动重渲一次**（现在是 warn 级、只标记、不自动重渲）。
2. 镜 6/8/12/13 的语音核对被**跳过**（因为镜本身不合格）⇒ 那四镜"到底有没有念台词"**未验**，重渲后 QC 会补上。
3. **观察项（未改）**：镜 10 的画面里有一张日期卡片「今年十一月底」——它**是模型自己画进画面的**
   （h3_prompt 里原文 `card "今年十一月底" at bottom of frame`，按平台规范引号内的文字会照画），
   而平台自己也会在同一时刻烧场次字幕（`final.ass` 的 `Caption` 轨：0:01:22.56「慈善总会档案室」）。
   两者都在画面偏下的位置，视觉上可能挤在一起。**没有改**：日期卡对"真实事迹短片"是有用的叙事元素，
   "要不要禁止模型自己加卡片"是创作口径，得你定。
4. **观察项（未改，此前已定性过）**：VLM 在多镜点了"单据/账本上的文字是 AI 乱码伪文字"、
   以及"第二帧景别跳到物件特写、角色出画"（镜 1/4/5）。前者是 H3 对未引号化文字的固有毛病，
   后者是既有的"VLM 景别项"（`docs/审计遗留-2026-09-29.md` 里已列，不在本轮范围）。
