## 乙类：需要你拍板

### 乙1. 场景图完全没有风格注入（**画风不一致不可逆**）
- **证据**：`internal/pipeline/stages_assets.go:175`；场景图只用 LLM 原样提示词出图，**不走** `styleExpand`（角色定妆照走）。四条出图路径（资产阶段 / backfillAssets / `server/handlers_asset.go` / `server/frame_asset.go`）各写各的。
- **后果**：一部剧里角色与场景**两套画风**；而 `portrait_assembly_test.go` 的闸门明确限定 `styleExpand(` 只能有一处调用点，所以不是改一行的事。
- **选项**：**A** 新增"场景装配唯一实现点"并让四条路径全部改走它（同时把"必须带全局风格串"写进 director 的 scenes 契约，要改那道闸门测试）；**B** 维持现状，只给场景图补一段风格后缀（半吊子，但改动小）。
- **代价**：A 属架构级，改动面大、要重跑闸门；B 会有"两个风格装配点"的技术债。
- **我的建议：A**。画风不一致是**不可逆**的观感损失，而且你已经付过一次"参考图与成片不在同一个视觉世界"的代价。

### 乙2. 局部重绘"按裁剪尺寸采样"（兑现"省一个数量级"）
- **证据**：`maskgraph.go:172-173` H3 拿的是整幅画布 `width/height`；SAM3 遮罩只连到 crop/uncrop，**从未进入采样**。而注释与 `docs/架构.md:102` 都写着"省一个数量级"。
- **后果**：每次局部重绘的成本 ≈ 整镜重渲；"局部"只体现在后置贴回。
- **选项**：**A** 真改成按裁剪尺寸采样（动态尺寸接进 H3 + 按裁切 latent 采样 + 贴回链调整）；**B** 保持现状，但**改掉注释与文档口径**（不再声称省成本）。
- **代价**：A 风险中高（采样画布/latent/贴回三处联动），但收益是局部重绘快一个数量级；B 零风险、零收益。
- **我的建议**：**先 B 后 A** —— 立刻把口径改对（不让文档继续骗人），A 单独立项（它同时能缓解"重绘成本高于直接重渲"这个体验问题）。

### 乙3. 色彩元数据（bt709）缺失
- **证据**：全链路没有一处写/校验色彩元数据；`compose` 规范化用 ffmpeg 默认。
- **后果**：若源片矩阵不是 bt709，成片可能整体偏色；现在**没人知道是哪种**。
- **选项**：**A** 先实测一次 H3 输出的矩阵/范围，再据此统一写标（需要渲一镜采样）；**B** 现在就直接写死 bt709。
- **代价**：B 在源片是 601 或未标记时会把本来正确的片子改坏。
- **我的建议：A**（拿一镜实测，别猜）。

### 乙4. 字幕对齐"真实人声落点"
- **证据**：`compose.go` 的字幕窗按镜头时长平均铺开（本次已把 SRT/ASS 两套窗口统一成一处）；
  真正按 `internal/audio` 的包络逐条对齐需要把包络从拼接函数传到字幕构造。
- **后果**：对白与字幕的贴合度只到"镜头级"，不到"句级"。
- **选项**：**A** 做到句级对齐（改动面中，要定义"对不上话时如何回退""字幕窗过短会不会闪"）；**B** 维持镜头级。
- **我的建议：A**，但排在甲类之后（先保证画面，再抠字幕节奏）。

### 乙5. 一次性 GPU 操作纳入管线互斥
- **证据**：局部重绘 / 音频驱动 / 单资产重生成 不参与管线互斥（`coordinator.go` 的 `HasRunning` 只覆盖管线本身）。
- **后果**：管线跑着时用户点局部重绘 → 两条链抢 GPU，**都变慢**，还可能触发显存问题。
- **选项**：**A** 纳入互斥（管线忙时禁用这些入口，或排队）；**B** 保持现在"能点就能跑"的宽松。
- **代价**：A 会牺牲"随时能修一镜"的灵活性。
- **我的建议**：**A 的温和版** —— 不禁止，但检测到管线在跑时**弹一条明确提示**（"管线正在渲染，同时跑会互相拖慢，确定继续？"），把知情权给用户。

### 乙6. 云端 4 秒镜被抬成 5 秒（当前只告警）
- **证据**：`h3api.go:365-369` `clampDuration` 把 <5 秒抬到 5；本次修复只做到**如实告警**。
- **选项**：**A** 保持告警（现状）；**B** 4 秒镜在云端直接拒绝提交，让用户改计划；**C** 本地渲 4 秒、云端渲 5 秒并**在清单里记实际值**（两条路产物长度不同但都如实）。
- **代价**：B 会挡住"只想用云端"的路；C 需要清单支持"实际帧数"字段。
- **我的建议：C**（最诚实：既不出错也不撒谎）。

### 乙7. 单镜云端 2K 产物归属
- **证据**：`upgrade2k.go:82-83` 产物落在 `clips/2k/`，**无人消费**（合成只收 `manifest.File`），界面也没有入口；本次修复加了产物校验 + 明确文案。
- **选项**：**A** 只导出（补一个下载/预览入口，成片仍是 768p）；**B** 让 2K 进成片（合成优先取 2K 版）。
- **代价**：B 会改变合成取片语义（混分辨率拼接需要考虑）。
- **我的建议：A**（先让付费产物可见可用），B 等你看过 2K 观感再定。

### 乙8. 云端超时/失败是否自动花钱重提
- **证据**：云端失败重试策略（报告 M-级）；重提 = 再花一次额度。
- **选项**：**A** 不自动重提（失败即停、如实报错）；**B** 自动重提一次。
- **我的建议：A**（钱的事不让机器替你决定）。

### 乙9. 云端引擎不支持 seed
- **证据**：请求体无 seed 字段（官方 API 参考 + 社区实测），本次修复已**如实告警**。
- **选项**：**A** 保持告警；**B** 在界面上把"云端 + 固定 seed"标成不可复现组合（禁用该组合或加红字）。
- **我的建议：B**（让它在选择引擎时就能看见，而不是提交后才知道）。
