# 定妆照肩上那三个 Q 型小人 + 分镜参考哪张 + 三视图改叫角色板（2026-10-10）

用户三句话：

> 咋每个角色的定妆照肩膀上都有三个Q型人物？另外三视图更换为角色板显示更详细，咨询一下分镜角色是参考三视图还是参考的定妆照啊？

## 一、每个角色肩上三个 Q 型小人 —— 真画面级缺陷，根因是「往图像提示词里塞别人」

### 取证（盘上那份真机卡，装配后的 `char:char_shenyan`，6827 字）

提示词里有一处**别人的外形描述**清单，两处都在：

```
CAST DISTINCTNESS (reference note, NOT to be drawn) — other cast members of this series:
  (A palm-sized miniature of a lean young man at two and a half heads tall, big head on a small
   short-legged body, long narrow face with a clear jawline, deep-blac…);
  (A palm-sized flat matte-black shadow creature lying low on the ground, no eyes, no mouth, …);
  (A tall slim young man of twenty-one, angular melon-seed face with a narrow fleshless chin …); …
FACE ID … NOT: A palm-sized miniature of a lean young man … NOT: A palm-sized flat matte-black
  shadow creature … NOT: A tall slim young man of twenty-one …
```

**其中两条就是"巴掌大的小人"**（Q 版形象 + 灵宠）⇒ 出图就多出几个小尺寸人物蹲在肩上。
这跟 2026-09-12 咬过的同型事故一模一样（当时是「郑伯的定妆照里出现了小尺寸的卫东与 Q 版江砚」），
那次的修法是**加一句否定**（`Do NOT depict any of these other characters`）——
而平台的图像侧规则写得很清楚：**CFG=1.0 的蒸馏档，否定词不生效、名词会被当指令画出来**
（`artstyle.go` 顶部 / `entity_prompts.go` 文件头）。所以"列出来 + 说不许画"在图像侧**注定只是半个办法**，
名单里的小人一定会被画。

### 修法：图像提示词里**不出现任何"别人"**

- `PortraitPrompt`（唯一装配点）不再拼 `castContrastBlock(...)`；`PortraitFaceIDClause` 的签名删掉
  `others []string`（那段 `NOT: <别人的外形>`），只留**主体自己**的身份锁逐字重述 +
  「这一帧是某一个具体的人、不许退回通用帅哥脸」。
- 两个只服务于那条路的函数（`castContrastBlock` / `castFaceIDs`）**整块删除**，
  连带上一轮为它写的"摘要收句"辅助（`distinctnessNote` / `distinctnessEntryRunes`）——
  **上一轮改的是"怎么列"，这一轮证明"不该列"**。
- `CastSeparationClause`（撞脸后重出用的分离指令）**也不再写对方的名字**：
  图像侧给一个可画的专名，轻则被画成画面上的字（本仓早有"画面文字命中"的实测），
  重则被当成"该出现的另一个角色"。功能不变（点明改哪几个维度），隐患去掉。
- 防撞脸改成两件**确定性**的事（都不依赖图像模型的否定词能力）：
  ① 主体自己的身份锁逐字重述；② **出图后看图判身份**（`cast_distinct.go`：与同剧已生成角色逐张比，
  判撞脸就带分离指令换种子重出一次）。

**门** `internal/pipeline/one_person_only_test.go::TestPortraitPromptNeverListsOtherCast`（夹具＝真机那批卡：
主体 + Q 版小人 + 灵宠 + 另一个年轻人）：装配后的图像提示词里
① 不许有 `CAST DISTINCTNESS`；② 不许有 `NOT: ` 清单；③ 不许出现任何别人的外形特征串
（`palm-sized miniature` / `shadow creature` / `angular melon-seed face` / `no eyes, no mouth` /
`two and a half heads tall`）；④ **必须**还留着自己的身份锁与「ONE specific person」。

**期望反转的旧门**（它们编码的是被推翻的那个决策，逐条改并写清理由）：
`castcontrast_test.go` 删除；`cast_distinct_test.go` 的两条改为"只讲自己 / 分离指令不许带名字"；
`entity_test.go` 的 `TestCastContrastIsKindAware` → `TestPortraitPromptIsKindAware`（器物仍不多拿人像介质，
人物仍带忠实度块，且提示词里没有别人）；`portrait_slim_test.go` 删掉那两条对比块的门；
`artstyle_test.go` 不再要求 `CAST DISTINCTNESS`；`portrait_assembly_test.go` 的调用清单去掉
`castContrastBlock(`。

**反向验证 2/2 全红**（`scratch/reverse_verify_oneperson_tree.ps1` 的 N1：把别人的外形塞回去 ⇒ 门红）。
**如实说**：那条门还有一半是"源码扫描"（装配点不许再出现那两个函数名）——
要反向验证得先把删掉的函数复活，收益不抵成本，**标注为未反向验证的冗余保险**。

**存量**：已入库的卡里的那段文字**不会自己消失**；对某张卡点「重新生成」即按新口径重拼。
（这也是用户现在看到那张图的来源：它是**旧提示词**出的图。）

## 二、分镜到底参考哪张？（给证据，不是印象）

`internal/pipeline/refs.go` 的参考图集合（`RefPlan`）：

| 参考 | 什么时候附 | 位置 |
|---|---|---|
| **定妆照**（`<base>.png`） | 角色出场就有 —— 它是**身份的唯一权威** | `refs.go:228/231`（`character_front`） |
| **角度参考** | 景别需要角度时（`withAngles`）：先找 `_turnaround`（多视角转台图）；**没有就用 `_board`（角色板）顶替** | `refs.go:213-217`（`character_angles`） |
| 角色板/转台图 | **近景/特写不附**：那种景别只用得上 1/4 像素的脸 | `refs.go:218-220` |
| 去冗余模式（`compact`） | 只喂那张拼合图，**它的最左格就是定妆照** | `refs.go:222-226`（`character_front_in_strip`） |
| Q 版形象 | 只在**内心活动镜**顶替本人（口径：本人不演这段） | `refs.go` 的 `character_chibi` |

**结论**：**两张都参考，分工不同** —— 定妆照管"这是谁"（一直在），角色板（原三视图板）管"从哪个角度"，
且只在需要角度、或没有转台图时上场。**单张的 `_board` 从来没进过 H3 的参考图集合**
（`board.go:34` 的注释也写着 `_board` 不在 `<base>.png` / `<base>_turnaround.png` 之内）——
上面看到的是"它顶替转台图当角度参考"这一条 2026-09-27 的定调（用户原话：
「有了三视图，就不需要转台图、背面、侧面、四分之三了」）。

## 三、三视图 → 角色板，并显示更详细

- 用户可见的字样统一改叫**角色板**：详情弹窗的标签改成
  `角色板（正/侧/背 + 头部细节）`（说清它画了什么，不用再猜"三视图"是啥）；
  项目参数抽屉与详情弹窗的 tooltip 同步（"角度参考已由角色板接手"）。
- **显示更详细**：角色板/转台图/场景板这些横向大图改成**占整行 + 更高的框**（`BOARD_BOX_H = 260px`
  对普通格子的 `190px`）—— 一张图 15 格，190px 高的缩略图根本看不清格子里画了什么。
- 文件名后缀仍是 `_board`（跨包契约，不动）；`frontend_library_detail_test.go` 那条门
  从"逐字要求 `height:' + IMG_BOX_H + '`"改成"**有定高 + 有比例**"（老判据挂在字面量上，
  会把正确的实现判红），并**新增**"角色板占整行 + 更高框 + 标签写清内容"三条断言。

## 四、附带修掉一条真缺陷：ASR 的孙进程没被清算

跑集成测试时当场咬到：`TestRunRenderDrivesEnginePerShot` 结束时清理临时目录失败 ——
`clips: The process cannot access the file because it is being used by another process`。

根因：ASR 工具链是 `asr.cmd`(cmd.exe) → `python.exe`，而 `exec.CommandContext` **只杀直接子进程**：
超时/取消之后 python 还活着，占着工作目录与 CPU（生产里的样子就是"点了停止，风扇还在转"；
质检逐镜跑 ASR 时，超时那一镜会留下一个 python）。

修法：`Transcribe` 自己 `Start`，把进程放进 **kill-on-close 的作业对象**
（`internal/asr/job_windows.go`，`JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`，约 60 行 kernel32 调用、
无新依赖；非 Windows 有 build-tag 的诚实兜底）—— `defer job.Close()` 一关，**整棵树被内核清算**。

**门** `TestTranscribeKillsTheWholeTreeOnCancel`（行为级）：假工具先写结果文件，再起一个
**7 秒后写标记文件的孙进程**，然后自己挂住；1 秒后取消 ctx ⇒ `Transcribe` 提前返回，
之后等 9 秒**标记文件必须始终不出现**。**反向验证 2/2 全红**（N2：不放进作业对象 ⇒ 孙进程写出标记 ⇒ 门红）。
修完这一条，`internal/pipeline` 整包测试从"清理失败"回到 **77.4 秒通过**。

**边界**：作业对象只挂在 ASR 这条链上。全仓其它子进程仍是"只杀直接子进程"的语义 ——
要推广得逐个评估（ComfyUI 是我们**故意**留着长期跑的，不能一起收）。
