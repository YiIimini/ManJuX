## ① 风格介质矛盾的判据接到 `ValidatePlan`（LLM 自编那句也判）

**病根**（2026-10-10 真机）：`plan.style` 被剧本会话自编成「中式梦幻磅礴的半写实绘画风，**3D CG 质感**：…」，
而本书风格卡写的是 `a semi-realistic hand-painted finish … **NOT a plastic 3D render**`。
平台随后按 `3d cg` 展开成 `next-generation 3D CG character render, realistic skin shading…`，
出图就是塑料娃娃（平台自己的 VLM 原话：「皮肤蜡感、磨皮重」「像 3D 塑料娃娃，不像真人定妆」）。
判据此前只吃**用户勾的预设 key**，LLM 自编的那一句**从来没被判过**。

**修法**：
- 新建 `internal/project/style_medium.go`：五族介质词表（live / 2d / 3d / painted / stopmotion）、
  **否定窗口 28 字符**（`NOT a plastic 3D render` 是**否定**，不算声明 3D）、
  `StyleMediumFamilies` / `StyleMediumConflictNote` / `MediumFamilyLabel`（中文名只此一份）/
  `StyleMediumConflictAdvice` / `RuneLenHead`。
- `internal/project/plan_contract.go` 的风格判据加一支：
  `else if c := StyleMediumConflictNote(p.Style); c != ""` → `add("warn", "plan.style", …)`
  ⇒ **预检 / 入口都看得见**（渲染前点名，不是等出图）。
- `internal/pipeline/prompts.go` 的 `mediumLabel` 改为委托同一份词表（**同一句话不判两遍**）。

**门** `internal/project/style_medium_test.go` 三条：
① 真机本书 `art_style` 原文里那句 `NOT a plastic 3D render` **不许误报**（只读出 `painted`）；
② 真机 LLM 自编串读出 `painted + 3d`；③ `ValidatePlan` 挂 **warn** 且正确串不报。

**口径不变**：矛盾时**照用户/剧本写的渲**，平台只负责当场说清（`StyleMediumConflictAdvice` 同一句文案）。

## ② 定妆照提示词瘦身（去重复取景块 + 摘要收成完整从句）

### ②-1 取景：**卡自己带来的**取景句一律剥掉

**先取证**（探针 `internal/pipeline/zz_probe_sheet_slim_live_test.go`，读盘上 `asset_map.json` 的**成品卡**，

开头声明 `BUST PORTRAIT (…) SCALE (mandatory) … The picture is a CHEST-UP portrait: …`（一句话里写三遍）
+ 收尾纪律 `FRAMING (mandatory): … ONE QUARTER … CHEST-UP portrait …`，不是三套独立口径。
这两句是 2026-09-27 实测出来的「开头声明 + 末尾收纪律」（只写末尾压不住卡里大段的全身描述），
`portrait_framing_lead_test.go` 守着 ⇒ **本轮不动它们**。

**真正修到的两处**：
- **卡侧**（新写的卡 / 旧措辞的存量句）：`StripPlatformFramingSentences` 提到人像三档
  （人 / Q 版 / 人形机械）**在 `rewriteSheetFraming` 之前**统一剥；`hitsFramingPhrase` 改**大小写不敏感**
  （`CHEST-UP portrait` 这种半大写写法原来一个词都不命中）。判据仍是**句首 80 字符窗口**，
  免得把含 neck/shoulder 的**外貌正文**一起吃掉。
- **存量成品**（走幂等短路的"重新生成"）：新增 `TightenSheetFraming` —— 用**同一份判据**把多余的取景句删掉，
  保留当前措辞的收尾纪律（缺了补在 `FACE ID` 之前），**逐句只删多余的、其余字节原样保留**。
  - 真机咬出的那个洞：**Q 版卡**是被人像那套装配的（标记 `IDENTITY FIDELITY`），而重出时 kind 判成 chibi
    ⇒ 卡里那份人像收尾纪律与新的 Q 版取景纪律**并存**：改前 **9554 字 / `FRAMING (mandatory)` ×2**，
    改后 **8347 字 / ×1**（`−1207` 字）。
  - 过程中咬出**我自己两处**错：① 第一版用「拆句再 Join」⇒ 不幂等（收尾纪律本身 2~3 句，
    整串匹配不上 ⇒ 被当多余句删掉再补一份，字节被重排）；② 保护区间用含 `. ` 尾随空格的 raw 去比
    ⇒ 收尾纪律最后一句永远"超出保护区"、**被误删**（真机那 196 字的裁切口径句就是这么没的）。
    改成**按命中区间删 + 去空白后比区间**。

**门**：`portrait_slim_test.go`
`TestPortraitPromptStatesFramingExactlyOnce`（判据是**旧措辞那句的特征串 `head-to-body ratio`** ——

### ②-2 CAST DISTINCTNESS：六条摘要收成**完整从句**（不整块删）

**真机形态**（逐字取自盘上卡）：旧实现按 **160 字符硬切 + 补省略号**，六条**全部切在词中间** ——
`…clear jawline, deep-blac…`、`…feathered and diss…`、`…heavy hooded eyelids over eyes …`、`…thick ey…`。
半截词对模型不是信息、是噪声。

**修法**：新增 `distinctnessNote` —— 每条在预算（110 字符）内**在逗号/分号处断**，断了补整词边界，
**不加省略号**；空串则整条不入列。块本身（防撞脸的 `traits` 结论句 + `Do NOT depict …`）**一字不动**
（2026-09-11 实测：不列别人时"胖→清瘦、疤→无疤"，列出来才掰得住）。

**真机量出来的变化**：同一批真机卡，六条摘要 **966 字符 → 475 字符（−491）**，
装配出的块里**省略号 0 处**（改前每条都可能切在词中）。

**门**：`TestCastDistinctnessEntriesAreWholeClauses`（夹具＝盘上六张卡的真实外形段；
逐条在源文里找得到，且**紧接着的字符不是字母/数字** ⇒ 没切断单词）。

## ③ VLM 预算：起步 16k + 空正文自动加倍重试一次

**实测依据**（同一张图、同一份 5 条评分表，`deepseek-flash`）：`max_tokens` 2048/4000 ⇒ **正文 0 字**
（`finish=length`，思考吃干净）；8192 ⇒ 257 字正文（思考占 **5347**）—— 余量只有 1.5 倍。

**修法**（`internal/llm/client.go`）：`visionMaxTokens = 16384`、`visionMaxTokensRetry = 32768`；
`ChatVision` 收到 200 就立刻解析：**正文非空即返回**；正文空且预算未到上限 ⇒ **加一倍重试一次**；
仍空**如实报错**并带上 `finish` 与预算，给出"换非推理模型 / 减评分表或图片数量"的建议。

**门** `internal/llm/vision_budget_test.go` 两条（httptest 假端点）：
① 第一次空正文 + `finish=length`、第二次出正文 ⇒ 断言**正好重试一次**且第二次预算更大；
② 两次都空 ⇒ 报错含 `finish=length`、共 **2** 次请求。

## ④ 取景 / 分辨率二选一：**选"真做成胸像"（口径收口），不改出图尺寸**

**决定**：不动 `assetImageSize`（资产图 = 项目成片画幅 768×1344），把力气放在"取景只留一处"上（②-1）。
**理由（都是盘上/规范里的事实）**：
1. 参考图**必须与成片同比例**是既有设计（`asset_size_test.go` 顶着"构图漂移从第一帧就埋下"那条事故）；
   单独拔高尺寸要连带把"参考图 = 成片画幅"这条口径改掉，**存量项目全部资产作废**（用户现在有 48 集的存量）。
2. "头占 1/4"的尺度线索与裁切口径**平台早在写**（`portraitFramingClause` 2026-09-29 实测定案）；
   真机偏离（VLM 原话「头连发髻约占画面高度 1/3；**裁到腰胯**」）是**被重复口径稀释**，
   本轮把卡侧重复收口正是冲这一点。
3. 拔高出图尺寸的收益**未实测**：本地 H3 拿参考图做什么尺寸的编码我没在这轮验证，
   而 Qwen-Image（int8）出图时间/显存是实打实的成本 ⇒ **不拿没验过的东西换存量资产作废**。

**如实说明边界**：本轮**没有重出图做 A/B**（要 ComfyUI 冷启动 + 逐张出图）。

## 生效范围（存量的处理）

- 「重新生成」某张定妆照即走**新口径**（不用重渲视频；定妆照本身要重出才变）。
- **人的那批卡**：装配结果**逐字节不变**（它们已经是"一处收口"的形态）⇒ 没有回归风险；
  改的是**卡侧剥离**（防新卡带进来）与**摘要收句**。
- **Q 版卡**：重出时补齐 Q 版自己的块（6664 → 8347 字），且**不再**复述人像取景纪律（改前 9554 字、两套并存）。
- 摘要收句对**新建与存量**都生效（每次装配都算一遍）。
