# 技能侧整改单（2026-09-29 · 由平台侧实测倒推）

> 这份文档是给**技能侧**（`manju-novel` 技能：小说 → 剧本 → 人物道具/场景/分镜 的产出侧）看的。
> 每条都带**平台侧实测证据**与**要求的产出口径**，并标明"谁改"。
> 平台侧只对自己能确定性兜住的事负责（装配点/校验门）；凡属"生成时就该写对"的，列在这里。

## 0. 为什么要有这份单子

平台侧这一轮修的是"模型没写对 → 平台兜住并如实播报"，但**兜底不等于写对**：
兜住只保证"不出灾难"，不保证"好"。下面这些是平台侧**兜不住或兜得很勉强**的，
必须由产出侧（技能）改正，否则每一集都要靠平台补救，质量上限被压在补丁那一层。

判据一律是**机检**（平台侧的门目录 `docs/门目录.md`），不是口味。

## 1. 剧本（① 小说转剧本）必须结构化

**证据**：本集 `source.txt` 的【本集剧情】3189 字，是**散文体剧本** —— 画面、对白、道具都有，
但**没有任何结构标注**。⑤ 分镜拿它只能自己猜结构，实测后果：重点平摊（压不住场）、机位乱跳、
道具位置关系丢失（卡面写「Q版总蹲在碑生左肩上」，成片里 Q 版单独蹲在石台上）。

**要求**（平台侧已按此把输出契约钉进提示词，产出侧要对齐同一条契约）：

```
【开场爆点】一句话（3 秒内抛出极致冲突/绝境/反转，无铺垫、无旁白起手）
【场 N|地点|时间|内外】
  目的:  冲突:  转折:  爽点:（小/大，具体哪一下）  钩子:
  正文:（短句、画面感、台词逐字）
【关键道具与信息】
  - 道具名|谁拿着或**在什么位置**（「蹲在碑生左肩上」这种）|在本集的作用
  - 信息点|第几场第一次揭示
【本集钩子】最后一段的终极钩子
```

依据：作者的《一、网文小说转剧本提示词指令》（爆点/爽点密度/段段留钩/人物与道具细节）
＋ 平台侧 `internal/server/novels_jobs.go` 的 `briefSectionMarkers`。

**谁改**：技能侧（产出侧）。平台侧的 `missingBriefSections` 会在缺节时告警（不会拒收）。

## 2. 分镜的 `view` / `view_note` 纪律

**证据**：本集 11 镜里 **8 镜既没写 `view` 也没写 `view_note`** → 机位由模型每镜自由发挥，
成片"机位随机跳、越轴"。平台侧首次重跑时把纪律写进了提示词与 schema，**模型一条都没写** ——
最后靠平台补了一趟"机位校对会话"（`director.FillShotViews`）才补齐 16/16。

**要求**：
- 官方 9 条视角词**逐字**使用（`ultra-wide 45-degree aerial view` / `ultra-wide aerial view` /
  `low-altitude flying aerial view` / `ultra-wide eye-level deep perspective` / `compressed distant depth` /
  `low-angle upward view` / `low-angle peeking upward view` / `low-angle strong perspective` /
  `telephoto compression`）；
- **对不上就留空并写 `view_note`** 说明原因（平视中近景/主观镜头/越轴反打…）——官方那 9 条是
  *大机位表*，平视中近景、俯拍特写没有对应项，硬填写错词比留空更糟（平台侧裁定 A）；
- 同一场戏相邻镜头**不无故越轴**；故意越轴要写出来。

**谁改**：技能侧优先（产出时就该写齐）；平台侧的校对会话是兜底，不是替代。

## 3. 定妆照的**头身比**要能被取景读到

**证据**：用户点名「碑生（丙十七）、钟离、碑生·Q版、崔无咎 这几个定妆照的比例就不对」。
实测两张 768×1344 白底竖幅：霍延（卡面「高壮、肩极宽、约八头身」）**头占画面一半以上**；
碑生（「瘦高、约七头半身」）头约占 1/3 —— 七头半身/八头身的高瘦角色全塌成"大头脑像"。

**要求**：
- 角色卡里的 **`比例锚_机器`/头身比**必须是**可直接画出来的数**（如 `7.5 头身`），
  并且与身形描述（瘦高/矮壮）一致，不要只写"高瘦"这类形容词；
- 定妆照提示词里要**同时给出取景尺度**：头占画面高度约四分之一、肩宽于头、胸与上臂填满下半幅
  （平台侧已补进 `portraitLeadBust` 与 `PortraitFramingClause`，产出侧请勿再写"全身/半身"这类
  与它冲突的取景词）。

**谁改**：平台侧已补取景句 ✔；**技能侧**负责"头身比数值得可信、与身形一致"。

## 4. Q 版形象：必须是 **Q 版手办/动漫**质感，并且**由对应角色图生图**产出

**证据**：用户原话「Q版形象是那种Q版手办动漫形象的，使用对应角色图生图产出，不是写实的那种，不可爱」。
平台侧现状：Q 版卡走的是**文生图**（`PortraitPrompt` 的 chibi 档 + 写实介质块），
出来的是一张"写实比例缩小的真人小孩"，不是手办/动漫质感。

**要求**（产出侧与平台侧各一半）：
- **技能侧**：Q 版卡的 `image_prompt` 要写明是 **Q-version / chibi FIGURE in an anime figurine style**：
  大头（2.5–3 头身）、圆润、大眼睛、简化五官、手办质感（哑光树脂/粘土感、干净的分件与接缝可选）、
  **可爱**优先于写实；并**不要**再写 `photorealistic`/`cinematic` 这类把人往写实拉的词；
- **平台侧**（已排期）：Q 版资产改成**图生图**——以主卡定妆照为参考图（ref2img），
  只改画风不改身份（同一张脸的 Q 版化），而不是从零文生图；
- 参考实现位置：`internal/pipeline/stages_assets.go` 的 Q 版派生（`chibiID`）与
  `entity_prompts.go` 的 `KindChibi` 档位。

**谁改**：以平台侧为主（图生图链路）+ 技能侧改 `image_prompt` 措辞（本节前半）。

## 5. 场景卡的光照：暗光会**传染**给分镜

**证据**：本集质检采样帧最暗帧占比 —— 镜 8 **47%**、镜 10 **52%**、镜 11 **77%**（判黑屏不合格）。
平台侧已在每一镜注入亮度守卫句（11/11 镜都有），但**参考图的暗调仍然主导成片**：
场景定妆照（`assets/scenes`）是暗调的话，镜头会继承它的曝光。

**要求**：
- 场景卡的 `image_prompt` 必须**写明光源**（主光方向、色温、是日戏还是夜戏）；
- **夜戏也必须有可见光源**（灯、火、月光的方向），不要写"漆黑/无光/浓雾压暗"这类没有光源描述的暗；
- 一个场景一张卡，**同一场戏的光照口径要一致**（不要同一地点两张卡一明一暗）。

**谁改**：技能侧（场景卡措辞）。平台侧的亮度守卫句只是安全网。

## 6. 器物卡不许凭空长字

**证据**：用户报「旧拓布 上有英文？」——器物（`kind=object`）定妆照上出现了拉丁字母。
根因：器物档此前**没有任何"不许写字"的约束**（只有转台那段有），而提示词本身是英文，
模型会把提示词里的词当装饰字画上去。

**要求**：
- 器物 `image_prompt` 里若**没有**铭文，就不要出现任何"文字/标签/牌子/书名"类描述；
  有铭文的，写明**是哪几个字**（平台侧按官方 ON-SCREEN TEXT 规则要求引号内逐字）；
- 平台侧已补 `NO LETTERING (mandatory)`（`entity_prompts.go` 的 `KindObject.SheetIdentity`）✔
  —— 技能侧对齐即可，别再依赖平台兜。

**谁改**：平台侧已补 ✔；技能侧对齐措辞。

## 7. 日志语义（产出侧调用的文案）

**证据**：用户报「运行日志中的函数方法调用、已确认、已入库这种是完成的类型，为什么标红？」
实测根因在平台侧：分镜的 `OnNote` 通道**一律发 warn**，于是"✔ 已把 12 处分镜对上卡"、
"✔ 给 8 镜补上了机位"这类**完成**播报全被标红（已修：按文案首字符判级别 ✔/⚠/其余）。

**要求**（技能侧发事件时同规矩）：
- `success` 只给**确实完成**的事（✔）；
- `info` 给过程与解释；
- `warn` 只给"用户需要知道、且可能需要动手"的事；
- **不要**把"平台已经自动兜底"的事报成 warn（平台侧已把这类降为 info 并写明"不需要你做什么"）。

**谁改**：平台侧已修 ✔；技能侧新增播报时按此分级。
