# H3 多风格组合：官方口径 + 介质互斥（2026-10-09）

用户原话：「H3 不是可以多风格组合吗？」

## 1. 先查官方原文（不许凭印象）

官方仓在本机：`D:\Ai\Refs\MiniMax-H3`（与 `docs/官方H3技能同步.md` 记的同步源一致）。

| 结论 | 官方原文（`file:行`） |
|---|---|
| **风格是一句话里的并列形容**（不是结构化多风格字段） | `…/h3-prompt-writing/references/base-en.txt` §4.1：「At the beginning of `[Shot 1]`, state the overall style and initial composition. **Common styles include `Cinematic`, `live-action`, `2D-animated`, `3D CG`, `claymation`, `watercolor`, and `vintage film`**」，示例 ```[Shot 1] Live-action, cinematic, a medium-wide shot frames...``` |
| **` + ` 是官方给「任务类型」的组合语法，不是风格** | `references/ref-en.txt`：「When a task satisfies multiple relationships, **combine the task types with ` + `** and do not repeat a type」 |
| 风格也可以由**参考资产**提供（参考生成） | `ref-en.txt` §参考关系表（`reference generation` / `weak_reference` 等） |

⇒ **用户说的对**：H3 支持"多风格"。但方式是**提示词里的并列句**（逗号并列），
而不是权重/风格 ID 那种结构化组合。**平台原来的做法有两处不实**：

1. 上一轮把多选预设用 **` + `** 拼 —— 那是官方给**任务类型**的语法，用错了地方；
2. **没有做互斥检查** —— 而平台自己的规则（`docs/技能侧改动-电影级口径.md` 检查表）明确写着
   风格串**不许含互斥词组**（「`no cartoon or anime styling` 与 `SEMI-STYLISED … faces` 同时出现 = 自相矛盾」，
   "负向禁令与自己的正向词打架"是真正的毒药）。我当时写成"有意不做冲突检测"，这一轮补上。

## 2. 改了什么

| # | 位置 | 改动 |
|---|---|---|
| 1 | `internal/pipeline/prompts.go` `composeStyleHint` | 组合改用**逗号并列**（对齐官方风格句写法），并**去重**（同一预设勾两次不再出现两遍）；` + ` 不再出现在风格串里 |
| 2 | 同上 `StylePresets` | 每项新增**介质族** `Medium`：`live`（真人实拍）/ `2d`（二维动画）/ `3d`（三维 CG）/ `painted`（手绘·水墨）/ `stopmotion`（定格）。**只给"串里明确写了介质"的预设填** —— 题材/调子类（`cyberpunk` / `urban_xianxia` / `film_noir` / `hongkong`）留空**不参与判定**（不猜介质，免得误报） |
| 3 | 同上 `StyleMediumConflicts` | 介质**多于一种**时返回一句可直接显示的说明（如「国风电影级（三维 CG） 与 国漫二维动画（二维动画）」）；同介质重复**不算**矛盾；输出顺序固定（map 遍历无序会让播报与判据不稳） |
| 4 | 同上 `MediumLabel`（导出） | 介质中文名**只此一份**（界面与播报都用它，前端不再抄表） |
| 5 | `internal/server/novels_produce.go` | 勾出矛盾组合时 **warn 如实点名**：一个画面不可能同时是这几样、会被拉成四不像（如塑料 CG 脸）、**平台照你选的做**、建议只留一项 |
| 6 | `internal/server/handlers_settings.go` | `/api/meta` 的 styles 增加 `medium` + `medium_label`（界面据此判定与显示） |
| 7 | `frontend/src/views/NovelsView.vue`（导入框）与 `components/ParamsDrawer.vue`（项目参数） | **勾选那一刻**就显示互斥提示（判定只用后端给的 `medium` 做**相等比较**，族名与中文名都由后端给） |

**决策（写清理由）**：矛盾时**仍然照用户选的做** —— 用户拍板优先是既有口径（"风格归上游/用户"）。
平台的职责是**当场说清**，不是替用户改选择；所以提示写成"会被拉成四不像 + 建议只留一项"。

## 4. 反向验证：7/7 全红（`reverse_verify_medium.ps1`）

① 组合回到 ` + ` ② 不判介质互斥 ③ 重复勾选不去重 ④ `meta` 不带介质 ⑤ 矛盾组合不播报
⑥ 导入框不提示 ⑦ 参数抽屉不提示；跑完 5/5 文件 sha256 与基线一致。

**过程中又抓出我自己三处摆设守卫（同一类错第三次记）**：

- ⑤ 第一版断言"文件里有 `style.Conflicts`" —— 把它罩进 `if false` 后**标识符还在**，照样绿
  ⇒ 改成断言**生效的条件整行** `if len(style.Conflicts) > 0 {`。
- ⑥⑦ 第一版断言"文件里有『介质互相矛盾』这句中文" —— **注释里也有这句**，把渲染文案改掉照样绿
  ⇒ 改成断言**渲染出来的那一行** `⚠ <b>介质互相矛盾</b>：{{ styleConflict }}`。

（同一类教训第三次出现，"改坏还绿"的三个变体都齐了：标识符出现 ≠ 代码执行；中文出现 ≠ 界面上有；
注释命中 ≠ 断言命中的是承重点。）

## 5. 边界（说清楚）

- **介质族是我逐条判定的**（依据是各预设串里的原文，如 `PHOTOREALISTIC LIVE-ACTION` ⇒ `live`）——
  它是**保守**的：只判明确写了介质的；将来加新预设时**必须一并填 Medium**，否则它不参与判定
  （宁可不说，也不误报）。
- **只判介质矛盾**，不判题材/调子冲突（如"黑色电影 × 赛博朋克霓虹"）：没有可靠判据说哪种组合一定矛盾，
  乱拦会拦掉用户要的效果。
- 提示是**建议**：平台不擅自改用户的选择（这条是有意的）。
- 官方那条"风格句在 `[Shot 1]` 之前/之后"的位置纪律由既有的 H3 装配链负责（`docs/官方H3技能同步.md` ✓），
  本轮没动它。
