## v0.34.0 拆集规则回归 1:1 + 镜头级增强(Mask / Audio Drive / 多视角转台图)+ 工程改造

**拆集严格一章一集(本次最重要的定调)**:根因——提示词自相矛盾,集粒度铁律写「默认 1 章 1 集」,随后又留了「信息极密集章可拆 2 集」的豁免并配「不要压并事件」的表述,模型择优执行了「多拆」,实测第 1 章被拆成两集、集名与章名对不上,用户在第 N 集里找不到对应的第 N 章;修复——段模式提示词改为 `本段覆盖 N 章:每章正好 1 集(章名即集名),本段应为 N 集`,删去多拆豁免,并明确「一章内信息量大就多给分镜(不设上限),不要把一章拆成两集,也不要把两章压进一集」;护栏:`checkOneChapterPerEpisode` 检测「一章被拆成多集」并告警(**不自动合并** —— 合并要重排 Brief 与集号,风险高于收益,由用户决定是否重拆),章节覆盖核对的警告文案补齐代价说明(缺章在最前面时自动补缺意味着删除全部分集后重拆,先核对是否只是 chapters 标注漏项);单测见 `episode_title_test.go`。

**集名即章名(含代码兜底)**:根因——提示词已要求 TITLE 取章标题原文,LLM 仍自起文艺标题(实测第 001 章《第一万三千七百四十一号》被起成《七文一斤》),集名一旦脱离章名,「章→集」失去可对账性,章节覆盖核对随之误报缺章(实测误报缺第 1、2 章,而内容其实都在);修复——解析层新增 `normalizeEpisodeTitles`,从 CHAPTERS 字段解析出「第一个章头 + 其标题」后**强制覆盖** TITLE(解析不出时如「第1章~第2章」保留 LLM 标题,不强行清空);验证——`TestNormalizeEpisodeTitles` 覆盖自起名/区间无标题/空标题/本来就一致四种情形。

**分镜数量不设上限**:根因——`MaxShotsCeiling=30` 与「镜头数由内容决定」的定调冲突,内容密的一章会被硬截到 30 镜;修复——`MaxShotsCeiling` 30→120(仅作安全网,防手改 JSON 写出天文数字把渲染成本打爆)、前端输入上限同步 30→120(`el-input-number` 的 `:max`;其标签文案仍写「最多 30」,未同步)、内容驱动(`max_shots=0`)时规划轮不再预设总镜数(提示词明写 `there is NO upper limit`,`defaultContentDrivenShots` 只服务分批阈值与秒数换算、不进提示词)、`normalizeSegments` 也不再截断(`segMax` 取规划轮自己给出的最大镜号);同批修复 `Sanitize` 把 `max_shots=0` 钳成 1 的语义错误(旧实现下用户点一次参数抽屉保存,十余镜的分镜就退化成「1 镜 / 7 秒」),单测见 `http_contract_test.go` 与 `params_test.go`。

**角色多视角转台图**:根因——定妆照只有正面一个角度,转身/走位/多人同框时身份漂移;Krea-2 img2img 路线实测走不通(它是纯文生图模型、无身份条件注入,denoise 0.7 直接换人、0.55 角度几乎不变,属模型固有限制);修复——改用有身份参考机制的 H3 Ref2V:定妆照生成后自动出「原地缓慢转身」短视频(124 帧≈5.2s)→ 按 0/1.3/2.6/3.9s 抽 4 帧 → ffmpeg hstack 拼成 `<base>_turnaround.png`,渲染时由 `AssembleShotRefs` 作该角色的**第二张参考**自动追加(`refs.go` 的 `turnaroundPath` 仅在文件存在时追加,老项目参考图组成与渲染指纹不变;拼成单张以只占 1 个参考槽);契约影响——`sysH3Format` 改为要求 LLM「按画面内容而非下标对应 Subject」(有转台图的角色占 2 张图,场景下标不再固定 N+1);增强项:任一步失败只告警不阻断;验证——真机 `ref_images` 从 1 张变 3 张(定妆照+转台图+场景),`TestTurnaroundPath` 锁引用判据,`TestTurnaroundRender` 为真机开关测试(`MANJUX_VERIFY_TURNAROUND=1`,默认跳过)。

**Mask 局部重绘**:根因——某镜只有手部/道具/人脸局部崩坏时,整镜重渲既贵又会把本来正确的部分一起改掉;修复——新增 `maskgraph.go` 与 `POST /api/projects/{id}/shot/{shotID}/mask-fix`:源帧 → SAM3 跨帧跟踪(`SAM3_VideoTrack`/`SAM3_TrackToMask`)→ `MVEx_SubjectCrop` 裁出 → H3 Ref2V 重绘(裁剪出的主体作 `ref_images` 参考,锁住外观)→ `MVEx_SubjectUncrop` 羽化贴回原帧(其余帧像素原样保留,动作因此不变),音轨沿用源视频;只用 ComfyUI 核心节点 + MaskVidExperiments,不引入 VideoHelperSuite 等额外依赖;默认复用该镜原提示词(只把崩坏部分描述改对);产物落成独立文件 `shot_00N_maskfix.mp4`,**不覆盖原镜头**;依赖 ComfyUI v0.35 的 `Fix MiniMax H3 denoise masks`;验证——`TestMaskGraphContract` 锁定裁剪/重绘/回贴链路与 SAM3 模型名 + 前端镜头卡「局部重绘」按钮。

**Audio Drive 音频驱动**:根因——精确台词路线需要「先把配音做成确定资产,再驱动画面」,而此前只能靠提示词文字描述台词;修复——`Job.Audios` 打通到 H3 Ref2V 的 `ref_audios` 条件(`engine.go` 先上传音频再拼图),新增 `POST /api/projects/{id}/shot/{shotID}/audio-drive`,人物口型与动作节奏跟随给定配音;同样产出独立文件 `shot_00N_audiodrive.mp4` 不覆盖原镜头;验证——`TestRenderGraphAudioDrive` 锁定三件事:聚合键名正确、音频加载节点存在、「只有音频没有参考图」的纯音频驱动仍走 Ref2VA 而非 t2va。

**LTX / ESRGAN 2× 放大(引擎层)**:新增 `upscalegraph.go`,在已完成的镜头上追加 2× 放大分支,两条链路都重混**源音轨**;LTX 隐空间 2×(`VAEEncodeTiled(LTX VAE)` → `LTXVLatentUpsampler` → `VAEDecodeTiled`)按 LTX 视频 VAE 的 8n+1 时间布局补齐尾帧、解码后 `ImageFromBatch` 裁回原帧防时长漂移;ESRGAN 帧级 2×(`UpscaleModelLoader` → `ImageUpscaleWithModel` → `ImageScaleBy(0.5)`)收敛到精确 2×;模型已就位(`ltx-2-spatial-upscaler-x2-1.0.safetensors` 949.6MB / `4x-UltraSharp.safetensors` 63.8MB,位于 `comfyui/shared/models/`,经 `extra_model_paths.yaml` 注册);**当前只有引擎实现+契约测试(`upscale_contract_test.go`),尚无 HTTP 端点与界面入口**,接入前用户无法从界面调用。

**资产库详情弹窗与重抽**:根因——库里只有一张主图与一句话描述,想比对多视角/转台图或想换一张只能删了重建;修复——`Entry.Images` 多图字段 + 入库时 `relatedImages` 自动收集同目录的多视角原图(`*_view_*.png`)与转台图(`*_turnaround.png`)+ `GET /api/library/{kind}/{name}` 详情接口 + `?file=` 多图服务(防目录穿越);前端点击库卡片弹出详情:全部图片(带用途标签、可放大)、中文描述、英文提示词、来源、首次入库项目与复用次数,支持「重抽(同角色换一张)」(`POST /api/library/{kind}/{name}/regen`,描述与提示词不动、只换随机种子,同时 `ClearRelated` 清掉旧的多视角与转台图)与删除;与「抽卡」的区别:抽卡抽全新角色,重抽是同一角色再摇一次。

**渲染前节点预检 + 冲突插件检测**:根因——此前只有打开管理页才查节点(且只查 2 个),渲染跑到一半才失败,用户看到的是 ComfyUI 原始 `node_errors`,分不清缺插件还是缺模型;修复——`preflight.go` 的 `Preflight` 在渲染起点按本次 mode 校验 graph 根节点(Ref2V / I2V / SigmaShift)是否存在,缺失即**阻止渲染**并给中文提示;引擎不可达时返回空(不把「暂时连不上」误判成「节点缺失」);条件缓存与镜间接缝**刻意不列入阻断项**(缓存已有自动降级、接缝缺失 ComfyUI 会回明确报文,误判会挡住整个生产);`Conflicts` 扫描 `custom_nodes/` 下未禁用的已知冲突插件(`MiniMaxH3-Cache` 的启动期 monkeypatch 会让镜间接缝必然失败)**只告警不阻断**;验证——`preflight_test.go` 覆盖冲突检测的启用/禁用与 RootDir 为空两种情形。

**ComfyUI v0.35.1**:含对本项目直接相关的 `Fix MiniMax H3 denoise masks`(局部重绘依赖的底层行为);新增插件 MaskVidExperiments(遮罩裁切/回贴)与 comfyui-vrgamedevgirl(音频处理)。

**条件缓存清理闭环**:根因——ComfyUI 侧的条件缓存数据是 `models/conditioning/*.pt`(文件名只有 `s{shot}_{hash}`),此前清理只删本地 sidecar 记账不删 `.pt`,实测堆积 **4.9GB**;修复——清理项目缓存时按记账一并删除对应的 `.pt`,形成闭环。
