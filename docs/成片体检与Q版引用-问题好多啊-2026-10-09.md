> 过程中**咬出我自己一个真 bug**：`srtSeconds` 把毫秒位当"1 位小数"处理，
> `00:00:03,349` 被算成 **37.900** —— 体检当场把一条字幕报成"挂了 15 秒"。
> 真机探针把原始字节 + 逐行匹配打出来才定位。修法：`div = 10^len(毫秒字段)`。

**同一个体检又咬出我自己的第二个真缺陷**：契约结论原来"一刀切留前 12 条"，而顺序是

## 4. 修法（确定性，三处收口）

### 4.1 `internal/project/chibi_refs.go`：判据只此一份

- `ResolveChibiRef(ref, cards)` —— 三套 id 空间一次认全：
  ① 卡片 id（`char_jianning_q`，可带 `char:`）；② 技能侧前缀/后缀（`chibi_<本体id>` / `<本体id>_chibi`）；
  ③ **显示名**（`简宁·Q版` / `Q版简宁` / `简宁Q版`，含括注）。
  归一后比较（去空白/间隔号/连接符/括注），剥标记后**整段**参与比较 ——
  所以 `简宁·Q版2` **不会**被截成 `简宁` 而对上简宁的 Q 版。
- `NormalizeChibiIDs()`（**装配点自愈**，幂等）：把 `chibi_ids` 里的显示名改写成方案里真实的卡片 id；
  认不出来的**不改写**、如实记账（`Plan.ChibiRefFixed` / `ChibiRefUnknown`）。
- 闸：只有"Q 版写法"（名字带 `Q版/chibi` 标记）才走本体对号 —— 平白一个本人名（`简宁`）
  **不许**被解析成 Q 版（那是数据错，该让门点名，不该被悄悄换成另一张卡）。
- `ChibiKey` 导出：装配点与渲染侧必须算出**同一个键**。

### 4.2 接进唯一读取边界 `HealPlan` + 两阶段如实播报

`HealPlan` → `plan.NormalizeChibiIDs()`（**排在各项之后**：并卡/引用归一之后卡片 id 才是终态）。
剧本阶段与渲染阶段各播报一遍（重渲/导入包路径不经过剧本阶段）：

> 🎭 把 N 处 `chibi_ids` 的**显示名**改写成真卡片 id（如「简宁·Q版」→ `char_jianning_q`）——
>    不改的话内心镜的 Q 版参考图绑不上（渲染时静默丢掉），画面里就会出现**本人演内心戏**

认不出来的另报一条（点名 + "平台不猜"）。

### 4.3 渲染侧 `refs.go`：三套解析 + 去重 + 本人不附

- 原有 `chibi_<本体id>` 前缀映射**保留**（老方案/夹具形态），新增按 `ResolveChibiRef` 的解析
  与「本体名 → Q 版资产 id」映射（`chibiByOwner`）；
- 内心镜：① Q 版卡自己写出场名单 ⇒ 按 `character_chibi` 附、不当本人；
  ② 前缀写法 ⇒ 原路；③ 显示名/派生写法 ⇒ 按本体对号；三路命中后都 `continue`（**不附本人照**）；
- **同一张 Q 版图只占一个参考图位**（`attachedChibi`）：真机镜 #15 的名单里本人与 Q 版卡都在，
  不去重就会附两张同一张图；
- 非内心镜**一个字不换**。

### 4.4 门与装配点同一判据

`plan_checks.go` 的引用完整性检查先走 `ResolveChibiRef`：**能对号的不报悬空**（渲染侧同样认它），
真认不出来的**仍然 fail**。口径：门管的是"这条引用能不能绑到一张真卡"，不是"写法是不是 id"。

## 6. 边界（永久，不是"还没做"）

- **认不出来就不猜**：`chibi_ids` 写成本人名/写错名字 ⇒ 不改写、门点名 fail，绝不"顶一张卡上去"
  （猜错的后果是把别人的 Q 版画进这一镜，比悬空更难查）。
- 只对**Q 版写法**开闸：`简宁` 这种本人名不会被改写成 Q 版卡。
- **非内心镜**不参与顶替（口径里 Q 版只服务画外演出）。
- **存量项目**：方案里的显示名要**重新读一遍**（预检/渲染/人检走的都是 `HealPlan`）才会被归一；
  已渲出的镜头要**重渲那几镜**画面才会变成 Q 版（改动落在装配点 ⇒ 重跑「合片」即生效，
  不用重渲整集）。
- 体检**只判确定性事实**：不调模型、不主观评"好不好看"；VLM 观感仍是另一条链（`internal/qc`）。

## 7. 这一轮没做的（如实点名）

- 体检清单里那 17 条 ⚠ 里，**已渲出的那一集**的：镜头口型（镜 14 画外音缺闭嘴约束）、
  自创切镜写法、屏幕文字没引号、场景缺时间 —— 这些都是**提示词层**的东西，新方案由
  提示词硬约束与门拦住；**老方案不会自动变**（要重跑剧本分镜或手改那一镜）。
- 「单场占 53%」—— 违反场次配额**不自动重排**（改判 `scene` 会让画面与场景卡对不上、参考图挂错），
  这是第 34 轮就定下的**永久边界**。
- 3 处素材/契约问题（镜 14 说话人不在画面、Q 版引用）里，**引用那条已经由平台确定性修好**；
  镜 14 的说话人不在本镜 `characters` 是**创作内容错**（谁在画面里由剧本定），平台只点名、不代改。

## A. 调研结论（按我们自己的问题分组）

| 问题 | 业界标准做法 | 我们的现状 | 结论 |
|---|---|---|---|
| **字幕贴在人声上** | **forced alignment**：WhisperX（wav2vec2 音素级对齐，arXiv 2303.00747）、stable-ts `align()`、MFA | 四档启发式（人声包络 → ASR 段落 → 收窗口按字数推 → 整镜） | **本轮补齐最省的一档**：whisper 自带**词级时间戳** + 平台侧**字符级对齐**（见 B）。WhisperX 那套要引新依赖与 wav2vec2 模型（CPU 上还要多装 ~1 GB），**先不引** —— 差别在 ±0.02s 量级，而我们原先的误差是 **±1~5 秒**，先把这一档吃满 |
| **谁在说话（说话人归属）** | pyannote.audio 说话人分离；SyncNet / ASD 做「谁在动嘴」 | 按出场名单 + `os` 标记（已做双向归一） | **没引**：pyannote 要 HF token + 模型，且我们的场景是**已知台词+已知出场名单**的构造问题，不是盲分离问题；「谁在动嘴」若要客观验，用我们已有的 insightface 关键点量**嘴部开合**（下一轮的候选，代价：逐镜逐帧，重） |
| **成片自动质检** | 广播级 QC 的标准项：黑帧 / 冻帧 / 静音 / 响度(EBU R128) / A/V 漂移 / 切点 | 只有 blackdetect + loudnorm（两遍归一，但**从不回验**） | **本轮补齐**：`silencedetect` + `freezedetect` + `ebur128` + `scdet` 入体检（见 C） |
| **转场/接缝** | PySceneDetect 场景切点检测 | 按 `scene` 字段决定 1 帧 / 0.5s | **本轮补齐客观验证**：用 `select='gt(scene,0.3)',showinfo` 数**实测硬切点**，与方案里的场次边界对照 |
| **角色一致性** | IPAdapter FaceID / InstantID / PuLID / 每角色 LoRA | 定妆照当参考图 + 撞脸检测 | **没引**：这三者都要 ComfyUI 插件 + 额外模型 + 显存（渲染峰值已吃 22/24 GB），属于**能力升级**要用户拍板；现路线（参考图 + 参考图上限管理）不需要新硬件 |
| **口型对不上** | LatentSync 等开源唇形重同步（后处理） | 靠提示词约束 + 出场名单 | **没引**：那是**重跑一遍生成**（几十 GB 显存 + 时间），而根因是"谁开口"没约束住 —— 已在上一轮按出场名单修掉 |

## B. 落地一：词级时间戳 + 强制对齐（字幕落点的第 ⓪ 档）

- **工具侧**（`D:\Ai\Tools\ASR\transcribe.py`）：`word_timestamps=True`，结果文件里多写一段
  `w   4.18-  6.30 公`（前缀 `w ` 与段级行 `[start-end] 文本` **不同前缀** ⇒ 老平台解析器忽略它、
  老工具不写这一段时新平台自动退回其余档 —— **双向兼容**）。
- **平台侧**（`internal/asr/align.go`）：`AlignLines(已知台词, 词流)` —— 字符级全局对齐
  （Needleman–Wunsch，命中 +2 / 错字 −1 / 空位 −1），命中比例 ≥ 0.6 才算"这句真念了"，
  落点收在**词边界**上。
- **接线**（`internal/compose/subtitle.go`）：新增 `cueAlign` 作为**最高一档**，插在包络之前。
- **真机取证**（这一集镜 10/12 的词级原文逐字拷进夹具）：

## C. 落地二：体检补上广播级标准项（`internal/filmaudit/ffcheck.go`）

`silencedetect`（静音）/ `freezedetect`（冻帧）/ `ebur128`（响度 + 真峰值）/ `showinfo+select(scene)`
（硬切点）四项，纯解析 + 判定（不 exec），夹具是**真机日志原文**（6 份，逐字节对过 sha256）。
真机实测：静音 **10 段**（≥2s 的 7 段）、冻帧 **0 段**（final 与 15 个 clip 全扫）、
响度 **−16.3 LUFS**（目标 −16，不报）/ 真峰值 −1.0 dBTP、硬切 **7 处**。

> 子代理同时报了一个**比这四项更严重**的发现（见 D），并如实指出三处与我的口径不一致
> （真峰值阈值取 −1.0 而平台自身编码目标是 −1.5；`-60dB` 抓不到 H3 的"近冻结"；
> 切点判据需要一道"日志可用"分辨，否则垃圾日志会被印成"实测 0 处"）—— 这几条按他的原话记在这里。

## D. **P0：成片的画面只有 23.7 秒**（这是本轮最严重的发现，且此前无人报出）

**取证**（`ffprobe -select_streams v:0 -count_frames` 于 `output/final.mp4` 与 `master_768p.mp4`）：

```
视频轨：23.708333 秒 / 569 帧 / 1080×1920
音频轨：122.498917 秒 / 5720 帧
format.duration：122.498917 秒   ← 取两条流里最长的那条，所以"看着正常"
```

569 帧 = 前 3 镜（192+175+204）减去 2 帧同场硬切 ⇒ **第 4 镜之后一帧画面都没有**：
观众从第 24 秒起看到的是**定格**，声音照常往下走。而日志里写的是
`✔ 成片就绪:final.mp4(122 秒 · 1080×1920)`。

**根因**（我自己在真机上复现，`scratch/chain4.mp4`）：
- 老代码把 xfade 的 `offset` 直接用**按秒连续累加**的 `starts[i]`；
- 而 xfade 每一步的实际输出长度会被落到**整数帧**上（标称 15.258s ⇒ 实测 366 帧 = 15.25s）；
- 于是第 2 个接缝的过渡窗口 `[15.217, 15.259]` 末端**越过了 A 的真实末帧**（15.25）；
- ffmpeg 的 xfade 遇到"过渡没做完 A 就没了"⇒ **不再输出 B 的任何一帧**，而且**退出码是 0**
  ⇒ 整条链从此静止，后面 12 个输入全部静默丢弃。

**修法**（`internal/compose/xfade.go`）：
1. `xfadeOffsets`：偏移**按整数帧累计**（`offset + 叠化时长` 恰好等于前一链的整帧长度）；
2. 每个输入先 `fps=24,setpts=PTS-STARTPTS` 归一 —— 上游 H3 片段有的比标称时长少 2~3 帧
   （实测 shot_004 是 221 帧而标称 9.3s=223 帧），不统一的话链长会一路短下去；
3. `verifyStitchedLength`：拼完**实测画面时长**，短于标称 0.5 秒以上 ⇒ **直接拒收**并说清原因
   （宁可失败，也不许交付"声音在走、画面定格"的片子）；
4. `ff.Probe` 现在**分开报两条轨的时长**（`VideoDuration`/`AudioDuration`）——这次没被发现，
   根因就是 `format.duration` 只报最长的那条；
5. 体检新增两条 ⛔（`film.tracks`）：画面 vs 音轨差 > 1 秒、画面 vs **逐镜合计**差 > 1.5 秒。

**真机复验**：同样 4 镜、同样参数，修复后 xfade 链输出 **32.417 秒 / 778 帧**
（= 780 帧标称减去 2 帧同场硬切，完全对得上），修复前是 **15.25 秒**。
体检在真机那一集上现在报 **⛔3**（其中两条就是 `film.tracks`）。

**反向验证 3/3 全红**（`scratch/reverse_verify_film_tracks.ps1`）：偏移不扣叠化 / 不比较两条轨 /
不与逐镜合计对照 —— 三根针都让守卫变红（第 3 根第一次没咬住，因为夹具里"画面比方案短"那一路
**没被覆盖** ⇒ 补了第二份夹具，这正是"反向验证抓出摆设守卫"的又一次）。
