# 小说库新增文本格式（.docx / .epub）（2026-10-10）

用户：「小说库解析新增文本格式，请实现功能」

一句话结论：**小说库原来只认 `.md`/`.txt`**，而盘上真机那本书的正文**就是 8 个 `.docx`**
⇒ 书卡列 **0 章 / 0 字**、点「视频制作」得到「小说正文过短(0 字,预处理后)」。
本轮把「哪些算正文」与「怎么取正文」各收成**一处**，并把 `.docx`（Word）与 `.epub`（电子书）
真正读进来；读不了的格式**逐条点名**，不静默跳过。

---

## 一、先取证：盘上到底是什么

```
data/小说/离婚后，千亿前夫跪求复合/
  第一章 签字，滚出顾家.docx … 第八章 神秘代号S与带血的手表.docx   ← 8 个，就是正文
data/小说/ 其余：README.md、_素材包/*.md、library.db、.gitattributes …
```

* 每个 `.docx` 都是标准 Word 导出形态：zip（15 个条目）+ `word/document.xml`（14–31 KB）。
* 旧判据 `hasTxtExt`（`internal/server/novels_text.go`）写死 `".md" || ".txt"` ⇒ 这本书
  `scanNovelDir` 收到 **0 章**，`collectManuscript` 收到 **0 册**。
* 旧读取点是**裸 `os.ReadFile`**（`novels.go` 的 `/api/novels/read`、`novels_produce.go` 的合并）——
  就算把 `.docx` 加进判据，也只会把 zip 二进制当正文，经 `NormalizeNovelText` 变成乱码喂给拆集 LLM。

## 二、改了什么（六处读取点全部收口）

新增 `internal/server/novel_formats.go`：

| 东西 | 作用 |
| --- | --- |
| `novelTextExts` / `novelTextExtsHint()` | 支持格式的**唯一出处**（识别、取正文、报错文案共用一份） |
| `isNovelTextFile` | 「这是不是小说正文册」的**唯一判据**（替掉 `hasTxtExt`） |
| `readNovelTextFile` | **唯一取正文入口**：按扩展名解码，不支持的格式返回明确错误（绝不回二进制） |
| `docxPlainText` | 抽 `word/document.xml`：同段内多个 `w:t` **直接拼**、段落换行、`w:tab`→空格、`w:br`→换行、`w:del`/`w:instrText` 不算正文 |
| `epubPlainText` / `xhtmlPlainText` | `META-INF/container.xml` → OPF → **按 spine 顺序**逐个 xhtml 抽文本；剔 `script/style/head`；`&nbsp;` 等实体用 `xml.HTMLEntity` 还原 |
| `novelUnsupportedReport` | 扫出**平台不读**的文档格式，返回一句能直接播报的点名文案 |
| `fullBookFile` | 「全本」取第一个**可读正文**文件（旧实现只看 `Glob(...)"*"` 的 `fbs[0]`） |
| `novelFileChars` | 一册字数：纯文本按 3 字节/汉字估；**容器格式真解一遍再数** |

只用标准库 `archive/zip` + `encoding/xml` ⇒ **不引新依赖、不要求用户装外部工具**。

接线（都是把旧调用换成唯一判据/唯一入口）：

| 文件 | 位置 | 原来 | 现在 |
| --- | --- | --- | --- |
| `novels.go` | 库根散文件识别 | `.md/.txt` 后缀硬写 | `isNovelTextFile` |
| `novels.go` | 书卡统计（`scanNovelDir`） | `hasTxtExt` | `isNovelTextFile` + `fullBookFile` + `novelFileChars` |
| `novels.go` | 详情章节清单（`/api/novels/detail`） | `Glob[0]` + `hasTxtExt` | `fullBookFile` + `isNovelTextFile` + `novelFileChars` |
| `novels.go` | 阅读（`/api/novels/read`） | `os.ReadFile` 裸读 | `readNovelTextFile`（不支持 ⇒ 400 并说清支持哪些） |
| `novel_format.go` | 章节册清单（`collectManuscript`） | `hasTxtExt` | `isNovelTextFile` |
| `novels_produce.go` | 拆集前合并（逐册 + 全本 + 单文件） | `os.ReadFile` 裸读 | `readNovelTextFile`；读不出来时**连原因一起报** |

**静默跳过这一条**：`novels_produce.go` 在合并前调 `novelUnsupportedReport`，把
「这本书里有 .pdf ×2、.doc ×1（例：…）—— 平台可读的文本格式是 …；这些文件**本次没有读入**」
播出来。用户看到的应当是"哪几个文件没读进来"，而不是对着「正文过短(0 字)」猜。

## 三、真机探针（不是模拟）

```
（书目录可用 $env:MANJUX_NOVEL_PROBE_DIR 指到别的书）
```

实测（2026-10-10，`data/小说/离婚后，千亿前夫跪求复合`）：

```
① 格式分布：.docx ×8（读）
② collectManuscript：章号册 8 册 / 共 8 册 —— 顺序 1..8（按章号，不是目录序）
③ 逐册：1629 / 2247 / 1885 / 2509 / 2385 / 2196 / 2444 / 2276 字（rune），每册章头 1 行，
   SplitChapters 认出的章号分别是 1..8

⑤ 点名：这本书里没有「平台不读」的文档格式
⑥ 书卡：章数 8 ｜ 字数 17571（改前：章数 0 ｜ 字数 0）
```

## 四、门（`internal/server/novel_formats_test.go`）

1. `TestNovelTextFormatRecognition` —— 认哪些（含大写 `.DOCX`）、不认哪些（`.pdf/.doc/.rtf/.mobi/.html`…）。
2. `TestDocxPlainTextMergesRunsAndKeepsParagraphs` —— 夹具照真机形态（章头被切成多个 run、`w:tab`、
   `w:br`、`w:del`、`w:instrText`）；判据钉到**消费方**：`countChapterHeads` 与 `SplitChapters` 必须认出来。
3. `TestEpubPlainTextFollowsSpineOrder` —— manifest 里第 2 章声明在前、spine 说第 1 章在前 ⇒ 必须按 spine 排；
   spine 之外的封面页不读；`script/style/head` 不读；`&nbsp;` 不许原样漏出。
4. `TestReadNovelTextFileRejectsUnsupportedFormat` —— `.pdf` 报错要点名扩展名并带上支持列表。
5. `TestCollectManuscriptAcceptsAndOrdersDocxChapters` —— 8 个中文数字章号的 `.docx`（乱序创建）要全收、
   按章号排（第 1 册在最前、第 8 册在最后），书卡统计 `Chapters=8 / Chars>0`。
6. `TestFullBookFileSkipsNonTextEntries` —— 「全本」里排在最前的是封面图时，仍要取到 `.md`；只有图 ⇒ 空串。
7. `TestNovelUnsupportedReportNamesFiles` —— `.pdf ×2 / .doc ×1` + 举例文件名 + 支持列表；封面目录不计；
   全是可读格式时**不许**报。
8. `TestNovelDocxBookIsListedAndReadable` —— HTTP 三面端到端：书卡 8 章 + 字数=真实正文数、详情列 8 章、
   阅读读回来是正文（不是 `PK…` 二进制）、`.pdf` 请求回 400 并说清支持哪些。
9. `TestNovelFormatJudgeHasSingleOwner` —— 源码级接线：旧判据 `hasTxtExt` 彻底消失、三个消费点都过
   `isNovelTextFile`、取正文都过 `readNovelTextFile`（**只用代码行判，注释行不算**）。

**反向验证 9/9 全红**（`scratch/reverse_verify_novel_formats.ps1`，每处都要求「命中恰好 1 次 → 门跑出
`--- FAIL:` → 恢复后字节与备份一致」；编译错不计入"变红"）：

| 改坏什么 | 哪条门红了 |
| --- | --- |
| N1 把 `.docx` 从支持列表去掉 | 识别 / 章节册 + 章号 / HTTP 三面（3 条） |
| N2 `.docx` 不再合并同段多个 run | docx 抽取（章头被切断） |
| N3 `.epub` 忽略 spine 顺序 | epub spine 顺序 |
| N4 `.docx` 不解码、直接回 zip 字节 | docx 抽取 + HTTP 三面 |
| N5 书卡字数回到字节估算 | HTTP 三面（字数断言） |
| N6 章节册判据退回只认 `.md/.txt` | 章节册 + 判据单一出处 |
| N7 「全本」退回取第一个条目 | 全本跳过非正文 |
| N8 不支持的格式清单清空 | 点名文案 |
| N9 取正文退回裸 `os.ReadFile` | HTTP 三面 + 判据单一出处 |

## 五、边界（如实说）

* **不读的格式**（真做要新依赖，本轮不做）：`.pdf`（要版式解析器）、`.doc`/`.rtf`（老式二进制/控制字）、
  `.wps`、`.mobi`/`.azw3`（Kindle 私有容器）、`.html`/`.htm`（网上扒来的 HTML 几乎都不是严格 XML）。
  它们是**永久边界**，但每次导入都会**点名**（见 `novelUnsupportedReport`）。
* **`.epub` 只用合成夹具验过** —— 盘上没有真 epub 样本，所以我不给"真 epub 一定读得对"的背书；
  读不了时会**带着是哪个文档**报错，不会悄悄少读一章（少读才是本仓最怕的形态）。
* **书卡字数**对容器格式现在是**真解一遍再数**（之前 40135 估 vs 17577 真）；纯文本仍是 3 字节/汉字估算。
  解不开的容器退回估算 —— 列表页不能因为一个坏文件整页失败（该文件在「一键创作」链上会被点名）。
* **不需要重拷文件**：改动全在读盘路径上，重启 app 后打开小说库即生效。
* 老门的夹具更新一处：`novel_detail_chapters_test.go` 原来用 `全本.epub` 当"平台不读的电子书"，
  现在 epub 读得出来 ⇒ 换成 `全本.pdf`（语义不变：文件在、但读不出正文），并在注释里写明原因。
