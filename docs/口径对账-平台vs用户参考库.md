# 平台口径对账表：ManJuX vs 用户的参考库

> **为什么要这张表**（用户 2026-09-28：「调整优化那就说明以前的存在问题，现在就是干升级优化调整的啊」）
>
> 平台里成百条"口径"是过去十几天里一条条拍下来的 —— 有的是抄用户文件的，有的是抄官方文档的，
> **有的就是我自己拍的**。它们混在一起，谁也没有系统地对过一次账。于是每次用户指出问题，
> 我都在"发现一处、改一处"，而不是**主动把整层口径对一遍**。
>
> 这张表的用法：**每次动手改口径之前先查这里**（有没有出处、出处是哪份文件的哪一句）；
> 每次新增口径也**必须在这里补一行**，写明它是"来自用户文件 / 来自官方 / 我的判断（需用户确认）"。
> 三分类的意义：前两类是**执行**，第三类是**待确认** —— 混起来的后果就是"闭门造车"。

## 四、维护本表的纪律

1. **新增任何口径**（提示词里的一句硬要求、代码里的一个常量）**都必须在本表补一行**，
   并写清出处类别：`用户文件（哪份哪句）` / `官方（哪份哪个 §）` / `我的判断（待确认）`。
2. **改口径先查本表**：如果那一行已经有"用户文件"出处，就按用户文件改；如果只有"我的判断"，
   改之前先去找出处（用户库 → 官方仓库 → 公开资料），找不到再按我的判断改并在此说明。
3. **第三类的行数是体检指标**：它越长，说明平台里"我自己拍的东西"越多 —— 那就是用户说的
   "闭门造车"的信号，应当主动去补出处或请用户拍板，而不是让它继续堆。
