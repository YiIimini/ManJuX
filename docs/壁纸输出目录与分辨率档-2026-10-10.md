# 壁纸输出目录可选 + 分辨率档更多（2026-10-10）

用户原话：「**壁纸需用户选择生成后输出的目录，壁纸分辨率参数多增加些**」。

这一轮把壁纸库从"图固定落在平台数据目录里、只有两档分辨率"改成"**图落在我选的目录里、
分辨率想怎么挑都行**"。

---

## 一、输出目录：每个分类一个目录，用户可改

### 设计（每条都有门）

| 决定 | 为什么 |
|---|---|
| **每个分类各一个目录**（`mobile` / `desktop`），默认仍是 `<DataDir>/wallpapers/<kind>` | 用户盘上现成的壁纸目录是**平铺**的（`data\壁纸\` 那种），按分类给目录可以直接指过去用，不用先把文件搬进子目录 |
| 配置落在 **`<DataDir>/wallpapers/settings.json`** | 配置**固定留在数据根下** ⇒ 换库位置不会把它弄丢（也不会出现"配置跟着库跑丢了"） |
| **唯一出处** `wallpaperDirOf(kind)` | 清单、生成、删除、只读图、设为壁纸全走它 —— 不给"清单读 A 处、生成写 B 处"留门（源码级门咬住：`listWallpapers` **只收分类**、不接目录参数） |
| **改目录只改"以后往哪写"** | **不搬动已有文件**：老目录里的图留在原地、新清单是空的 —— 这句话在界面上如实写出来（否则用户会以为"我的图没了"） |
| **守卫跟着目录走** | 只读图/删除/设为壁纸只认"该文件在**这个分类当前的输出目录**里"；换目录后老图不再属于这一类 ⇒ 403 且**说清是"改过输出目录"造成的**（可逆：恢复默认又能读） |
| **能确定性做到的当场做** | 路径规整 → 拒绝**驱动器根**与**系统目录** → 建目录 → **写一个临时文件探可写** → 才落盘；设不上就报错，**设置保持原样**（不许把库指到一个用不了的目录） |
| 空串 = 恢复默认 | 界面上「恢复默认」就是它；返回里如实写"此前生成在别处的图不会被搬动" |

### 接口

- `GET /api/wallpapers` 现在多带 `dirs`：`{mobile:{path,default,custom,exists}, desktop:{…}}`（只 `Stat`，**不建目录** —— GET 不许有副作用）
- `POST /api/wallpapers/dir` `{kind, dir}` → 改目录（`dir` 为空串 = 恢复默认）；被拒时 400 **带为什么**

### 界面

参数区多一行「输出目录」：显示当前目录（气泡里写清"改目录不会搬动老图"）+「改目录」+「恢复默认」。
「改目录」优先用 **Wails 的原生目录选择器**（`window.runtime.OpenDirectoryDialog`，桌面模式有），
浏览器里没有就回退到**手输绝对路径**（Wails 的 runtime 只在桌面端注入，这条回退是必须的）。

## 二、分辨率：档位变多 + 自定义 + 按本机屏幕

### 档位（真机取证过的硬口径：**每条边 16 对齐**、**夹在 [512,2048]**）

| 分类 | 档位 |
|---|---|
| 桌面（横版） | **2048×1152**（16:9 最大档）· **1920×1088**（16:9 主流）· **1920×1200**（16:10）· **2048×864**（21:9 带鱼屏）· **1600×896** · **1280×720**（试稿） |
| 手机（竖版） | **1088×1920**（9:16 主流）· **1200×1920**（5:8 大屏）· **896×1600** · **768×1360** · **720×1280**（试稿） |

**为什么没有 2K/4K 档**：平台图像侧单边上限是 **2048**（引擎硬约束），2560/3440/3840/7680 全都超过它 ——
所以这一栏**不可能**列出"和 3440 带鱼屏一样大"的档。要这个观感就用下一条。

### 「按本机屏幕」

`GetSystemMetrics(SM_CXSCREEN/SM_CYSCREEN)` 读主屏分辨率，再**保持屏幕比例**压到上限、两边对齐 16：

**真机实测**（`TestZZProbeWallpaperDesktopLive`，`MANJUX_LIVE_PROBE=1`）：

```
本机屏幕（GetSystemMetrics）：3440×1440；「按本机屏幕」会出 2048×848 ——
  本机屏幕 3440×1440；平台出图单边上限 2048 ⇒ 按屏幕比例出 2048×848
```

### 自定义尺寸 + 如实说"实际出多少"

下拉里加「自定义…（自己填宽高）」，两个输入框按 16 对齐步进。
**界面不许自己算实际尺寸**：`GET /api/wallpapers/size?kind=&w=&h=` 回来问 Go 那一处口径
（`normWallpaperSize` + `wallpaperSizeNote`），返回 `{w,h,note}`；note 形如
「你填的是 3440×1440，按平台口径（单边上限 2048）**实际出 2048×1440**」。
只有"实际 ≠ 所选"时才在界面上显示 —— 免得整屏废话。

另外 `GET /api/wallpapers` 带回 `limits{max_side,min_side,align}` 与 `screen{w,h,fit_w,fit_h,note}`，
界面直接显示硬口径，用户改词/改尺寸时看得见规矩。

## 三、门与反向验证

## 五、边界（如实说）

- **改目录不搬旧图**（设计如此、界面写明、门钉住）；想搬得用户自己搬。
- 输出目录可以是**任意可写目录**（含 `D:\壁纸` 这类自建目录），但拒绝**驱动器根**与**系统目录**（防手滑）；
- **单边上限 2048** 是图像侧的硬约束 ⇒ 没有 2K/4K 档；3440×1440 这类带鱼屏只能按比例出 2048×848；
- **"按本机屏幕"读的是主屏的物理像素**（多显示器只取主屏，与上一轮"没有多显示器分别设壁纸"同一条边界）；
- 手机/桌面**各自记忆**自己的输出目录与档位偏好；自定义宽高在换分类时会重置成新类的第一档
  （否则会出现"竖版尺寸出横版图"）；
- 没做：目录树里"选一个子目录"的浏览、把旧目录的图一并列出来、批量搬移/整理。
