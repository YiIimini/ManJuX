# 小说转剧本：渲染效果为什么差 —— 真机取证与根因（2026-10-10）

> 用户：「那你帮我分析小说转剧本为什么渲染的效果如此之差」。
> 本文只写**在这台机器上量到的东西**：文件原文、日志原文、平台自己的 VLM 读图原话。
> 结论先给：**不是出图模型不行，是"风格"这一环在快路径上整条丢了**，然后被 LLM 自编成
> 与本书风格卡**正相反**的一句话，进而把出图/出片提示词全带成「3D CG 渲染」。

## 二、证据链（每一环都量过）

### 环 1｜小说侧写得**很清楚**，而且专门写了排除句

`立项.json` 的 `art_style`（`设定集/视觉风格卡-中式梦幻磅礴.md` 里逐字重复）写着：

```
… a semi-realistic hand-painted finish with visible brushwork and fine film grain; …
This is eastern xianxia fantasy, NOT neon cyberpunk, NOT a western castle,
NOT flat anime cel-shading, NOT a plastic 3D render, NOT a child's cartoon.
```

风格卡还专门解释了为什么要有这一串 NOT：**默认后端 qwen2.1 是 cfg=1.0、负面提示词权重为零**，
所以"禁区"必须写成正向排除句 —— 也就是说这串 NOT **是护栏本身，不是装饰**。

### 环 2｜平台在导入时**确实扫到了**它（日志原文）

```
2026/10/10 00:13:45 [事件][][novel][info] 🎨 已从这本书里解析到视频风格字段(立项.json 的 art_style):
    DREAMLIKE CHINESE ARCHITECTURAL FANTASY, cinematic vertical poster look: colossa…
2026/10/10 00:13:45 [事件][][novel][info] 🎨 另发现风格卡 设定集/视觉风格卡-中式梦幻磅礴.md(4333 字):
    本书的画面口径以它为准
```

### 环 3｜可是它**没有进到任何一集**：48 集的「全局风格:」全是空行

```
第01集·钥匙没坏: len=0 值=[]
第02集·石阶下的影子: len=0 值=[]
…（抽到第06集，全 0；48 集的 source.txt 建/改时间集中在 00:13:45–00:14:06）
```

**根因（代码级）**：`internal/server/novels_split.go` 里三档风格裁决原来只写在
**"分层拆解"分支的 `if ci == 0`** 里（LLM 拆集那条路），而
**「一章一档」快路径（第 266 行）在它之前就 `return` 了** ——
快路径建集时 `createSeg` 读到的 `globalStyle` 恒为空。真机那本书正好是一章一档（48 章 → 48 集），
于是一次就写出 48 个空行。

### 环 4｜空行 ⇒ 剧本会话**自己编**风格，而且编反了

平台的剧本提示词（`internal/director/prompts/sysOutputFull__OUTPUT.md`）只规定：
「源文里若含【全局风格】**逐字照抄**，不许另编」——**空的时候没人管**。
于是 `plan/plan.json` 的 `style` 成了：

```
中式梦幻磅礴的半写实绘画风，3D CG 质感：眉骨有阴影、眼尾有一线光、皮肤带暗部；…
```

注意两个事实：① 它把**互斥的两件事并列**（"半写实绘画"与"3D CG"）；
② 它**丢掉了**风格卡里那串 NOT（尤其 `NOT a plastic 3D render`）。

### 环 5｜平台按"3D CG"展开 ⇒ 出图/出片提示词全是 3D 渲染语言

`internal/pipeline/prompts.go:1452`：

```go
medium3D := strings.Contains(s, "3d render") || strings.Contains(s, "3d cg")
```

命中后（`:1501`）往提示词里写：

```
next-generation 3D CG character render, realistic skin shading with visible skin texture and
natural facial highlights, real materials with visible craft, a matte-to-satin finish
```

出片侧同理：`plan/shots[0].h3_prompt` 的风格句是
`Cinematic, 3D CG, Chinese guofeng semi-realistic painterly rendering; …`
—— 官方口径里**风格就是这一句开头的并列形容**，而"3D CG"排在第二。

### 环 6｜平台自己的 VLM 读图原话（`deepseek-flash`，max_tokens=8192）

拿**这一集刚出的定妆照**（`char_shenyan.png`）跑平台自己的评分表，原文：

```
1) 头连发髻约占画面高度1/3；裁到腰胯，底边露双拳。背景纯白，无道具文字。
2) 能分辨：眼细长、眉浓直、唇偏薄；脸宽约190px（图宽约768px计）。
3) 半写实/3D渲染感；皮肤蜡感、磨皮重；布料有粗织纹理；柔光有弱塑形。
4) 双拳指节偏糊、结构软。
5.1 面部磨皮和蜡感最重，缺毛孔皱纹，像3D塑料娃娃，不像真人定妆。
5.2 白底柔光太像证件照，缺电影级环境光和面部塑形，氛围弱。
5.3 表情空、眼神无戏，发型服装过于干净，角色性格和故事感不足。
```

场景图（`scene_zhifa_tang.png`）同样被判：

```
2) 门外台阶直通云海，空间悬空；左侧窗与右墙不对称。
3) 暗部死黑，光束和天空过曝，地面发灰。
5) 最难看三点：门外云海悬空穿帮；前景散石板杂乱；暗部死黑、过曝，材质细节少。
```

**"像 3D 塑料娃娃"就是环 4→5 那句话的直接后果**——而书的风格卡写的正是 `NOT a plastic 3D render`。

### 环 7｜定妆照提示词本身太长、自相打架（第二条根因）

`asset_map.json` 里 `char:char_shenyan` 的 `image_prompt` **6789 字符**，里面：
同一件"胸像/头占 1/4"的取景要求**写了两遍**（`BUST PORTRAIT (…)` 与 `FRAMING (mandatory):`），
外加 `SCALE (mandatory)`、`FACE ID (final check, mandatory)`、`HAIR EXACTLY AS BRIEFED`、
`CAST DISTINCTNESS`（**6 段被截断到 `deep-blac…` / `diss…` 的别人外形摘要**）与 `NOT: … ×3`，
还有一句空列表残句：`Do NOT depict any of these other characters: exactly ONE person appears in the frame — .`

结果（VLM 原话）：**要求"胸像、裁到胸、头占 1/4"，实际"裁到腰胯、露双拳、头占 1/3"**；
而脸只占 768px 宽里的约 190px ⇒ **它作为视频参考图，天生就是糊的**。

### 环 8（系统级）｜质检这一层的余量只剩 1.5 倍

同一张图、同一份 5 条评分表，改 `max_tokens` 实测：

| max_tokens | finish | 思考 token | 正文 |
|---|---|---|---|
| 2048 | length | 2048 | **0 字** |
| 4000 | length | 4000 | **0 字** |
| 8192 | stop | 5347 | 257 字 |

平台 `ChatVision` 用的就是 8192（`internal/llm/client.go:345`），拿到空正文会报错（`:407`，
**不是静默通过**）。但换个更长的评分表或一次发多张图，就会整条"判不了"。

## 三、本轮改了什么（一处收口 + 门）

**改**：`internal/server/novels_split.go` —— 把三档风格裁决（用户选 > 立项 `art_style` > 补缺沿用）
**提到两条件路之前**，分层拆解那一支只剩"两档都没有才用 LLM 首段自生成"的兜底。
⇒ **一章一档快路径建出来的每一集，都会带上「全局风格:<串>」**，并当场播报是哪一档。

**门**：`internal/server/novels_fastpath_style_test.go`（`TestFastPathKeepsGlobalStyle`）
造一本 9 章的「一章一档」书 → 走快路径 → 读**建出来的** `source.txt` →
断言「全局风格:」那一行**逐字等于**导入时定下的串。判据是**行为**，不是"代码里有没有那句话"。

**反向验证**（`scratch/reverse_verify_fastpath_style.ps1`）：**2/2 全红**
- N1 把快路径前的风格裁决关掉（`if false && …`）⇒ 门红；
- N2 把夹具压到 3 章（走不到快路径）⇒ 门红（证明夹具真的在快路径上，不是空过）。

## 四、还没修的（按影响排序，都是显式待办）

1. **存量 48 集仍是空行** —— 本轮修的是"新建集"。已生成的那 48 集要生效有两条路：
   ① 逐集在项目参数里勾一次风格（会把「全局风格:」行同步过去）+ 重跑「剧本分镜」；
   ② 我加一个"按小说侧回填这一批集 source"的入口（一次性、幂等）。**②才是对的做法**，下一轮做。
2. **风格串互斥（"半写实绘画" + "3D CG"）** —— 平台已有 `StyleMediumConflicts` 判据，但它只在
   "用户勾预设"时判，**对 LLM 自己写出的 `plan.Style` 不判**。要接到 `ValidatePlan`（渲染入口）上，
   并明确"以小说侧 `art_style` 为准"这一档。
3. **定妆照提示词瘦身**：去掉重复的取景块、去掉被截断的 `CAST DISTINCTNESS` 摘要与空列表残句，
   取景口径只留一处。注意 `CAST DISTINCTNESS` 是防**撞脸**的，不能整块删，只能把"截断的六段描述"
   换成"结论式一句"。
4. **VLM 预算**：8192 → 16384，并在"正文空"时自动加预算重试一次（现在直接报错）。
5. **取景/分辨率二选一**：要么把定妆照的取景真做成胸像（头占 1/4），要么提高出图尺寸；
   否则"脸只有 190px"这条会一直让参考图发糊。
