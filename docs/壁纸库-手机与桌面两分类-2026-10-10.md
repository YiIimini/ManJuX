# 壁纸库：手机/桌面两分类 + 描述→LLM 写词→可编辑→文生图（2026-10-10）

用户原话：「新增"壁纸库"，分类"手机壁纸"和"桌面壁纸"，新增用户描述然后结合LLM生成提示词后编辑进行文生图
（分辨率配置、是否同时生成移动端和桌面端等相关参数配置）」。

链路：**用户描述 → 平台 LLM 写成一段英文正向提示词 → 用户可编辑 → 文生图（本机 ComfyUI）→ 落盘进壁纸库**。

---

## 一、提示词必须由平台收口（这一条是"壁纸能不能用"的成败）

平台自己的图像侧口径（`internal/pipeline/artstyle.go` 顶部）：出图只吃英文，**汉字注解会被模型
当成"要画的字"照抄**；2026-10-10 封面那一轮又把另一半钉死了 —— 出图侧 **cfg=1.0：否定词不生效，
且提示词里提到的名词会被当成要画的东西**（真机证据：词里写着 no other text，画面里照样多出一行乱码伪字）。

壁纸最怕的正是这个：**画面上出现乱码字**，还天天挂在桌面上。所以 `internal/server/wallpapers.go` 收口三条：

1. **整段不许有汉字**（用户那句中文描述**不进**提示词 —— 翻译是 LLM 的活）；
2. **不许出现文字类名词**（text / lettering / title / caption / subtitle / watermark / logo / signature /
   sign / number）：一个都不提，模型就没理由画字；
3. **不许写否定句**（no / without / avoid / free of）：要"没有"什么，就只描述**要**的画面。

收口落在 `cleanWallpaperPrompt`：剥围栏/前缀 → 压成一行 → `stripCJK` 清汉字 →
**逐短语**摘掉含被禁词的短语（提示词是逗号分隔的短语清单，摘一个不会打断句子）→ 再过 `wallpaperPromptUsable`
（≥40 字符 / ≥5 个英文词 / 无汉字 / 无被禁词）。改过什么写进 `Note`，一路带到日志与界面。

**兜底**（`wallpaperSeedPrompt`）：拿不到 LLM 时用**平台自己的通用构图句**（手机竖版 / 桌面横版各一条），
**不含用户描述**，并**如实标注**「LLM 没用上 / 这是平台通用构图词，不含你的描述」——
不许把通用词说成是照用户描述写的。

## 二、分类与分辨率

| 分类 | 目录 | 预设（16 对齐、[512,2048] 内） |
| --- | --- | --- |
| 手机壁纸 `mobile` | `<数据根>/wallpapers/mobile/` | 1088×1920（9:16 主流）、896×1600（小屏） |
| 桌面壁纸 `desktop` | `<数据根>/wallpapers/desktop/` | 1920×1088（16:9 主流）、1600×896（笔记本） |

自定义分辨率经 `normWallpaperSize`：夹到 [512,2048] 并**对齐 16**（图像侧硬要求）；
不给就回落到该分类第一档。**「同时生成手机 + 桌面」**＝两端各出一套：**同一条词，各按自己的画幅**
（这是这个开关的全部意义，门里逐张断言每一端用的画幅）。

## 三、接口

```
GET    /api/wallpapers               两分类清单（从盘上扫）+ 尺寸预设 + llm_ready + 提示词口径 hint
GET    /api/wallpapers/image?path=   只读输出壁纸图（路径必须在壁纸库内，否则 403）
POST   /api/wallpapers/prompt        {desc,kind} → 「AI 写词」（**强制走 LLM**；拿不到就通用词 + 如实说明，200）
POST   /api/wallpapers/generate      {desc,prompt,kind,width,height,seed,count,both} → 出图并落盘
DELETE /api/wallpapers/item?file=    删壁纸（图 + 伴随 .json）
```

**存储**：`<数据根>/wallpapers/<kind>/wp-<kind>-<时间>-<seed>.png` + 同名 `.json` 伴随文件
（正向词、来源、尺寸、seed、时间）。**清单从盘上算，不维护索引文件** —— 少一处会失同步的状态。

**失败纪律**（与封面那轮同一条教训）：**引擎检查在造目录之前** —— 拿不到引擎就 503 如实报错，
**一个目录都不建、一张图都不落**（否则盘上留下空目录，看起来像"生过但失败了"）。
出图失败同样不留半成品。伴随文件写失败**不致命但不静默**（`s.opLog("⚠ …")`，审计门
`TestNoSwallowedPersistenceErrors` 会咬"流程照跑、日志照报成功"）。

## 四、界面

新视图 `frontend/src/views/WallpapersView.vue`（菜单「壁纸库」，位于「作品库」与「ComfyUI」之间）：

* 顶栏：**手机壁纸 / 桌面壁纸** 两分类切换 + 本类张数/总数 + 提示词口径提示 + 刷新；
* 左栏三步：① 描述 + **「AI 写词」**（平台 LLM 没配置时置灰并在气泡里说明）② 提示词（**可编辑**）
  ③ 参数：分辨率下拉、张数 1–4、seed、**同时生成手机 + 桌面**、生成按钮；
* 右栏：当前分类的网格（悬浮显示尺寸/seed/正向词，点图放大用全站同一套预览，可删除）。

## 六、边界（如实说）

1. **没跑真机出图**：ComfyUI 当前不在跑。门的出图路径用的是**假引擎**（真跑 HTTP、真落盘、真校验画幅与伴随文件），
   **"Qwen-Image 在这几个画幅上的实际观感/耗时"没量**。
2. **提示词里的"不要出现文字"只管 LLM 那一段**：用户手改的词平台**不拦**（只清汉字这件事发生在 LLM 收口那一步）。
   要拦用户手写就得再加一道"生成前校验"，本轮没做。
3. **壁纸没有"重新生成"入口**：不满意就再点一次生成（同 seed 可复现那一张）。批量管理（多选删除/重命名）也没做。
4. **16 对齐导致 1080×1920 变成 1088×1920**：1080 不是 16 的倍数，图像侧要求对齐，故取最接近的 1088
   （标签里如实写着实际像素）。
