# 定妆照朝向 · 实测与处置（2026-09-27）

> **一句话**：定妆照的"正面"约束**压不住模型**（措辞改了也没用），而它的种子是按资产名
> 锚定的 —— 一次采样偏成四分之三侧脸，这个角色就会**一直是侧脸**。处置不是继续堆提示词，
> 是**测出来 + 换种子重出**。

---

## 1. 问题：上一轮的修复没有生效

上一轮（`fc12ba7`）在定妆照提示词里把正面约束写强了：

```
FRAMING (mandatory): a front-facing chest-up portrait, shot STRAIGHT-ON from the front —
the face looks directly into the camera, both eyes visible at the same size and symmetric,
the head is upright and squared to the lens with the nose and chin pointing at the camera,
the WHOLE head is inside the picture with clear empty space above the hair…
```

真机重出（本机 ComfyUI + Qwen-Image-2.1，768×1344）后的**实际产物**：

| 角色 | 朝向 | 头顶完整 | 画风 | 取景 |
|---|---|---|---|---|
| 沈砚 | **四分之三侧**（鼻尖偏右、只看得全一只眼） | ✅ | ✅ 国风电影级 photoreal | ✅ 胸像 + 留白 |
| 苏晚 | 正面 | ✅ | ✅ | ✅ |
| 阿婆 | 正面 | ✅ | ✅ | ✅ |

也就是说：**取景（头顶不裁）与画风这两条修好了，正面这条没有。**

## 2. 根因实验：换措辞没用，换种子才有用

### 2.1 决定性的第一步：**定妆照是确定性产物**

同一份提示词、同一颗种子，重跑资产阶段两次，产物**逐像素相同**（framedmd5 一致，
文件大小也一致 1751109 字节）。因为种子是**按资产名锚定**的：

```go
seed := nameSeed(kind, name)   // "同名必同图" —— 跨集一致性的保险
```

**推论**：一旦某个角色的那次采样偏成侧脸，它**不会自愈** —— 重跑资产阶段、重启平台、
换项目再建（只要角色名一样）都是同一张侧脸。这不是"偶尔抽到坏的"，是"这个角色就长这样了"。

### 2.2 A/B：把正面约束**前置**（variance 实验）

从 ComfyUI history 里取出那次出图的**完整工作流图**（即平台真正提交的那份），只改两处重放：
`variant A` = 原提示词；`variant B` = 在提示词**最前面**加一句更硬的构图声明
（"Frontal symmetrical chest-up portrait composition: the person faces the camera directly,
head upright and squared to the lens, both eyes at the same size and level."）。固定 4 颗种子
（101/202/303/404），A、B 各 4 张：

| 种子 | A（原措辞） | B（前置强调） |
|---|---|---|
| 101 | 正面 | 正面 |
| 202 | 正面 | 正面 |
| 303 | 正面 | 正面 |
| 404 | **四分之三侧** | **四分之三侧** |

**结论：一模一样。** 前置、加重、重复一遍"必须正面"都不改变结果 —— 朝向由**那次采样**
决定，不由措辞决定。同时这也给出了失手率的一阶估计：**4 个样本里 1 个偏**（约 1/4）。

> 复现方式（本机）：把 `A_*.png` / `B_*.png` 逐张 `ffmpeg -f framemd5` 比对，再目视分类朝向；
> 八张图的像素哈希两两不同（种子确实生效了），而同变体内不同种子的图**内容各不相同**。
>
> 踩过的坑：第一次重放时把种子写到了节点对象的顶层（`nodes['7'].seed`）而不是
> `nodes['7']['inputs']['seed']` —— ComfyUI 照收不误，四个"不同种子"其实全是原种子，
> 四张图逐像素相同。**验证实验本身也要先证明"自变量真的变了"。**

## 3. 处置：测出来 + 换种子重出

### 3.1 把「朝向」并进已有的定妆照自检

定妆照出图后本来就有一次**视觉模型自检**（`internal/qc/proportion.go`，量化三庭/眼距/头身比）。
朝向是**构图项**而不是比例项，但它与比例项吃的是同一张图、同一次视觉调用 —— 多调一次模型
只为问一句"是不是正脸"不划算，所以并进同一份检查表：

- 新增一项 `face_direction`（中文名「朝向」），期望口径写明"正面胸像"；
- 系统提示词补一句：**四分之三侧/侧脸 = 明显偏离（clear）**，免得模型拿自己的审美判；
- 判据落在 `qc.FacingOf` / `qc.FacingNeedsRegen`（纯函数，可穷举）：
  **"没量到"（没做/失败/看不见）与"量到且是正面"严格分开** —— 前者绝不当成合格，
  也绝不触发重出（不能拿"没验过"当"不合格"去烧 GPU）。

### 3.2 未过就换种子重出（资产阶段）

`pipeline.stages_assets.go` 的 `regenerateOnBadFacing`：

- 只在量到 **clear** 时才重出（`slight` 仍走原来的告警通道，由用户决定）；
- 重出的种子 = `nameSeed(kind, name) + attempt*101` —— **"同名必同图"在重出这条路上被有意打破**，
  同种子重出等于画出同一张图，白烧一次 GPU；
- 最多 **2 次**（`maxFacingRegen`）：单次失手约 1/4，连失三次约 1/64，再加只是拿 GPU 换概率；
- 每次重出都独立播报，用完次数仍不过就**如实告警收手**（保留最后一张，提示手动「重新生成」）；
- 重出写的是**同一个文件**（路径由资产 id 派生），所以重出后刷新内容指纹。

「单资产重新生成」那条路**不自动重出**：那本来就是用户手动换一张（随机种子），
自动连抽两三次会把一次点击变成"不知道在等什么"的静默等待；这条路径改成**如实告知**
（"这张不是正面，再点一次通常就好"）。

### 3.3 真机验收（本机实测，逐条可复现）

把库里与项目里的沈砚定妆照删掉（避开库复用），只跑 `only=["char:char_shenyan"]` 的资产阶段：

```
11:10:55  Qwen-Image-2.1 生成:角色「沈砚」(768×1344)…
11:11:10  ✔ 已生成:角色「沈砚」(人)
11:11:48  ⚠ 比例自检发现 2 项明显偏离 …眼线位置…;朝向(实测:头部转向右侧，非正面)
11:11:48  ↻ 定妆照「沈砚」朝向自检未过(不是正面):换种子重出第 1/2 次…
11:12:26  ✔ 定妆照「沈砚」朝向已修正(第 1 次重出为正面)
```

产物目视复核：正面、两眼同大小对称、头顶完整带留白、胸像取景、国风电影级、
灰白粗布短打 + 旧汗巾搭肩 + 右前臂刀口 + 左手腕墨色纹路 —— 与外形锚表逐项一致。

## 4. 顺带修掉的一个静默降级：VLM 的 `max_tokens`

第一次真机验收时，重出后的第二次自检报了一句：

```
⚠ 定妆照「沈砚」比例自检失败(未判定,不当作通过):VLM 返回空内容(finish=length)
```

根因：`llm.ChatVision` 的 `max_tokens` 写死 **2048**，而 GLM 一类**思考型**视觉模型的推理
token 也计入 completion —— 推理把额度吃干净，正文一个字没出就 `finish=length`。
症状正是最坏的一种：自检被判成"未判定"，于是**朝向重出根本不触发**，而事件流里只有一句
无从下手的失败。上限提到 **8192**（`internal/llm/client.go`），失败才真的是失败。

## 5. 还没做的

- **失手率的精确估计**：现有样本只有 4（A/B 各 4，同种子的两遍一致）+ 真机 3 个角色，
  一阶估计约 1/4。要更准就得跑 20+ 张，但**处置不依赖这个数字**（重出上限 2 次足够）。
- **`views`（多视角转台图）本身也有同样的问题**：它是从定妆照派生的，主图正了、派生视角
  的质量就跟着正；但派生视角自己的"是否准确"只由**身份校验**（逐帧与定妆照一致，≥90 分）
  把关，没有朝向项 —— 而"四分之三侧"这类视角是**故意**生成的，不该套正面判据。**保持现状。**
- 若将来要"完全不靠视觉模型"也能保证正面：需要换采样器/加 LoRA 或在 latent 层约束，
  那是另一条技术路线（本机没有可依据的方案）。
