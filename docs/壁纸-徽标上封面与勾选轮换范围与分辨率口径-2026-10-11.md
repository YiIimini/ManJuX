## 1. 「系统壁纸」徽标：挪到缩略图封面上

**症状**：徽标原来与尺寸、按钮挤在同一行的 flex 里（`<div class="flex items-center gap-2 mt-1">`）。
窄卡片上它被挤成**一字一行**（中文逐字换行），看起来就像一条竖排的"系统壁纸"条贴在缩略图旁边 ——
用户截图里那个红框就是这个。

**修法**（`frontend/src/views/WallpapersView.vue`）：

* 缩略图包一层 `.wp-thumb { position: relative; }`，图还是那张图；
* `.wp-badge` 改成 **`position:absolute; top:6px; left:6px`** ⇒ 压在封面左上角，**脱离文档流**，
  再也不会被 flex 挤压换行；
* 尺寸与按钮那行恢复成"只有尺寸 + 按钮"，不再抢空间；
* 颜色仍走主题变量（`var(--mx-accent, #7aa2f7)` / `var(--mx-bg1, #0b0b0e)`），裸色会被 `theme_coverage` 门拦下。

**边界**：没有在真窗口量像素（本轮只做了源码级接线门 + vite 构建通过）；徽标文案与三态未变。

## 2. 分辨率：口径修正（对齐 32）+ 档位抬高

### 2.1 口径原来就说错了：platform 写 16，引擎是 32

真机取证（`cmd/imagecheck`，同一 prompt/seed，落盘像素用 System.Drawing 读回来）：

| 我提交 | 引擎实际落盘 | 说明 |
|---|---|---|
| 3440×1440 | **3424×1440** | 3440/32 = 107.5 ⇒ 向下取整 |
| 3840×2160 | **3840×2144** | 2160/32 = 67.5 |
| 1440×3120 | **1440×3104** | 3120/32 = 97.5 |
| 2560×1440 | 2560×1440 | 两侧都是 32 的倍数，原样 |

根因在图像侧：`internal/engine/comfyengine/imagegen.go` 顶部写着「画幅对齐 32(潜空间要求)」，
实现是 `snap32`（**向下**取整到 32）。而平台这一侧一直按 **16** 承诺 ⇒ 旧档位表里的
`1280×720`、`1200×1920`、`1920×1200`、`768×1360` 全都会**被引擎悄悄改掉**（→ 704 / 1184 / 1184 / 1344），
标签写的却是"好看的那个数"。本轮把 `wallpaperAlign` 改成 **32**，并按实测把每一档的标签都写成真实像素。

### 2.2 上限 2048 → 4096，另加一条像素预算

* 旧口径 `wallpaperMaxSide = 2048` ⇒ **不可能**有 2K/4K/带鱼屏原生档（用户抱怨的正是这个）。
* 新口径：单边 `4096`，**外加像素预算 `wallpaperMaxPixels = 850 万`** —— 依据是本轮实测跑过的最大一张
  （3840×2144 ≈ 824 万像素 / 129 秒）；超过预算**按比例缩**并把"为什么"写进说明（不是静默夹）。
* 超上限也不再"硬夹成方图"：先按比例缩进上限，再对齐、再套预算。

### 2.3 新档位（标签 = 真实像素；括号里是**真机实测耗时**）

桌面（9 档，第一档＝缺省档）：

```
2560×1440（2K 16:9 · 实测 42 秒）
3424×1440（21:9 带鱼屏 · 3440×1440 一类 · 实测 60 秒）   ← 用户那块屏的"原生"档
3840×2144（≈4K 16:9 · 实测 129 秒）
2048×1152 / 1920×1088 / 1920×1184 / 2048×864 / 1600×896 / 1280×704
```

手机（6 档）：

```
1088×1920 / 1216×1920 / 1440×3104（2K 竖屏手机 · 实测 60 秒） / 896×1600 / 768×1344 / 704×1280
```

「按本机屏幕」也跟着受益：真机 3440×1440 的屏幕现在出 **3424×1440**（原来只有 2048×848），
说明里逐字写着「本机屏幕 3440×1440 ⇒ 按平台口径（32 对齐、像素预算 850 万）出 3424×1440」。

**边界（如实）**：

* 4K 档只跑过**一次**（同一 prompt/seed，129 秒），**没做多 seed/多 prompt 的稳定性验证**；
  出图质量（有没有重复结构、细节够不够）**我没有看图的判据**，所以档位标签只写尺寸与耗时，不写"更好"。
* 像素预算 850 万是我按"实测跑过的最大值"定的阈值 —— 4096×4096（1678 万）**没有验证过**，正好被预算挡住。
* 引擎的 32 对齐是**向下**取整；要不要改成"向上取整"是图像侧的事（会影响定妆照/封面），本轮不动。

## 3. 轮换范围：只在自己喜欢的那几张里换

**原来**：幻灯片轮换用的是**桌面分类里的全部**图 —— 用户挑不出来。

**现在**（`internal/server/wallpaper_desktop.go`）：

* 状态多一个 `picks []string`（绝对路径，**空 = 全部**，兼容老行为）；
* 纯函数 `deskPicksFilter(all, picks)` 三态：空⇒全部 / 勾过的按清单顺序留下 / **勾过但已不在盘上的进 `missing`（如实点名，不静默）**；
* `deskSeqBuild` 只对**勾选出来的那批**排序列（顺序/随机都走它）；
* 新端点 **`POST /api/wallpapers/desktop/picks {files:[...]}`**：
  * 只收**桌面分类里且在盘上**的图 —— 越界 `403`、手机分类 `400`（"轮换只换桌面壁纸"）、
    盘上没有 `404`，**失败一个字节都不写状态**；
  * 同一张传两遍会去重；
  * **选择变了而轮换正在跑 ⇒ 立刻按新集合重排**（否则用户要等到下一轮才看见效果）；
  * 空数组 = 清空选择 = 回到"全部参与"。
* 状态响应加 `picks / picks_count / picks_missing / picks_note`，`note` 里也会写清"全部 N 张"或"只在你勾的 N 张里换"；
* 前端：缩略图**右上角勾选框**（压在封面上，与徽标同一套做法）、顶部「参与轮换 已选 N / 共 M 张」+
  「全选」「清空」+ 一句 `picks_note`；勾选即写后端。

**边界**：`picks` 存的是**绝对路径**（与状态里原有的 `file` 字段同一套写法）⇒ 改了输出目录之后，
老路径的勾选会以"已不在盘上"被点名，需要重新勾（不会静默丢失）。

## 6. 边界（一句话清单）

* 徽标只做了源码级接线 + 构建验证，**没在真窗口量像素**。
* 4K 档只跑过 1 次；**画面质量没有判据**，只播报实测耗时。
* 像素预算 850 万是"实测最大值"定的阈值，**1678 万那个量级没验过**（正好被挡住）。
* `picks` 用绝对路径 ⇒ 换输出目录后勾选需要重勾（会点名，不静默）。
* 引擎的 32 对齐是向下的，本轮只让**平台承诺的数字与它一致**，没去改引擎（那是图像侧，会牵动定妆照/封面）。
