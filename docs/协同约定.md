# 双会话协同约定（ManJuX 平台侧 ↔ ManJuNovel 技能侧）

> 背景：2026-09-26 两个会话同时改同一个仓库并各自 `git push`，出了这些事：
> ① 我用 `git add -A` 整合时，把另一个会话的**临时文件** `internal/server/e2e_v2_temp_test.go`
> 一起提交并推了上去；② 对方随后删掉它、又改了契约文档，工作区再次变脏；
> ③ 双方都在动 `internal/project/*` 附近，谁先提交谁就把对方的半成品卷进去。
> 用户裁定：**「你两不要推了，协同配合处理」**。

## 一、硬规矩（两边都适用）

1. **不推送**。改完只提交到本地或干脆留在工作区，等用户明确说"推"再推。
2. **禁止 `git add -A` / `git add .`**。只 `git add <显式路径>`，一个文件一个文件点。
   提交前必须 `git status --porcelain` 看一遍：**不属于自己这轮的改动，一律不提交、不还原**。
3. **一次只会话改一块**（见下面的分工表）。需要动对方那块的，先在
   `docs/协同约定.md` 末尾的「交接区」写一条（谁、要什么、为什么、什么时候要），
   不动手改。
4. **不还原/不清理对方的文件**。看到工作区里有自己没做的改动，就当作"对方正在进行中"，
   连删除都要走交接区。
5. 提交信息里写清**这一轮只动了哪些文件**；动了别人的文件必须在正文里点名并说明理由。
