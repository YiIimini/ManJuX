# 实测：H3 Ref2V 的参考图**从未进入条件** —— 根因是 autogrow 提交键写错（2026-09-27）

> **一句话**：`<Picture 1>` 不是"装饰品"，**是我们根本没把它送进去**。参考图槽位的提交键写成了
> 聚合数组 `ref_images=[节点引用…]`，而 ComfyUI 只认点号键 `ref_images.ref_image_0`；
> 前者被静默丢成空 dict，节点 `ref_items=0`，参考图一张都不进条件，且**不报错**。
> 改成点号键后同一套权重立刻生效 —— **不需要下未剪枝权重，也不必换 ComfyUI 版本**。
>
> 本文在 2026-09-27 傍晚按**实测+源码**重写。旧版把根因写成"剪枝 + int8 权重把参考分支削掉了"，
> 那个结论**是错的**（被本文第 5 节的两条反证推翻）。

---

## 1. 现象（可在盘上复核）

`ComfyUI/output/mjxverdict/` 里 6 段 22 帧对照片段，判据是全片解码帧序列 MD5（`ffmpeg -f framemd5`）：

| 运行 | 底模 / LoRA | 参考图 | 帧指纹 |
|---|---|---|---|
| A | Singularity ref2va int8 + turbo | 年轻男子 | `908A7ED455190C2D30C35A45BEDC4404` |
| B | 同上 | **老妇** | `908A7ED455190C2D30C35A45BEDC4404` |
| C | 官方 ref2va int8 convrot + turbo | 年轻男子 | `C0D8E3C6F79BE82BB1565112738A197E` |
| D | 同上 | **老妇** | `C0D8E3C6F79BE82BB1565112738A197E` |
| E | 官方 ref2va int8 convrot，不挂 LoRA | 年轻男子 | `15D8DDDEA258CF80FF87FD0A84E7AF3F` |
| F | 同上 | **老妇** | `15D8DDDEA258CF80FF87FD0A84E7AF3F` |

结论仍然成立：**换参考图完全不影响成片**（三对全等）；不同底模之间确实不同（模型本身在起作用）。

## 2. 定位：三层探针，看参考图死在哪一步

临时给 ComfyUI 源码打了三处打印（节点 / `extra_conds` / DiT `forward`，见第 6 节配方），
用一张"只跑 conditioning、不采样"的最小图（CLIPLoader + 两个 VAELoader + LoadImage + 条件节点 + PreviewAny）
逐一对照提交形态：

| 提交形态 | 节点实际收到 | `ref_items` / `ref_blocks` | conditioning | 结果 |
|---|---|---|---|---|
| 聚合数组 `ref_images=[["10",0]]` | 空 dict | 0 / 0 | 无 `minimax_refs`，`cross_attn=77962ff3bf9868a0` | 静默无效 |
| 嵌套 dict `{ref_image_0:[…]}` | 空 dict | 0 / 0 | 同上（**与参考图无关，恒等**） | 静默无效 |
| 扁平键 `ref_image_0` | —— | —— | —— | 报 `unexpected keyword argument 'ref_image_0'` |
| **点号键 `ref_images.ref_image_0`** | `{ref_image_0: tensor}` | **1 / 1** | 出现 `minimax_refs`，`cross_attn=a3283dca…`（换图变 `b36fdcfc…`） | **生效** |

点号键下再往下一层看：`[MJXDBG forward] seq_len=9200 layout_refs=[(1062, 2070, 'ref_img')] payload_refs=1
cond_rows=(1008, 96)` —— 参考图占了 1008 行 packed 序列，视频行的 RoPE 时间坐标因此整体后移。
**这也解释了为什么"参考图没生效"必然等价于"根本没送到"**：只要 refs 进了 layout，位置编码就会变，
逐帧指纹不可能保持相同。

## 3. 根因（ComfyUI 0.37.4 源码）

`comfy_api/latest/_io.py` 的 autogrow（动态槽位）解析：

- `_expand_schema_for_dynamic`：`expected_id = finalize_prefix(["ref_images"], "ref_image_0")`
  → `"ref_images.ref_image_0"`（`finalize_prefix` 用 `.` join），**只有这个名字出现在节点输入里**，
  该槽位才会被登记成真实输入（`_io.py:1199-1211`）；
- `build_nested_inputs`：再按 `.` 把它还原成 `{ref_images: {ref_image_0: tensor}}` 交给节点（`_io.py:1942-1974`）；
- 若一个槽位都没提交，走"所有 optional 都没值"分支：`dynamic_paths_default_value = empty_dict`
  （`_io.py:1213-1216`），于是 `ref_images` 被填成 `{}` —— 节点 `(ref_images or {}).values()` 得到空，
  **既不报错也不生效**。

我们一直提交的是聚合数组（`engine.go:701`、`maskgraph.go:189`，且旧注释明确写着"聚合键 …(不是 ref_image_N)"），
所以从 H3 ref2va 上线那天起，参考图链路就没通过。

## 4. 修复

- 新增 `internal/engine/comfyengine/autogrow.go`：`autogrowKey(聚合键, 模板名, i)`，注释里写清依据与失效机理；
- `engine.go`：`ref_images` / `ref_audios` 两个槽位改走它；
- `maskgraph.go`：局部重绘喂裁剪主体的参考槽位改走它；
- 新增 `autogrow_contract_test.go`：锁住"必须是点号键、不得出现聚合键本身、槽位必须指向图里真实存在的节点"；
  `mask_audio_contract_test.go` 的断言同步改。

## 5. 被推翻的两个旧假设

1. **"本机四个 H3 底模都是剪枝 + int8 转换版，参考分支被削掉了"** —— 不成立。
   同一批权重、同一个 `MiniMax_H3_ref2va_pruned_int8_convrot`，只把提交键改成点号键，
   参考图立刻生效（第 2 节表最后一行）。**不需要下 20–40GB 未剪枝权重。**
2. **"ComfyUI 版本与这批权重不匹配"** —— 不成立。`v0.36.0 → v0.37.4` 之间
   `comfy/ldm/minimax/**`、`comfy/text_encoders/minimax.py`、`nodes_minimax_h3.py` 没有任何 ref 相关改动
   （只有无关的 ming-image 提交），换版本治不了这个病。

顺带纠正一条旧记录的措辞：条件缓存 `.pt` 两次内容不同**不能**证明"图被编码进去了" ——
实测里不同参考图产出的 `cross_attn` 是两个完全相同的常量（`77962ff3…`），
`.pt` 的差异只能来自缓存键或随包落盘的其它字段。

## 7. 剩下的真问题（顺序变了）

参考图既然通了，旧结论的第 5 节要反过来读：

1. **已渲的成片不会自己变** —— 之前所有镜头都是在"无参考图"下出的，重渲才会带上定妆照；
2. **画风基线的优先级下降** —— 旧的"人物像不像定妆照"这条抱怨，主因是参考图没生效，不是画风串；
   画风串（`GUOFENG …` 里那句 `3D surface` / `SEMI-STYLIZED`）仍值得单独 A/B，但要在参考图生效之后再看观感；
3. 交付链路、字幕边距、去颗粒等 09-27 白天的修复不受影响。
