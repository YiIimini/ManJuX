# 角色多视角(转台图)方案

> 面向:想知道"角色多视角是怎么来的、为什么老是失败、现在该怎么配"的人。
> 代码入口:`internal/pipeline/turnaround.go`(分流 + 视频路径)、`internal/pipeline/viewedit.go`(编辑路径)、
> `internal/engine/comfyengine/imageedit.go`(编辑工作流)。
> 最后更新:2026-09-24(切换默认为图像编辑路径)。

---

## 1. 它是什么、为什么需要

多视角转台图 = 把**一张定妆照**扩成"正面 + 四分之三 + 侧面 + 背面"的横向拼图,
存成 `<定妆照主名>_turnaround.png`,渲染时作为该角色的**第二张参考图**喂给 H3。

它不是装饰品:`ref2va` 镜头只有一张正面照时,角色一转头就靠模型自由发挥 —— 脸型、
发型、服装都会漂。第二张参考图是"锁脸"之外唯一的角度锚点。

产物命名(与定妆照同目录,资产库靠 glob 收集):

| 文件 | 含义 |
|---|---|
| `<base>_view_threequarter.png` | 四分之三侧 |
| `<base>_view_side.png` | 正侧面 |
| `<base>_view_back.png` | 背面 |
| `<base>_turnaround.png` | 上面三张 + 定妆照的横向拼接(= 渲染用的第二张参考) |

三种触发时机共用同一份实现(产物因此完全一致):
资产阶段定妆后自动生成 / 渲染前发现缺了自动补齐 / 资产库详情弹窗「补全多视角」。

## 2. 两条路径

| | **图像编辑**(默认) | **H3 转身视频**(回退) |
|---|---|---|
| 怎么拿到另一个角度 | Qwen-Image-Edit-2511 拿定妆照本体改一个角度 | H3 Ref2V 渲一段转身视频,按 1.3 / 2.6 / 3.9 秒抽帧 |
| 身份保住吗 | 按像素保住(它就是同一张图) | **不保**:视频模型会顺手重新设计角色 |
| 耗时 | 每张几秒(4 步 Lightning) | 每个角色数分钟 |
| 实测结果 | — | 赛璐璐少年 → 写实真人(素色和服、迷彩丢失);插画铜雀 → 3D 机械铜鸟(铆钉/玻璃眼/金属板) |
| 现状 | **首选** | 仅在编辑链路未就绪时使用 |

### 为什么曾经"多视角老是生成错误"

旧实现只有视频路径。H3 是生成模型,它**有创作自由**:转身时会按自己的介质先验把角色
重画一遍。逐帧身份校验(`qc.IdentityJudge`)因此正确地判"不是同一个主体"并丢弃产物 ——
三个角色连续失败,用户看到的就是"多视角老是生成错误"。

- 判定没错,缺的是"身份不会被改写"的生成方式;
- 补介质锁(定妆照怎么画的就怎么转,见 `artstyle.go` 的 `TurnaroundMediumBlock`)只修了
  一半:画风对了,脸和服装细节仍在漂;
- 结论:**换模型,不换参数**。Krea-2 img2img 也不行 —— 它是纯文生图模型,没有身份条件
  注入机制,denoise 0.7 把人整个换掉、0.55 角度几乎不动。

## 3. 怎么配(默认就好,这里说清为什么)

编辑链路需要 4 个文件放进 ComfyUI 模型目录,默认文件名与 Comfy-Org 官方打包一致:

| 文件 | 放到 | 用途 |
|---|---|---|
| `qwen_image_edit_2511_fp8mixed.safetensors` | `models/diffusion_models/` | 编辑底模 |
| `qwen_2.5_vl_7b_fp8_scaled.safetensors` | `models/text_encoders/` | 文本/图像编码器(CLIPLoader type=`qwen_image`) |
| `qwen_image_vae.safetensors` | `models/vae/` | VAE |
| `Qwen-Image-Edit-2511-Lightning-4steps-V1.0-bf16.safetensors` | `models/loras/` | 4 步加速(可选,但强烈建议) |
| `qwen-image-edit-2511-multiple-angles-lora.safetensors` | `models/loras/` | 转角度专用 LoRA(可选) |

- 在「ComfyUI」管理页可以看到这 5 项的**核对结果**(在/不在,不在就给出可选清单);
- 项目参数「资产定妆 · 调优」里可以显式指定走哪条路(`自动` / `图像编辑` / `H3 转身`),
  默认 `自动`;
- `自动` 的判据:`EditAssets` 体检通过(文件在 ComfyUI 的模型目录里可见、服务在线)
  就走编辑,否则走视频,并在日志里说明**为什么退回去、补上什么会自动变好**。

## 4. 校验与失败策略(两条路完全一致)

```
定妆照 → [编辑/视频] 生成各角度 → 逐张/逐帧判"像不像本人" → 都通过? → 拼转台图
                                          │否
                                          ↓
                              换种子重出(默认 1 次)
                                          │仍否
                                          ↓
                    删除本次角度帧、不生成转台图、返回错误(调用方只告警)
                    → 该角色退回"单张正面照"渲染
```

要点:

- **宁缺勿错**:错误的第二张参考图会把成片人脸往错的方向拉,比"没有多视角"更糟;
- 未配置视觉模型时**跳过校验并如实写日志**,不假装校验过;
- 编辑路径逐张校验(哪一张不对就整批重来),视频路径逐帧校验。

## 5. 常见问题

**Q:为什么我的转台图看起来是"另一个人"?**
编辑路径不该出现这种图(它改的是同一张图),出现就说明当次走的是视频路径 ——
去日志里找"图像编辑链路还没就绪"那行,按提示把权重放好。

**Q:多视角失败了会影响出片吗?**
不会。失败只告警,角色按单张正面照渲染(锁脸锚点仍在,只是少了其它角度)。

**Q:能只喂拼合图省一张参考吗?**
不建议。拼合图缩放后每格只剩约 1/4 像素,脸会变糊;锁脸靠的正是定妆照那张锐利的脸。
项目参数里的「参考图去冗余」默认关,就是要两张都喂。

**Q:换第三方 repack 的 2511 权重后结构崩坏?**
官方模板注记:若不用 Comfy-Org 打包的 fp8mixed,可能需要在图里补
`FluxKontextMultiReferenceLatentMethod` 节点。当前实现按其说明未加。
