== 合计：12 镜；结构字段刀数=37（均 3.1）；正文 [Shot N] 数=37（均 3.1）；

## 2. 当天就咬出并修掉**我自己这个量尺**的一个真缺陷

### 2.1 症状

第一版跑真机时，体检里只有：

```
⚠ [shot #1] 计划 2 个内切，片段里只看出 1 个（实测切点 5.04s）
· [cuts] 有 10 镜的内容切点没量到：2、4、5…12 —— 没量到不算合格
```

**镜 2 那条最该报的结论（计划 2 刀 / 画面里一刀都没有）不见了**，被印成"没量到"。

### 2.2 根因

`select='gt(scene,0.3)'` 在"一帧都没选中"时输出 **0 帧**，`ParseCutTimes` 于是返回 **nil** ——
而 nil 与"没量到"在 Go 里**同形**（`shotCutTimes` 就是用 `ts[i] == nil` 判"没量到"的）。
于是**已经量出来的失败被印成了"没验过"** —— 三态反着用。

真机日志为证（`testdata/ff_cuts_clip002_real.txt`）：**2 行滤镜初始化**（`config in time_base`）
**+ 0 行 `pts_time`** —— 滤镜确实跑过，就是一帧都没选中。

### 2.3 为什么单测当时全绿：**摆设守卫**

原来的 ② 是**手写 `[]float64{}` 直接喂判据**，从没走过真入口 ⇒ 真入口那条路上的 nil 没人测。
这正是本仓反复记过的那条形态（判据不挂在真实入口上）。

### 2.4 修法（一句话：把"量到 0 刀"变成一个**能表达的状态**）

- 解析收成一格 `cutsFromLog`（**真机日志与单测走同一条**），一个点都没有时返回**非 nil 空切片**；
- `MeasureCuts` 再把 nil 统一成空切片（自定义量尺把"0 处"写成 nil 也照样算"量到"）；
- 三态的唯一出处收在**错误值**上：`err != nil` = 没量到；空切片 = 量到 0 刀。
- 结论措辞也跟着改：一处都没选中时写「（**滤镜一处都没选中：画面里一刀都没切**）」，
  不再留 `（实测切点 ）` 这种空括号（看着像模板坏了，反倒不像结论）。

修完真机输出（实测）：

```
⚠ [shot #1] 计划 2 个内切，片段里**只看出 1 个**（实测切点 5.04s）…
⚠ [shot #2] 计划 2 个内切，片段里**只看出 0 个**（滤镜一处都没选中：画面里一刀都没切）…
· [cuts] 有 9 镜的内容切点没量到：4、5、6、7、8、9、10、11、12 —— 没量到不算合格
```

（那 9 镜是**没渲**的镜，属"没量到"的正例。）

### 2.5 反向验证又咬出**两条我自己写的摆设守卫**

`scratch/reverse_verify_cuts_stamp.ps1` 第一次跑完，11 条里 **P2 / P4 没变红**：

- **P2**：把 `out = append(out, cutDeliveryFindings(in)...)` 改成 `_ = cutDeliveryFindings(in)`
  （算完就扔 = 结论不进表），门只查了子串 `cutDeliveryFindings(in)` ⇒ 放过去了；
- **P4**：把 `cuts := cutsFn(...)` 改成 `var cuts filmaudit.CutFn`（量尺造了、主流程不调），
  门查的是 `filmaudit.CutsFromFFmpeg(` —— 而它在**辅助函数体里**照样在 ⇒ 也放过去了。

两条门都改成咬**接线处**（`out = append(...)` / `cuts := cutsFn(`），再跑 11/11 全红。

## 3. 首镜那个多余的时间戳：平台早判出来了，但**没有任何一步去改**

- 官方多镜形式是**首镜不带时间戳**、从 `[Shot 2]` 起才写 `At MM:SS.mmm`（判据 `h3_format.go` 的②）；
- 真机的 **11 镜**正文全写成 `[Shot 1] At 00:00.000 …`；
- `H3FormatViolations` 早就会把这一条报成 warn —— 但**没有一步去改**（门只管说，不管做）。

修法：`project.NormalizeFirstShotTimestamp`（**纯机械格式，一个词都不动**）收在**唯一读取边界**
`HealPlan` 上，并如实播报改了几镜：

```
抹平了 1 镜首镜那个**多余的时间戳**（[Shot 1] At 00:00.000 ⇒ [Shot 1]）——
官方多镜形式的首镜不带时间戳，从 [Shot 2] 起才写 At MM:SS.mmm；
写着它模型认不出这一刀，内切就容易被忽略（真机那一集的内切实测基本没出现）
```

边界与门：只动 `[Shot 1]` 紧跟的那一个 `At`，**`[Shot 2]` 起的时间戳一个字都不碰**（那是真切点）；
幂等；`ParseCutsFromPrompt` 的切点数据前后完全一致；格式门前后对照（抹平前报、抹平后不报）；
`HealPlan` 真入口 + 播报各一条门。

修完真机复核：`cmd/auditfilm` 里那条"首镜带了时间戳"的投诉**消失**，只剩标点（#2/#3）与自创切词（#1）。

## 5. 边界（如实：这一轮**没有**验证到的部分）

1. **没重渲**：ComfyUI 没在跑，`data/projects` 下没有新产物 —— 所以"改了首镜时间戳之后内切兑现率会不会上升"
   **没有成片证据**。已有的证据只有：计划侧数据不变、格式门不再报、片段侧新判据能量出来。
2. **阈值与夹具样本量**：内容切点判据的真机样本 = **3 镜**（本集已渲的那三镜），外加既有整片夹具 1 份
   （`ff_cuts_real.txt`，用来钉"多了不报"）。它只报"少了"的方向、属**漏报方向**（同景别小角度切换量不到）。
3. **`[Shot 1] At` 之后模型是不是真的更听话**：首镜时间戳与自创切词都是**嫌疑**，不是因果证明 ——
   镜 2 用的是**官方措辞**（`the shot cuts to …`）却同样一刀没切 ⇒ H3 兑现内切本来就不牢靠。
4. **自创切词只点名、不自动改**（**待拍板**）：镜 1 的两刀写成 `cut to` / `switch to`（官方只认五句：
   `the camera cuts to / the shot cuts to / the shot transitions to / the shot changes to / the shot switches to`）。
   可确定性的映射只有"补主语"这一种，而补主语就是**改写散文**——像 `a blade cuts to the bone` 这种句子会被
   误伤成镜头动作，所以这一轮**只点名镜号与词**（判据已经报出来了），不自动改。要自动改请拍板。
5. **画质本身没有判据**："8 步 vs 4 步 vs 不挂蒸馏"的画面差异**没有抽帧 A/B**，只有引擎口径与用户主观感受；
   要真提清晰度，本机唯一可用的档是 `refine`（不挂蒸馏 + ≥20 步，约 2.5× 慢）。
6. **裁剪掉的 0.25 秒**：ffprobe 镜 1 = 7.75s（计划 8s）。与黑闪切除/接缝多渲有关（`compose.StrippedBlackSec`），
   这一轮没有继续追。

## 6. 给用户：能直接粘的命令

```powershell
# ① 这一集到底哪几镜「小分镜没兑现」（会点名镜号 + 实测切点 + 没量到的镜）

```

界面上的动作：

- **想让画面更清晰** → 参数抽屉里把「加速档」改成 **精修**（不挂蒸馏 LoRA + ≥20 步，约 2.5× 慢）。
  默认档在 `steps=8` 下挂的是 8 步蒸馏，那是"快"的那一档；`质量优先` 在本机量化底座上**与默认档完全一样**。
- **修好的首镜时间戳/台词标签要生效** → **重跑渲染**即可（渲染指纹含提示词，提示词变了会自动重渲，
  不用手动删片段）。
- **自创切词（`cut to` / `switch to`）** → 目前只能重新生成方案（让模型照官方五句写）；判据已点名镜号。
