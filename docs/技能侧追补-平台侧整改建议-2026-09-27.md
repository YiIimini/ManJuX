## 1. N1（P0）特写/近景 + 没有参考卡 —— 我这边刚踩过，别让平台也踩

### 为什么现在提

平台侧这份验收（`平台侧交付-技能侧整改单-2026-09-27.md` D3）正是在**技能侧**抓到这个：
全书 2462 镜里有 3 镜"特写/近景却没有角色参考图"，其中**第一条是全书第一镜、主角的脸**。
根因不是笔误，而是**这类缺陷没有门**：谁写分镜都可能犯（**平台 LLM 直出更可能**
—— 它每集现写，没有我这边"从 plan 继承"的约束）。

### 现在的缺口（两处，都很小）

1. **契约没有这条门**：`plan_contract.go` 有
   `if strings.Contains(sh.ShotSize, bad) { establishingClose = ... }`（L488，查"建立镜头不许特写"），
   但没有"`shot_size ∈ {特写, 近景}` 且 `characters` 为空"的检查。
   **加一条同形状的**（几行）：命中即 warn，文案建议直接抄技能侧那句 ——
   "特写/近景却没有角色参考图 ⇒ 每次生成一张新脸：去 `characters` 绑卡，或把景别改到不露脸并把正文里的脸删掉"。
2. **导演提示词没有这条规则**：`director.go` 的 `sysXXXRules` 里加一句 ——
   "**没有参考图的人不给脸**：写特写/近景前先确认该角色有卡；没有卡就用背影/局部/群演，
   并且**不要**写他的脸（画面里有人时也不许写 `empty frame, no people` 这种自相矛盾的锚点）。"

### 验收

```powershell
# 期望 0（技能侧那边同样命令已 0/1）
python - <<'PY'
import json,glob
bad=[]
for f in glob.glob(r'<项目>\漫剧脚本\*\plan\plan.json'):
    d=json.load(open(f,encoding='utf-8'))
    for s in d['shots']:
        if s.get('shot_size') in ('特写','近景') and not (s.get('characters') or []):
            bad.append((f.split('\\')[-3][:14], s['id']))
print(bad)
PY
```
外加：新集用 LLM 直出后，抽 1 集跑同一判据（因为它没有"继承"约束）。
