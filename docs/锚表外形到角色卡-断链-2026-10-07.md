# 非主角的角色卡为什么是"随机脸"：锚表外形到卡片的那一段断链（2026-10-07）

用户问：「人物生成的角色提示词去哪了？墨洄、尉迟彻、断桅、邵舷、霜见等不是主角的角色都随机生成的吗？」

**答案是：对，现状就是随机的** —— 而且锚表里这五个人的外形**是写全的**，是平台在"锚表 → 角色卡"这一段
断了链。下面全是真机第01集的现场证据（`data/projects/名册之外，八万零一号/…第01集…/`）。

---

## 一、现场：同一份 plan.json 里两类卡一眼可分

| 卡 | `description` | `image_prompt` | 出图时模型拿到了什么 |
| --- | --- | --- | --- |
| 祁七（主角） | 470 字 | 1829 字（脸型/眉眼/装甲/光环/铭牌链…） | 完整外形 |
| Q版祁七 | 319 字 | 1337 字 | 完整外形 |
| 系统机器人 | 35 字 | 221 字 | 完整外形 |
| **霜见** | **空** | 78 字：`[ANCHOR-STUB] a Chinese period-film character, aged 17 to 19, seven heads tall` | **只有一个古装人 + 年龄** |
| **墨洄** | **空** | 78 字：同上形态，`aged 25 to 30, eight heads tall` | 同上 |
| **邵舷** | **空** | 89 字：`aged 40 to 48, seven and a half heads tall` | 同上 |
| **尉迟彻** | **空** | 89 字：`aged 30 to 36, seven and a half heads tall` | 同上 |
| **断桅** | **空** | 60 字：`aged 58 to 66` | 同上 |

而**源文本里的锚表**（`source.txt`，`project.ParseCharAnchor` 实测解析）写的是：

    霜见 471 字 / 墨洄 316 字 / 邵舷 294 字 / 尉迟彻 275 字 / 断桅 4846 字（后者含缺陷，见第三节）

例如尉迟彻那一节逐项写着「脸型：方中带圆脸，下颌方，眉骨压眼／眉眼：剑眉…细长单眼皮／独特记号：左手小指
缺一节…／首套服装：深灰值勤装甲（肩甲有划痕）」—— 一个字都没进卡片。

**日志里的下游症状**（`data/logs/manjux.log`）：

    ⚠ 定妆照「墨洄（卡片 char_mohui）」与「霜见（卡片 char_shuangjian）」**长得像同一个人**
      （脸型窄长、眼型细长、眉形与发髻完全一致，年龄感相当。）
    ⚠ 重出后「墨洄」仍与「霜见」像同一个人 —— 已收手，请在资产详情里改描述/提示词后「重新生成」

撞脸门报的是**症状**；原因是这五张卡**没有可照抄的外形**，模型只能按"一个古装人、某岁"现编，同样的
prompt 重渲还是同一种脸。

---

## 二、根因：断在 `EnsureAnchorCast` 的"已存在卡片"那条路

1. ②人物道具会话按名字出了这五张卡（id 是拼音 `char_shuangjian`…），但**没写 `description`**；
2. `EnsureAnchorCast`（`internal/pipeline/cast_anchor.go`）对账锚表时：
   * **新增**卡片那条路 → 写 `Description = 锚表原文` ✔
   * **已存在**卡片那条路 → 只补英文兜底串 `anchorImagePrompt(a)`（只有年龄+头身比），**从不补 `description`** ✘
3. 专职翻译会话 `TranslateCardPrompts` 的判据是 `NeedsPromptTranslation`：
   `Description != ""` **且**（`ImagePrompt` 为空**或**含兜底标记）——
   `description` 是空的 ⇒ **这五张永远不进翻译队列**；
4. 于是出图装配（`pipeline.PortraitPrompt`）只拿到兜底串 ⇒ 脸现编 ⇒ 跨镜/跨集不一致 ⇒ 撞脸门报警。

一句话：**"锚表是外形唯一权威"这句话，在"名字已存在的卡"上没有落地。**

## 三、顺带查出的第二个真缺陷：锚表小节吞掉了整集剧本

`ParseCharAnchor` 用 `splitSections` 切小节，body 一直取到**下一个角色标题**或**文末**。
真机 `source.txt` 里锚表最后一节「断桅」只写到 `- 身形：瘦，背驼，走路` 就接上了平台自己的
`【本集剧情】…`，随后是整集剧本 ⇒ 解析出的 `Raw` = **4846 字**（其余四个是 275~471 字），
里面大半是剧本正文。

危险性不止"体积"：这段 `Raw` 是被当作**外形描述**用的 —— 它会进 `description`、进翻译会话的输入、
进卡片详情展示。作者在每一项之间爱空一行，所以边界**只能靠平台自己的节标记**划
（与 `internal/server` 的 `briefEndMarkers` 同一口径）。

---

## 四、修法（四步，都是"能确定性做到的就别让模型自觉"）

1. **正文边界**（`internal/project/settingbook.go`）：`ParseCharAnchor` 在
   `【本集剧情】/【本集原文】/【前情提要】/【开场爆点】/【场 ` 的最早出现处截断小节，
   并给 `SettingChar` 加一个 `Cut` 位（"这一节被正文截断了"）——因为截断本身是**源文本的问题**，
   平台不会替作者编外形，但必须**如实点名**。
2. **锚表原文回填**（`FillAnchorDescriptions`）：按归一化名字匹配，**只填空的 `description`**
   （已有的一个字都不覆盖），空提示词顺带补上兜底串（那同时是"待翻译"的标记）。幂等。
3. **两条链都接上**：
   * 脚本阶段（新方案落盘前）：`EnsureAnchorCast` → `FillAnchorDescriptions` → `TranslateCardPrompts`；
   * **资产阶段出图前**（`c.backfillCastIdentity`）：同样三步。**这一条是为存量项目**——
     否则修好之后用户还得重跑剧本，而重跑剧本会重排分镜、把已经渲过的镜头全废掉；
     重跑「资产生成」就够了。补完会 `SavePlan` 落盘。
4. **出图前点名缺口**（`IdentityPromptGaps`）：`image_prompt` 为空或仍是兜底串的卡，逐张报名字，
   说清"身份没锁、脸靠现编"。此前这件事只在下游撞脸门报警时才看得见（那是症状）。

降级路径一律 **warn + 如实说**：没有可用 LLM（设置页未配置）⇒ 播报"N 张卡只有中文设定、译不了"；
源文本被截断 ⇒ 点名哪几节不全，请补全后重跑。**不拦产线、不静默跳过。**

## 六、边界与"还要你补的东西"

* **这次修好的是"链路"**：锚表里有的外形，从此会进卡片并译成英文定妆提示词。
  已经出过的那五张定妆照**不会自动变** —— 要重跑「资产生成」（或单卡「重新生成」）才会用新提示词出图。
* **断桅那一节的源文本本身是截断的**（只到「身形：瘦，背驼，走路」）。平台只能照抄到断点并**点名**；
  要让她也逐项照抄，需要在 `source.txt` 里把这一节补全（后续四项：脸型/眉眼/鼻唇/肤色…）后重跑。
* **②人物道具会话为什么不写 `description`**：这是模型没按 schema 给（同一份 schema 里祁七给了、这五个没给）。
  平台侧现在有回填兜底；但"模型漏字段"这件事本身仍可能出现 —— 兜底的位置是
  `FillAnchorDescriptions`（有锚表就补）与 `IdentityPromptGaps`（没锚表就点名）。

## 七、补一条真源：小说原文里的"首次出场段"（用户追问：「小说内容第一次出现角色没有描述角色形象吗？」）

**写了** —— 而且写得很具体。真机《名册之外，八万零一号》全本里五个人的首次出场（原文照抄）：

| 角色 | 首次出场那几段（节选） |
| --- | --- |

而且这几段**本来就在②人物道具会话的输入里**（`director/sessions.go`：user = 设定集摘要 + 已确立清单 +
`【本集原文】`）—— 模型却偏偏只给这五张卡写了名字，没写 `description`。

所以这一轮把它也接上（**锚表优先，锚表没有才用它**）：

* `project.FirstAppearanceExcerpt(text, name, otherNames)` —— 从原文里取"首次出场段"的外形材料，
  判据是确定性的：按**出现顺序**试每一个"名字所在段"，每处向**前**最多扫 8 段，取第一段"像在描写人"的段落，
  段内只保留**含外形线索词的句子**。三道把关：
  * 段落门槛：命中 ≥2 类外形词才算描写段（名字自己那一段降到 ≥1 —— 邵舷那种写法）；
  * **别人的描写不许当他的**：该段出现别的已知角色名、却没有本名 ⇒ 跳过；
  * 逐句筛：剧情与对话不进材料（断桅那句"链条在她腰上碰了两下"就是在被选中的段落里被滤掉的）。
  取不到就**不填**（宁可不填，也不要把剧情译成外貌）。
* `pipeline.FillCastDescriptionsFromSource` 写回卡片（只填空的、幂等），装兜底串 ⇒ 交给同一个专职翻译会话。
* 两条链与锚表那条并列：脚本阶段（存盘前）+ 资产阶段出图前，并**如实播报**
  「📖 N 张卡的外形材料取自**本集原文的首次出场段**（锚表里没有这几个人）：…」。

验证：夹具 = 四个人的**全本原文照抄**（连它前后的剧情与对话一起，因为难点正是"只取描写不取剧情"）
+ 三个反例（别人的描写、全对话、名字不在文本里）；**反向验证 5 处**（关掉取材料 / 去掉"别人的"守卫 /
去掉逐句筛 / 去掉"只填空的"守卫 / 资产阶段漏调 ⇒ 全红）。

**边界（照实说）**：这条兜底给的是"材料"，不是证件照——它可能只覆盖到体格与服装（尉迟彻那一段就只有
轮廓与装甲），翻成英文后细节仍取决于小说的写法；而字数上限 400、取不到就点名（不填）。

## 八、第三条通路：锚表本身被**静默腰斩在 2500 字**（同一症状，另一条链路）

回答用户这个问题时顺手把"角色外形是怎么进模型的"整条链路走了一遍，发现**输给模型的第一步就已经丢东西**：

| 事实 | 实测值 |
| --- | --- |
| 作者的 `设定集/人物外形锚表.md` | **15468 B / 6202 字 / 14 条角色**（祁七…议长，外加 Q 版附录） |
| 平台注入每集 `source.txt` 的上限 | `characterSheetMaxRunes = 2500` 字（`internal/server/novels_produce.go`） |
| 实际后果 | 砍点落在**「断桅」条目中间**（`- 身形：瘦，背驼，走路` 之后直接接 `【本集剧情】`）；其后的**苔生/拾叁/回波/关棠/剥线刀/毕申/白手套/议长 8 条从未进过任何一集的分镜输入** |
| 为什么坏 | 锚表是外形唯一权威。这 8 个人"每集都以硬约束的形式出现过"是**假的** —— 模型看到的只有他们前面那些人的外形，于是这 8 张定妆照只能现编脸（与第七节那个"随机脸"同源，只是发生在更上游） |
| 而且**无声** | 截断走的是 `rs[:2500]`，没有播报、没有日志 —— 人只能从"某个角色的描述怪怪的"倒推 |

修法（`internal/server/novels_produce.go`）：

1. **上限按真实量级放宽**：2500 → **12000** 字（锚表仍是"每人数行"的东西，上限保留只为防"有人把整本设定集
   塞成锚表"，设定集实测 6 万字）。
2. **超上限时不许腰斩某个人**：`trimCharacterSheet` 退到**最近的小节起点**（`^名字（定位：…）`）整条丢 ——
   "半个人的外形"比"没这个人"更坏，模型会照半条现编另外半张脸；没有小节时才退到最后一个空行，都没有才按
   rune 硬切。
3. **如实点名**：第二个返回值是说明串，由调用方以 warn 播报：「⚠ 外形锚表超上限(6202 字 > 12000 字)：末尾 N 字
   未进每一集的输入，被整条略过的角色：…」。

判据（`internal/server/character_sheet_trim_test.go`，夹具 = **真机锚表原文** `testdata/char_anchor_real.md`）：

* 真机表必须**一条不落**：14 条角色名都在、`- Q版形象：` 字段正好 14 个（结构判据：条目被腰斩会少字段）、
  文末「三卡规范口径」还在；
* 超上限（真机表 ×3 = 18606 字）时：留下的小节数 **==** `- Q版形象：` 数（每个留下的角色都完整）、
  说明里必须点名被丢掉的角色；
* 没有小节时退空行边界：留下内容的末尾必须仍是一整行（不腰斩行），且不许编出"被略过的角色"。

**反向验证 3 处**（`reverse_verify_sheet.ps1`，全红后回滚）：① 上限退回 2500 ⇒ 真机表被判"被砍" ② 去掉小节边界切
⇒ 条目被腰斩被咬住 ③ 截断说明不播报 ⇒ 接线门变红。

**照实说的边界**：这条只解决"表被砍"，不解决"表里没写这个人"——后者由第七节的原文首现段兜底；另外
**第01集那五张已经出过的定妆照不会自动变**（要重跑「资产生成」）。
