## 2. 当前最大的待办：**H3 的参考图根本没参与生成**

### 结论（已实测，逐帧可复现）

`<Picture 1>` 目前是**装饰品**。分镜里的人物长相与画面质感**只由文字决定**，
换定妆照 / 换场景板**不会改变成片**。这解释了用户的三条报障：
「镜头里的人跟定妆照差距大」「画风跟定妆照不一致」「改定妆照也没用」。

### 证据（判据＝全片解码帧序列 md5，`ffmpeg -f framemd5`）

1. 把定妆照 + 场景板换成完全不同的一版（半风格化 3D → 实拍质感）→ 两次帧指纹**完全一致**
   （`1F711C0A…`），而两次的条件缓存 `.pt` 内容**确实不同**（说明图被读进去、被编码了）。
2. 把沈砚的参考图换成**另一个人**（卖菜婆，老妇；已核对 `ComfyUI/input/` 里那张 md5 同步）
   → **仍然 `1F711C0A…`**。
3. 手搓与官方 bench 工作流（`D:\Ai\ComfyUI\api-workflows\h3-ref2va-bench.json`）**逐节点一致**
   的最小图（22 帧 / 8 步 / 固定种子 / 同一句提示词）：Singularity 底模、官方底模、挂 / 不挂 turbo LoRA
   —— **每一对只有参考图不同的运行都逐帧一致**。

### 已排除

条件缓存那条近路（关掉后一样）、社区底模（换官方一样）、turbo 蒸馏 LoRA（不挂一样）、
平台侧装配 / 上传 / 参数（实验 3 是手搓图）、文本编码器没有视觉塔（该 CLIP 有 351 个 `visual.*`
张量，tokenizer 也确实把图塞进 token 流）。

### 剩下的嫌疑

1. 本机四个 H3 底模**全是"剪枝 + int8"转换版**（`Pruned_v1.3_int8` / `pruned_int8_convrot`），
   参考分支很可能在转换时被削掉；**全盘没有任何未剪枝权重可对照**。
2. ComfyUI 0.37.4 与这批权重的组合不匹配。

### 下一步（**2 分钟就能判定**）

用那张最小图，**换一套未剪枝权重（或换 ComfyUI 版本）后跑两张截然不同的参考图**，
比较全片帧指纹：

- 不同 → refs 通了，本机这批剪枝权重就是坏的，换掉即可；
- 仍相同 → 问题在 ComfyUI 侧，要往上报。

复现要点（都在 `docs/参考图未生效-实测.md`）：`length=22`、`steps=8`、`noise_seed=424242`、
`ref_image_size=max`、`prompt="The person shown in <Picture 1> …"`、
参考图 `ComfyUI/input/abtest_shenyan.png`（年轻男子）/ `abtest_maicaipo.png`（老妇）。

### 需要用户拍板的事（别自己下几十 GB 的东西）

- **A**：下未剪枝 / 未量化的 H3 ref2va 权重（官方 fp16/fp8，约 20–40GB，落到
  `D:\Ai\ComfyUI\shared\models\diffusion_models\`）来验证 / 替换；
- **B**：先试**换 ComfyUI 版本**（不下载大模型，风险低但可能白忙）。
