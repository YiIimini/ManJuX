## 2. 已解决：H3 Ref2V 的参考图**从来没进过条件**（`a9924b4`）

### 根因（一句话）

参考图槽位的**提交键形态写错了**。ComfyUI 的 autogrow（动态槽位）输入在 API prompt 里只认
**「聚合键.模板名」**点号键（`ref_images.ref_image_0`）；我们一直提交聚合数组 `ref_images=[link,…]`，
被 `comfy_api/latest/_io.py` 的「所有 optional 都没值」分支静默填成 `{}` ——
节点 `ref_items=0`，参考图一张都不进条件，**而且不报错**。

### 证据（真机，同提示词同种子，只换参考图，22 帧）

| 提交形态 | 节点收到 | `ref_items` | conditioning | 帧指纹 |
|---|---|---|---|---|
| 聚合数组（旧写法） | 空 dict | 0 | 无 `minimax_refs`，`cross_attn` 恒为 `77962ff3…` | 年轻男子 vs 老妇 **逐帧相同** |
| 点号键（新写法） | `{ref_image_0: tensor}` | 1（3 张时 =3） | 有 `minimax_refs`，`cross_attn` 随图变 | **完全不同**，人与服装跟着参考图走 |

辅证：点号键下 `layout.segments` 出现 1008 行 `ref_img` 段、`cond_video_rows=(1008,96)` ——
视频行的 RoPE 时间坐标整体后移，**所以"参考图没生效"必然等价于"根本没送到"**。

### 修复

- `internal/engine/comfyengine/autogrow.go`：新增 `autogrowKey(聚合键, 模板名, i)`，注释里写明源码依据与失效机理；
- `engine.go`（`ref_images` / `ref_audios`）+ `maskgraph.go`（局部重绘喂裁剪主体）一律改走它；
- `autogrow_contract_test.go` 锁死形态：必须点号键、不得出现聚合键本身、槽位必须指向图里真实节点。

### 顺带证伪（别再花冤枉时间）

1. **本机四个「剪枝 + int8」H3 底模无罪** —— 同一套 `MiniMax_H3_ref2va_pruned_int8_convrot`，
   只改提交键参考图立刻生效 ⇒ **不需要下 20–40GB 未剪枝权重**；
2. **ComfyUI 版本无关** —— `v0.36.0→v0.37.4` 之间没有任何 H3 ref 路径改动，换版本治不了这个病。

### 影响面（**要记住**）

- **之前所有镜头都是在"无参考图"下渲出来的**，成片不会自己变；重渲才带定妆照。
  「镜头里的人跟定妆照不像 / 改定妆照没用」这组报障的主因就是这个，**不是**提示词措辞、**不是**权重、**不是**版本。
- 反过来：**重渲会让画面明显变化**（人与服装现在真的听定妆照），做 A/B 时别把"变好/变坏"混为噪声。
